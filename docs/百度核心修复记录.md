# 百度网盘适配器核心修复记录（2026-09-16）

## 一、问题现象

| 现象 | 出处 |
|---|---|
| 写操作（建目录/上传）报 `errno:-6 未登录或登录已过期` | V8_3 建目录、上传 |
| 终端刷屏 `[认证] 刷新会话失败：RecursionError: maximum recursion depth exceeded` | 启动连通性测试 |
| 账号状态耗时 ~43s，用户名显示 `-` | 启动核心信息 |
| 容量永远为空 | 账号状态详情 |

## 二、逆向分析（真机 HTTP 实测 + 浏览器交叉验证）

### 2.1 端点矩阵（用适配器 `数据/会话.json` 里的 Cookie 实测）

| 端点 | 结果 | 结论 |
|---|---|---|
| `GET /api/gettemplatevariable?fields=[…]` | ❌ `errno:-6` | **接口已失效**（对有效会话也拒绝） |
| `GET /api/loginStatus?clienttype=1&channel=web&version=0` | ✅ `errno:0` | 返回 `login_info{bdstoken, uk, username, vip_type, vip_level, photo_url, sec_mobile}` —— **唯一可靠的引导入口** |
| `GET /api/user/getinfo?need_boardinfo=1&user_list=[uk]` | ✅ `errno:0`（需带 uk 才有数据） | 端点健在，但依赖上面的引导提供 uk |
| `GET /api/list?dir=/…` | ✅ `errno:0` | 读操作一直正常 |
| `GET /api/quota` | ❌ `-6 用户未登录`（补 `bdstoken` / `BAIDUID` / `PANWEB` 均无效） | 容量接口对该类会话不可用 |
| `POST /api/create`（建目录） | ❌ `-6`（试过 `a=commit`、`method=create`、补 `BAIDUID`/`PANWEB` 全部一样） | **会话只有读权限**，与令牌无关 |

浏览器交叉验证：`browser_panel` 打开同一个 `loginStatus` URL，返回
`{"errno":-6,"show_msg":"账户已过期，重新登陆"}` —— 说明浏览器本身没登录百度，
而适配器存储的 Cookie 反而能拿到 `errno:0`，证明**问题在适配器链路，不在网络/账号**。

### 2.2 递归崩溃的根因

```text
网络客户端.请求()  收到 errno:-6
   └─ 调用 会话刷新器 = 认证服务.刷新会话()
        └─ 认证服务.取模板变量() → 又走**同一个**网络客户端
             └─ gettemplatevariable 还是 -6
                  └─ 再调 会话刷新器 → …… 直到 RecursionError
```

即：**刷新链路自身又触发了刷新**，且唯一引导端点已失效 → 每次刷 new 都必然失败，
最后以栈溢出收场；写操作永远拿不到 `bdstoken`。

## 三、修复内容

### 3.1 `核心/认证/认证服务.py`
1. 新增 `取登录状态()`：走 `/api/loginStatus`（`自动刷新=False`），
   一次取回 `bdstoken + uk + username + vip_*` 并落库；
2. `取模板变量()` 改为**优先 loginStatus**，`gettemplatevariable` 仅作兜底
   （返回结构保持兼容，含 `bdstoken/token/uk/...`）；
3. `刷新会话()` 加 **threading.local 防重入**：刷新中再被回调直接返回 False；
4. `取当前用户()` 优先用 loginStatus 的信息（省一次请求），`getinfo` 兜底；
5. `检查登录态()` 直接返回 loginStatus 的 `login_info`；
6. `取容量()` 遇 `-6` **优雅降级**（返回 `{}` + 一次性警告），不再抛错。

### 3.2 `核心/网络/网络客户端.py`
1. `请求()` 增加 `自动刷新: bool = True`；**会话引导自身必须传 False**，
   从机制上杜绝"刷新→引导→再刷新"的递归；
2. 写路径（`需要bdstoken=True`）的 `errno:-6` 现在会带上可操作提示：

   > 当前会话只有读权限 —— 请在「登录 / 管理」里重新扫码或粘贴 Cookie
   > 登录后再试写操作（重新登录后 BDUSS/STOKEN 会带写权限）

### 3.3 `网盘管理_V8_3/v8_3/桥/后端_百度.py`
`account()` 增加只读的写权限提示字段（`write_hint`），界面可直接展示。

## 五、写操作的真正根因（已定位并解决）

### 5.1 请求写法是对的 —— 会话本身只读

进一步用浏览器 + 前端 JS 逆向排查：

1. **抓前端 JS 源码**（`https://nd-static.bdstatic.com/m-static/v20-main/home/js/*.js`）
   找到真实调用：`createNewFolder(){ let i=toQuery({channel:'chunlei',clienttype:0,
   web:1,app_id:250528,logId, bdstoken}); return e.post('/api/create'+i,{params:t}) }`
   —— 端点、query 参数与适配器一致；body 经实测仍是 **form 编码**（换成 JSON
   `{"params":…}` 反而报 `errno:2`）。**所以适配器的请求形态一直是正确的。**
2. **浏览器实测**：在面板里登录百度网盘（短信登录）→ Web UI「新建文件夹」**成功**；
3. **解密浏览器 Cookie 库**（`~/.dsh/browser-panel/profile/Default/Cookies`，
    Chrome v10：PBKDF2("peanuts") + AES-128-CBC）对比：
   * 浏览器会话与适配器会话是**两套不同的 BDUSS/STOKEN**；
   * 用**浏览器那套**（最小集 `BDUSS`+`STOKEN`）调 `/api/create` → **成功**；
   * 用**适配器那套** + 同样的请求 → `errno:-6`；
   * 给适配器那套**补上** `csrfToken`/`PANPSC`/`XFI`/`XFT`/`XFCS`/`ndut_fmt` 也没用。

结论：**失效的是适配器手里的那套会话（只读会话）**，不是代码、不是端点、不是缺参数。

### 5.2 处理

用适配器自己的 `登录服务.手工导入cookie()`（不直接改它的文件）把浏览器刚登录的
会话导入进去，随后端到端实测写路径全通：

```
① 账号：x894597841 已登录
② 建目录 → {'path': '/V8_3_写路径验证_1789524581'}
③ 上传 → /V8_3_写路径验证_1789524581/写测试.txt (36 字节)
④ 列目录 → [('写测试.txt', 36)]
⑤ 回读 sha256 6b807c166a0d6dfc vs 本地 6b807c166a0d6dfc → ✅ 一致
⑥ 删除目录 → {"errno": 0, ...}；复查根目录已无残留
```

> 测试期间在网盘里建过 `V8_3_写路径验证_*`、`V8_3_浏览器会话验证_*`、
> `V8_3_写权限实测` 三个临时目录，**均已在验证后删除**（实测列目录已无 `V8_3_` 前缀残留）。

### 5.3 以后再遇到写失败怎么办

`errno:-6` 且读操作正常 = **会话只读**，重新登录即可（拿到的会话自带写权限）：

1. V8_3 → 选中「百度网盘」→ 点「🔐 登录 / 管理」→ 统一登录对话框；
2. 选「🍪 导入Cookie」粘贴浏览器里 `pan.baidu.com` 的 `BDUSS` + `STOKEN`
   （推荐：浏览器登录一次再复制，实测这样拿到的会话可写）；
3. 回来点「🔄 刷新状态」，再试建目录/上传。

现在写失败时错误信息已经会直接这么提示（见 3.2 第 2 条），不会再是干巴巴的"未登录"。

复验命令（会自建自删一个临时目录）：

```bash
cd <项目根>
<项目根>/运行环境/venv/bin/python - <<'PY'
import sys; sys.path.insert(0, ".")
from v8_3.核心.适配器 import 适配器规格

a = 子进程适配器(适配器规格(类型=网盘类型.百度,
                          项目根="<项目根>/适配器/百度网盘适配器"))
a.启动()
try:
    目录 = "/V8_3_写权限复验"
    print("建目录：", a.确保目录(目录))
    print("目录内容：", [x.name for x in a.列目录(目录)])
    print("删除：", a.删除(目录))
finally:
    a.关闭()
PY
```
