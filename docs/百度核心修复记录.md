# 百度网盘适配器核心修复记录（2026-09-16）

## 一、问题现象

| 现象 | 出处 |
|---|---|
| 写操作（建目录/上传）报 `errno:-6 未登录或登录已过期` | V8_3 建目录、上传 |
| 终端刷屏 `[认证] 刷新会话失败：RecursionError: maximum recursion depth exceeded` | 启动连通性测试 |
| 账号状态耗时 ~43s，用户名显示 `-` | 启动核心信息 |
| 容量永远为空 | 账号状态详情 |

## 二、逆向分析（真机 HTTP 实测 + 浏览器交叉验证）

### 2.1 端点矩阵（用适配器 `数据/会话.json` 里的 Cookie 实测）

| 端点 | 结果 | 结论 |
|---|---|---|
| `GET /api/gettemplatevariable?fields=[…]` | ❌ `errno:-6` | **接口已失效**（对有效会话也拒绝） |
| `GET /api/loginStatus?clienttype=1&channel=web&version=0` | ✅ `errno:0` | 返回 `login_info{bdstoken, uk, username, vip_type, vip_level, photo_url, sec_mobile}` —— **唯一可靠的引导入口** |
| `GET /api/user/getinfo?need_boardinfo=1&user_list=[uk]` | ✅ `errno:0`（需带 uk 才有数据） | 端点健在，但依赖上面的引导提供 uk |
| `GET /api/list?dir=/…` | ✅ `errno:0` | 读操作一直正常 |
| `GET /api/quota` | ❌ `-6 用户未登录`（补 `bdstoken` / `BAIDUID` / `PANWEB` 均无效） | 容量接口对该类会话不可用 |
| `POST /api/create`（建目录） | ❌ `-6`（试过 `a=commit`、`method=create`、补 `BAIDUID`/`PANWEB` 全部一样） | **会话只有读权限**，与令牌无关 |

浏览器交叉验证：`browser_panel` 打开同一个 `loginStatus` URL，返回
`{"errno":-6,"show_msg":"账户已过期，重新登陆"}` —— 说明浏览器本身没登录百度，
而适配器存储的 Cookie 反而能拿到 `errno:0`，证明**问题在适配器链路，不在网络/账号**。

### 2.2 递归崩溃的根因

```text
网络客户端.请求()  收到 errno:-6
   └─ 调用 会话刷新器 = 认证服务.刷新会话()
        └─ 认证服务.取模板变量() → 又走**同一个**网络客户端
             └─ gettemplatevariable 还是 -6
                  └─ 再调 会话刷新器 → …… 直到 RecursionError
```

即：**刷新链路自身又触发了刷新**，且唯一引导端点已失效 → 每次刷 new 都必然失败，
最后以栈溢出收场；写操作永远拿不到 `bdstoken`。

## 三、修复内容

### 3.1 `核心/认证/认证服务.py`
1. 新增 `取登录状态()`：走 `/api/loginStatus`（`自动刷新=False`），
   一次取回 `bdstoken + uk + username + vip_*` 并落库；
2. `取模板变量()` 改为**优先 loginStatus**，`gettemplatevariable` 仅作兜底
   （返回结构保持兼容，含 `bdstoken/token/uk/...`）；
3. `刷新会话()` 加 **threading.local 防重入**：刷新中再被回调直接返回 False；
4. `取当前用户()` 优先用 loginStatus 的信息（省一次请求），`getinfo` 兜底；
5. `检查登录态()` 直接返回 loginStatus 的 `login_info`；
6. `取容量()` 遇 `-6` **优雅降级**（返回 `{}` + 一次性警告），不再抛错。

### 3.2 `核心/网络/网络客户端.py`
1. `请求()` 增加 `自动刷新: bool = True`；**会话引导自身必须传 False**，
   从机制上杜绝"刷新→引导→再刷新"的递归；
2. 写路径（`需要bdstoken=True`）的 `errno:-6` 现在会带上可操作提示：

   > 当前会话只有读权限 —— 请在「登录 / 管理」里重新扫码或粘贴 Cookie
   > 登录后再试写操作（重新登录后 BDUSS/STOKEN 会带写权限）

### 3.3 `网盘管理_V8_3/v8_3/桥/后端_百度.py`
`account()` 增加只读的写权限提示字段（`write_hint`），界面可直接展示。

## 五、写操作的真正根因（已定位并解决）

### 5.1 请求写法是对的 —— 会话本身只读

进一步用浏览器 + 前端 JS 逆向排查：

1. **抓前端 JS 源码**（`https://nd-static.bdstatic.com/m-static/v20-main/home/js/*.js`）
   找到真实调用：`createNewFolder(){ let i=toQuery({channel:'chunlei',clienttype:0,
   web:1,app_id:250528,logId, bdstoken}); return e.post('/api/create'+i,{params:t}) }`
   —— 端点、query 参数与适配器一致；body 经实测仍是 **form 编码**（换成 JSON
   `{"params":…}` 反而报 `errno:2`）。**所以适配器的请求形态一直是正确的。**
2. **浏览器实测**：在面板里登录百度网盘（短信登录）→ Web UI「新建文件夹」**成功**；
3. **解密浏览器 Cookie 库**（`~/.dsh/browser-panel/profile/Default/Cookies`，
    Chrome v10：PBKDF2("peanuts") + AES-128-CBC）对比：
   * 浏览器会话与适配器会话是**两套不同的 BDUSS/STOKEN**；
   * 用**浏览器那套**（最小集 `BDUSS`+`STOKEN`）调 `/api/create` → **成功**；
   * 用**适配器那套** + 同样的请求 → `errno:-6`；
   * 给适配器那套**补上** `csrfToken`/`PANPSC`/`XFI`/`XFT`/`XFCS`/`ndut_fmt` 也没用。

结论：**失效的是适配器手里的那套会话（只读会话）**，不是代码、不是端点、不是缺参数。

### 5.2 处理

用适配器自己的 `登录服务.手工导入cookie()`（不直接改它的文件）把浏览器刚登录的
会话导入进去，随后端到端实测写路径全通：

```

④ 列目录 → [('写测试.txt', 36)]
⑤ 回读 sha256 6b807c166a0d6dfc vs 本地 6b807c166a0d6dfc → ✅ 一致
⑥ 删除目录 → {"errno": 0, ...}；复查根目录已无残留
```

> 测试期间在网盘里建过 `V8_3_写路径验证_*`、`V8_3_浏览器会话验证_*`、
> `V8_3_写权限实测` 三个临时目录，**均已在验证后删除**（实测列目录已无 `V8_3_` 前缀残留）。

# 写权限最终答案：从浏览器导入"完整会话"（2026-09-19）

## 现象

扫码登录后网盘页显示 **🟢 已登录，用户：-**，并附一行：

> ⚠️ 写操作不可用：写操作被服务端拒绝（errno:-6）：会话里的 STOKEN 已失效…

列目录、播放、下载都正常，**上传 / 改名 / 删除 / 新建文件夹一律失败**。

## 真机实测的结论（一条条打出来的）

用浏览器里那份会话（CDP 取出的 cookie）直接打接口：

| 接口 | 结果 |
|---|---|
| `GET /api/list` | `errno:0`（BDUSS 有效） |
| `GET /api/gettemplatevariable` | `errno:0`（拿到 bdstoken） |
| `POST /api/create`（表单带 `path`） | **`errno:0`，目录真的建出来了** |
| `POST /api/filemanager opera=rename` | `errno:0` |
| `POST /api/filemanager opera=delete` | `errno:0` |

同一账号，换成扫码登录那份会话 → 上面三条写操作全部 `errno:-6`。

**所以：写权限 = BDUSS + `pan.baidu.com` 域上的 STOKEN。**
扫码登录换来的会话缺这份 pan 域 STOKEN（或被后续登录轮换掉了），
于是"能读不能写"。浏览器里的会话是完整的 —— 问题只是**怎么把它拿回来**。

## 为什么不能直接读浏览器 cookie 文件

Chromium 系（Brave/Chrome）的 cookie **值是加密的**（v20 加密 + 系统密钥环），
直接读 `Cookies` sqlite 只能拿到 `length(value)=0` 的密文行。
我们实测确认过：`host_key='.baidu.com' AND name='BDUSS'` 的 `value` 为空字符串。

## 解法：走 CDP（不需要装任何插件）

浏览器开着调试端口时（本项目的浏览器面板默认开在 38489），
用 **Chrome DevTools Protocol** 的 `Network.getCookies` 让**浏览器自己解密**，
把 cookie（含 HttpOnly 的 BDUSS / STOKEN）通过 `127.0.0.1` 交给我们。
这正是"浏览器插件式"的取法，但零安装。

实现在 `核心/认证/浏览器会话导入.py`：

* `找调试端口()`：先试常见端口（38489/9222/9223/9229），
  再从进程命令行里抓 `--remote-debugging-port=`（端口被改过也能找到）；
* `_抓cookie()`：优先连**页面** target（`Network` 域只在页面级有效），
  退回浏览器级 `Storage.getCookies`；
* `会话字段()`：**按域名优先级取 STOKEN** ——
  `.pan.baidu.com` > `.baidu.com` > `.passport.baidu.com`。
  同名 cookie 在不同域上值不同，拿成 passport 域那份照样 errno:-6（实测）。

桥侧入口：`login_cookie` 传 `__取浏览器会话__` 即触发
（`后端_百度._从浏览器导入会话()`）：取 → 落盘 → 服务端验证（读 + bdstoken）
→ 写权限探针 → 失败自动回滚到导入前的会话。

## 界面入口

百度 → 「🍪 导入Cookie」面板 → **「🌐 从浏览器导入完整会话」**：

1. 在带调试端口的浏览器里登录 pan.baidu.com（本项目的浏览器面板默认已登录）；
2. 点这个按钮 —— 它会显示"已从浏览器取到完整会话：BDUSS 192 字节、
   pan 域 STOKEN 64 字节"，随后网盘页的写操作立刻可用。

## 顺带修掉的两个真 bug

1. **`适配器规格.路径` 相对路径解析错**：桥工作进程用 `cwd=v8_3/桥` 启动，
   配置里写 `适配器/百度网盘适配器` 会被解析成
   `v8_3/桥/适配器/百度网盘适配器` → 适配器 `核心` 包 import 不进来，
   所有调用报 `ModuleNotFoundError: No module named '核心'`。
   现在统一解析成**绝对路径**。
2. **写权限探针误报**：探针用"非法路径 CREATE"，服务端在路径已存在时回
   `errno:2`（文件已存在）—— 这**恰恰证明写权限是通的**，
   以前却当成"探针异常"报警。现在 `errno:2` 视为通过。

## 验收记录

* 桥调用 `Cookie登录("__取浏览器会话__")` → `状态=成功`，
  `用户=x894597841`，**写权限探针通过**（`write_error` 为空）；
* 适配器接口级：`新建文件夹` → `errno:0`、`重命名单个` → `errno:0`、
  `删除` → `errno:0`，列表核对目录确实出现又消失（测试目录已清理干净）。

# 追加修复（2026-09-19 02:0x，用户实机启动后报的两件事）

## 一、关窗崩溃：QThread: Destroyed while thread '' is still running → Fatal error: Aborted

用户日志：

```
[01:59:38] 已启动「百度网盘」原 GUI …
[02:01:33] QThread: Destroyed while thread '' is still running
Fatal Python error: Aborted
Thread … [账号状态线]  ← 还卡在 子进程客户端.调用 → future.result()
```

**成因**：关窗时还有 QThread 卡在适配器调用里（`future.result` 最长 120 秒），
Qt 销毁父控件时把**运行中**的 QThread 一起删了 —— Qt 遇到这种情况直接 `abort()`，
**不是 Python 异常，try/except 抓不住**。

**修法（三层）**：

1. `v8_3/界面/后台线程.py` 新增**按窗口记的关窗闸门**：窗口开始关窗时登记自己，
   此后**属于该窗口**的界面线程不再发起新的适配器调用（立刻抛"程序正在关闭"）。
   * 闸门按窗口记（`weakref.WeakSet`）而不是全局开关 —— 自检里连开多个窗口，
     关掉第一个之后新窗口必须还能用（早先写成全局开关时，后面所有窗口的网盘
     调用全被挡了，自检直接卡死）。
2. `主窗口.closeEvent` 重排顺序：
   ①关闸门 → ②关还开着的登录对话框 → ③停在跑的线程（预算 20s，可用类属性调）
   → ④关适配器（让还卡着的调用立刻失败退出）→ ⑤再等一轮（6s）→ ⑥才交给 Qt 销毁。
3. 线程列表卫生：
   * 登录对话框的"账号状态核对"线程跑完就从列表里摘掉再 `deleteLater()` ——
     以前 C++ 对象被销毁、Python 包装还留在列表里，之后任何 `isRunning()/wait()`
     都抛 `libshiboken: Internal C++ object already deleted`，关窗时也就等不到它们；
   * 网盘页 `关闭()` 里"在跑就等 8 秒"（原来只等 2 秒），并先停掉凭证轮询计时器。

复现脚本（离屏，打开扫码对话框 → 让核对线程在飞 → 直接关窗）：
`~/v8_3_工作区/逆向/复现关闭崩溃.py` —— 修前必崩（SIGABRT），修后退出码 0、
进程退出时"在跑的 QThread = 0 个"。

## 二、"百度网盘提示写操作必须带 STOKEN" 的真正原因：**别的进程把它抹掉了**

真机复现出来的链条（这就是用户看到"明明导入过完整会话，一会儿又不行了"的原因）：

1. 浏览器会话导入把完整会话写进 `数据/会话.json`（含 **pan 域 STOKEN**）→ 写操作可用；
2. 桥进程里那份 `会话仓库` 是**进程启动时**读进内存的（当时还没有 STOKEN）；
3. 之后**任何一次** `保存会话(...)`（扫码登录、刷新 bdstoken、回填 uk）
   都会拿着那份旧内存副本 `json.dump` **整体覆盖**文件 → pan 域 STOKEN 被抹掉；
4. 于是又变成"能读不能写"，界面提示"写操作必须带 STOKEN"。

**修法**：`会话仓库.保存会话()` 写盘前先 `_必要时重载()`（按 mtime 比对，
和 `取会话()` 用的是同一套），再合并白名单字段。这样**任何进程写入的字段都不会
被别的进程覆盖**。单测覆盖：先让"另一个进程"写 stoken，再在本进程保存 bdstoken，
断言 stoken 仍在。

## 三、写权限判定与自愈（让用户不用理解上面这些）

* 桥新增 `_写权限状态()`：真打一次写接口，判定 **可写 / 只读 / 未登录**。
  以前只看"STOKEN 字段在不在"，而扫码登录写进来的常是 passport 域那份 ——
  读接口照样通，写接口恒 `errno:-6`，界面就显示"已登录"然后上传失败。
* 判定为**只读**时自动 `_试从浏览器补全会话()`：从本机浏览器调试端口取完整会话
  写回（节流 2 分钟、先探端口在不在，不在就不再反复试）。
* `_确保可写()`（上传/改名/删除的入口）也接了同一个自愈：
  **用户点上传的那一刻**就会自动修好，而不是等他去点登录按钮。
* 界面状态栏据此给出可执行指引："这份会话只能读：上传/改名/删除需要 pan 域
  STOKEN。浏览器里有完整会话，可在登录对话框点「🌐 从浏览器导入完整会话」一键修好。"

# 扫码登录为什么"只读"：pan 域 STOKEN 是**换发**的（2026-09-19 03:0x）

用户实测：扫码登录成功后仍提示
「⚠️ 写操作不可用：这份会话只能读：上传/改名/删除需要 pan 域 STOKEN」。

## 诊断（脚本 `~/v8_3_工作区/逆向/诊断STOKEN来源.py`）

拿扫码登录得到的会话，按顺序打印每一步：

```
原始会话：stoken 9dfe29b56b（passport 域那份）
取 bdstoken(模板变量)：失败 errno=-6
loginStatus 回退：拿到 ae8616ea25（但写接口仍然不行）
写探针(非法路径)：失败 errno=-6            ← 只读

--- 补种 / 换发 pan 域会话 ---
建立网盘会话：OK
种植子域会话：OK
补种后 stoken：a1c9d58d21 | 变了：True     ← 与浏览器那份**完全一致**
补种后取 bdstoken：0fe0a7ce4f（errno 0）
补种后写探针：errno=2（路径已存在）→ **可写！**
```

## 结论

* **pan 域的 STOKEN 不在登录响应里**，而是**访问 pan 域时换发**的：
  `GET passport/v3/login/api/auth/?return_type=5&u=https://pan.baidu.com/disk/main`
  （建立 pan 域会话）+ 子域种植，跑完 stoken 就从 passport 域那份换成 pan 域那份；
* 我们以前**只在"手工导入 Cookie"路径里**跑这两步，**扫码路径漏了** ——
  于是扫码登录永远是"只读会话"：能列目录，上传/改名/删除全 `errno:-6`。
  这正是用户反复遇到的"已登录、用户 -、写操作必须带 STOKEN"。

## 修法

1. **适配器**（`核心/认证/登录服务.py`）：`完成扫码登录()` 在 `换取会话()` 之后
   调用新增的 `建立pan域会话_换发stoken()` —— 建立 pan 域会话 + 走一遍 pan 首页
   + 种植子域，然后对比 stoken 是否变化并记日志（"✅ 已换发 pan 域 STOKEN（写权限就绪）"）。
2. **桥**（`v8_3/桥/后端_百度.py`）：`_写权限状态()` 判为"只读"时**先自己救一次**：
   `_补种pan域会话()` → 重新取 bdstoken → 再打一次写探针；救不回来才报只读，
   并给出可执行指引（自动从浏览器导入 / 手动导入 / `V8_3_浏览器调试端口=<端口>`）。
3. `_确保可写()` 同样接这条自愈链：**用户点上传的那一刻**就会先补种、再补浏览器会话。

## 实测

* 把会话人为改成"只读"后启动：桥先补种（日志「已补种 pan 域会话」）→
  复测仍只读 → 自动从浏览器导入 → `写权限=可写（已自动从浏览器补全会话）`
  → 真建目录 ✅ → 列目录确认 ✅ → 删除 ✅；
* 单测 631 项全绿；界面自检 427 项全绿。

# 扫码会话为什么进不了网页版 pan 域（2026-09-19 03:1x，把根因钉死）

用户第二次扫码后仍是只读，且这次连浏览器调试端口都没开（自动补全也失败）。
把会话拆开逐条打，得到**决定性证据**：

```
会话：bduss 5JNHFkTGFm | stoken 79b8bf03dc（passport 域那份）

GET https://pan.baidu.com/disk/main        ← 网页版
  → 200，但被重定向到
    /disk/main?errmsg=Auth Login Params Not Corret
    Set-Cookie 只有一个 PANPSC=（清空）

GET https://pan.baidu.com/api/list         ← 网盘 API
  → 200，正常返回（读接口通）
```

**结论：扫码登录拿到的 BDUSS 只能用于网盘 API，进不了网页版 pan 域。**
而 **pan 域的 STOKEN 是网页版登录时才下发的**（API 通道不换发），
所以这份会话天生"只能读"：`/api/list` 通，`/api/gettemplatevariable` 与
所有写接口 `errno:-6`。这也解释了为什么"换发 pan 域 STOKEN"那一步在
扫码会话上永远拿不到变化 —— 不是代码没跑，是**服务端不会给**。

对照：浏览器里那份会话（网页版登录）同一时刻 `/disk/main` 正常、STOKEN 齐全、
写操作全通（实测建目录/改名/删除 errno:0）。

## 因此的工程结论

1. **扫码登录 = 只读会话**（这个账号/这条链路下）；要写就必须有一份**网页版会话**：
   * 浏览器登录 pan.baidu.com → 点「🌐 从浏览器导入完整会话」（一键，已实测可用）；
2. 所以把"写权限"做成**登录后立刻判定 + 自动自愈 + 如实告知**，而不是让用户
   在几轮之后才发现上传失败：
   * 扫码登录成功后**当场** `_写权限状态()` 实测；
   * 只读 → 自动补种（3 次×0.6s，便宜）→ 仍只读 → 自动从浏览器补全会话；
   * 都不行就把**具体原因**写进登录提示与网盘页状态栏
     （例如"没有找到开着调试端口的浏览器"），用户按提示做一步即可；
3. `_确保可写()`（点上传那一刻）跑同一条自愈链，所以即使会话在别处被换掉，
   用户点上传时也会先自动修。

## 验收

* 单测 631 项全绿；界面自检 427 项全绿；
* 浏览器可用时：只读会话 → 自动补全 → `写权限=可写（已自动从浏览器补全会话）`
  → 真建目录 ✅ / 列目录确认 ✅ / 删除 ✅；
* 浏览器不可用时：状态栏明确显示"没有找到开着调试端口的浏览器…"，
  并给出两条可执行路径（用带调试端口的浏览器 / 设 V8_3_浏览器调试端口=<端口>）。
