# 跨网盘直链传输修复记录（2026-09-16）

复现方式：自动生成"最容易让直链传输失败"的文件 → 上传夸克 → 夸克 → 光鸭 跨盘传输
→ 核对"引擎报完成 vs 目标端实际落地"。两个工具可随时重跑：

```bash
cd <项目根>
PY=<项目根>/运行环境/venv/bin/python

$PY 工具/直链失败复现.py      # 25 个边界形态（空文件/特殊字符/emoji/换行/超长/敏感词/深层/大文件…）
$PY 工具/直链压力复现.py --小 150 --大 5 --大MB 12   # 并发压力 + 落地核对
```

> 两个工具都会在云上建 `V8_3_直链诊断_*` / `V8_3_压力_*` 临时目录，
> 跑完自动删除；`--保留` 可留档人工检查。

## 一、定位到的 4 个真问题

### 1. 源路径"刚上传完就查不到" → 传输报"源路径不存在"（最终一致性 + 10 秒缓存放大）

* 夸克/光鸭服务端对**刚上传的文件**有 1–3 秒可见性延迟；
* 夸克后端 `_列一层` 有 **10 秒 TTL 缓存**，`_找子项`（点查）默认吃这个缓存，
  于是"上传完立刻查"在 10 秒内一直返回"不存在"；
* 实测复现：先列一次目录 → 上传 → 立刻 `文件信息` → **找不到**，3 秒后**仍找不到**；
  再上传一个（触发缓存失效）→ 才看得到。

**修复**：
* 夸克/光鸭后端 `_找子项(…, 用缓存=False)`：**点查（stat/文件信息/重名检查）一律读实时**，
  只有列目录浏览走缓存；
* 引擎新增 `_确认源存在()`：源路径查不到时**重试 4 次 × 1.5s**，恢复后照常传输，
  日志会打 `源路径第 N 次查询才可见`。

### 2. 并发建目录竞态 → `file is doloading[同名冲突]`（上传/传输入口失败）

* 实测：8 个线程并发上传到**尚未创建**的目录 → **5/8 失败**，
  错误是夸克服务端的 `file is doloading[同名冲突]`；预先建好目录 → **0/8 失败**；
* 原因：夸克后端 `创建文件夹()` 抛异常时**没有兜底**（只有"返回空 fid"才重查），
  并发抢建目录时输的一方直接把异常抛给上层。

**修复**：
* 夸克/光鸭后端新增**按路径加锁**（`_路径锁`）：同一条目录只让一个线程"查—建"；
* 夸克新增 `_建目录并定位()`：建目录异常/无 fid 时 **重查 + 退避重试 4 次**；
* 光鸭原有的"重查一次"升级为**重查 4 次（0.6/1.2/2.4/3s）**。
* 回归：同一并发场景 **0/8 失败**（三种场景各 8 并发放到未创建目录）。

### 3. 敏感词文件直接失败 → 守卫漏检光鸭的真实文案

* 边界用例里 `敏感词总统选举.txt` 传输失败：
  `适配器错误: [guangya/] 名称不可用，请更换后重试`；
* 这句是**光鸭服务端**的原文（我们代码里没有），而上传守卫的 `拦截关键词` 表
  只有 `405/403/敏感/违规/禁止…`，**没有"名称不可用"** → 预检改名与 P1–P4 探测式绕过
  全都没触发。

**修复**：`拦截关键词` 补齐各家"文件名不可用"类文案
（`名称不可用`/`请更换后重试`/`名称非法`/`命名不符合`/`invalid name`…）。
修复后该类文件会走绕过（改名 + 学习安全词）而不是失败。

### 4. 瞬时错误退避太短 → 重试次数被"服务端处理中"耗光

* 引擎原来统一 `1.5^n` 退避（1.5/2.25/3.4s），对"同名冲突/正在处理/内部错误/限流"
  这类需要几秒到几十秒才恢复的状态不够；
* 现在引擎区分两类：
  * **瞬时**（doloading/同名冲突/超时/连接/5xx/429/限流/内部错误…）
    → `3/6/12/24s`（上限 60s）；
  * **非瞬时**（认证、权限、参数、不存在、敏感词…）→ 原节奏，且不误判重试。

另外给夸克下载补了**直链失效重取**：直链是签名 URL，会过期/被限流，
下载失败且属于 403/404/过期/瞬时类时，重取一次链接再试（引擎级重试会从零开始，更贵）。

## 五、目标同名语义（2026-09-16 明确化）

原实现只看**文件名**，而且预检查在 `覆盖` 判断之前就跳过了——所以
「勾了覆盖也照样跳过」、**同名但大小不同的半截文件会被当成"已传过"静默跳过**
（可能导致目标端缺内容）。现在按"类型 + 大小 + 覆盖开关"判定：

| 目标端情况 | 覆盖关（默认） | 覆盖开 |
|---|---|---|
| 不存在 | 正常传输 | 正常传输 |
| 同名，大小一致 | 跳过：`目标已存在` | 删除后重传 |
| 同名，大小不同 | 跳过：`同名但大小不同（目标 150 B / 源 300 B）：勾选「覆盖」可替换` | 删除后重传（内容与源一致） |
| 同名是文件夹 | 跳过：`目标同名是文件夹` | 删除该文件夹后上传为文件 |
| 同名，源大小未知（未上报 size） | 跳过：`目标同名（源大小未知，按已存在处理）` | 删除后重传 |

设计取向：**默认不覆盖用户已有文件**，但把"同名不同大小"这种可疑情况**明确说出来**
（而不是静默跳过），需要替换时勾选「覆盖」。

实测（夸克 → 光鸭，`工具/同名与续传复现.py`）：

```
① 同名+大小一致（覆盖关）      → 跳过   目标已存在
② 同名+大小不同（覆盖关）      → 跳过   同名但大小不同（目标 150 B / 源 300 B）：勾选「覆盖」可替换
③ 同名+大小不同（覆盖开）      → 完成   内容=源 ✅
④ 同名是文件夹（覆盖关）       → 跳过   目标同名是文件夹
⑤ 同名是文件夹（覆盖开）       → 完成   目标形态=文件 ✅
```

## 六、大文件断点续传（2026-09-16 新增）

原实现：下载失败就把中转文件删掉，重试**从 0 重下**——弱网下大文件几乎传不完。
现在：

* **分段下载**每段落盘为 `<目标>.v8_3partN`，进度写进 `<目标>.v8_3resume.json`
  （总大小 + 指纹 + 每段区间/已完成字节）；失败时**保留**，下次按
  `Range: bytes=<已下载>-<段止>` 续传；
* **单连接回退**同样可续传（`Range: bytes=<已有>-` 追加）；服务端不支持 Range
  （返回 200）时自动改为重下，避免把新内容接在旧内容后面；
* 防御：分片写入按区间**封顶**（服务端忽略 Range 末端时丢弃多余字节）、
  状态周期性落盘（每 4 MiB + 每次失败）、合并先写临时文件再原子替换；
* 引擎：重试时**保留中转分片**并在日志里报"复用已下载 X MiB"；任务结束
  （完成/失败/取消）统一清理分片与状态；适配器不支持 `续传` 形参时自动按老签名调用
  （向后兼容第三方适配器）；
* 后端：本地已有断点时**不再回退到适配器下载器从 0 重下**，而是上抛让引擎续传。

实测（`工具/同名与续传复现.py` B 段 + 引擎级注入断流）：

```
基线下载 12 MiB → 截断到 4 MiB →
续传后 12 MiB，哈希一致 ✅，只补剩余部分 ✅
```

引擎级（`V8_3_DL_ABORT_AFTER=4194304` 注入一次性断流）：

```
[夸克] 下载中断：已保留断点 4.0 MiB / 12.0 MiB，重试将从断点续传
[引擎] 任务失败（第 1 次）→ [引擎] 保留断点 4.0 MiB，下次续传
[引擎] 3.0s 后重试（服务端暂时不可用）第 2 次
[引擎] 断点续传：复用已下载 4.0 MiB → [夸克] 续传：单连接从 4.0 MiB 继续
统计：完成 1，失败 0，11.2s；目标文件 12.0 MiB 哈希一致 ✅
```

单测：`tests/test_断点续传.py`（8 项，本地 HTTP 服务器模拟中途断流）、
`tests/test_同名语义.py`（7 项）。

矩阵过程中新发现并修掉的问题：

### 7.1 百度：上传**忽略 `name` 参数**（严重）

百度上传接口只认本地文件名（没有"另存为"参数），而 V8_3 原来直接传了引擎的中转文件
→ **夸克→百度 / 光鸭→百度的目标文件名会变成引擎缓存名**（如 `3f9a....bin`）。
修复：用硬链接别名把目标名落到本地文件名上（夸克/光鸭本来就这么做，百度漏了）。

### 7.2 目标盘命名限制 → 上传前自动规避（新增 `v8_3/敏感词/命名规避.py`）

实测百度 `/api/create` 的真实限制（**与文件大小无关**）：

| 名字 | 结果 |
|---|---|
| `引号'单"双.txt` | ❌ 文件名中不能包含 `? \|"><:*` 等特殊字符 |
| `换行\n名字.txt` | ❌ 文件名中不能包含不可见字符 |
| `emoji🎬🦆.mp4` | ❌ 接口返回异常（星平面字符直接让接口报错） |
| `末尾空格 .txt` / `一字节.bin` | ✅ 正常 |

> ⚠️ 陷阱：**秒传命中会绕过这层校验**（同样内容重传一次居然成功），
> 只有"真实上传"才能看到真相；夸克/光鸭实测无此限制。

规避规则：非法字符 → 全角等价（`"`→`＂`、`?`→`？`…）；不可见字符 → 空格；
emoji/星平面 → 移除（若清空则回退 `未命名_<4位哈希>`）；改名写进**改名记录**，
下载还原原名照旧可用。

### 7.3 上传成功 ≠ 立刻可见 → 上传后可见性确认（关键）

实测夸克：**12MB 文件上传返回成功后，列目录 1–3 秒内看不到它**。
后果：紧接其后的跨盘传输在"扫描源"时漏掉这个文件 ——
**没有报错、没有失败，就是少传了**（实测 12 个文件只传了 11 个）。
修复：每个后端上传成功后轮询父目录确认可见（5 次 × 1.2s），并顺带拿到
**服务端实际落盘名**（夸克会把引号存成 `&#39;`/`&quot;`）回传，供改名记录使用。

### 7.4 直链彻底不通 vs 中途断流（细分处理）

实测光鸭偶发 `peer closed connection ... received 0 bytes`（链接本身不通）。
原逻辑"本地有断点就上抛续传"在这种情况会白等重试；现在区分：

* 本次**搬动过字节** → 中途断流 → 上抛，下次按 Range 续传；
* 本次**一个字节都没动** → 链接不通 → 回退适配器自带下载器（覆盖断点也要传完）。

### 7.5 对称补齐（夸克→光鸭 之外的方向）

| 能力 | 夸克 | 光鸭 | 百度 |
|---|---|---|---|
| 上传瞬时错误重试 | ✅ | ✅（本次补） | ✅（本次补） |
| 目录并发锁 `_路径锁` | ✅ | ✅ | ✅（本次补） |
| 建目录重查重试 | ✅ | ✅ | ✅（本次补） |
| 直链续传 + 断流上抛 | ✅ | ✅ | ✅（本次补） |
| 命名规避 | ✅（无限制） | ✅（无限制） | ✅（本次补，含名称限制表） |
| 上传后可见性确认 | ✅（本次补） | ✅（本次补） | ✅（本次补） |

## 八、传输失败兜底 + 磁盘占用控制（2026-09-16 新增）

### 8.1 兜底阶梯

```
常规尝试（可配 重试次数）
  └─ 直链多段续传 → 直链单连接续传 → 适配器原生下载
       └─ 仍失败 → 【兜底】「源 → 本地 → 目标」保守模式
            · 清干净中转（分片/续传状态/半成品全部丢弃）
            · 跳过直链，直接用适配器自带下载器（另一条鉴权/服务器路径，实测能救回）
            · 串行执行（传输.兜底串行，默认 1）——同批多个失败也不会同时铺开大文件
            · 成功则计 统计.兜底成功，任务详情标「完成（兜底：本地中转）」
```

真机实测（夸克→光鸭，12 MiB，注入直链前两次都断）：

```
[引擎] 任务失败（第 1 次）… 保留断点 0.3 MiB
[引擎] 3.0s 后重试（服务端暂时不可用）第 2 次 → 又断
[引擎] 兜底：常规重试失败…，改用「源→本地→目标」保守模式
[夸克] 保守模式：跳过直链，直接用适配器原生下载
[引擎] 兜底成功 → 目标 12.0 MiB 哈希一致 ✅
```

开关：界面「失败后本地中转兜底」勾选框 / `传输.失败兜底`（默认开）。
关掉就照常失败，不会偷偷重试。

### 8.2 磁盘占用：暂存预算（这是"尽量减少磁盘占用"的核心）

| 机制 | 说明 |
|---|---|
| **总量上限** | `传输.暂存上限GB`（0=自动：剩余空间的 1/4、最多 4 GiB） |
| **系统余量** | `传输.磁盘余量GB`（默认 1）——永远给系统留这么多，不碰 |
| **额度预留** | 下载前先拿额度，拿不到就**排队等待**（日志每 5 秒报一次"暂存额度等待中"），超时给明确报错而不是把磁盘写满 |
| **大文件按 2× 计** | 多段下载真实占用是"分片 + 合并副本"两份（实测 12 MiB 文件峰值 24 MiB），所以 ≥8 MiB 的文件按 2 倍预留，预算才是真的"不会超" |
| **超大单文件放行** | 单个文件比上限还大时放行（文件不能切块上传），并打日志提醒 |
| **立刻归还 + 立刻删** | 任务一结束（成功/失败/取消）就释放额度并删掉中转文件（含 `.v8_3part*`、`.v8_3resume.json`、`.v8_3merge`） |

真机实测（4×12 MiB = 48 MiB，上限设 30 MiB）：

```
★ 完成 4/4，耗时 24.0s
★ 中转峰值 24.0 MiB（≤ 上限 30 MiB；不设限时最高会同时铺 48 MiB）
★ 预算日志：[引擎] 暂存额度等待中：需要 24.0 MiB，当前可用 6.0 MiB
★ 结束时中转残留：（无）
```

也就是说：**峰值磁盘占用由配置封顶，而不是由"文件总量"决定**；
批量越大越省（多出来的文件在排队，不是在占盘）。

单测：`tests/test_兜底与磁盘.py`（9 项：兜底救回/关掉即失败/兜底失败如实报错/
兜底清中转/预留释放/超额等待超时/超大放行/释放后等待者拿到/取消立刻放弃）。
