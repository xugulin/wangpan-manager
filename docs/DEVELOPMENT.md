# 网盘管理 V8_3

**目标：彻底去掉 Alist，直接调用百度/光鸭/夸克三个自研适配器的原生接口，做跨网盘传输与性能优化。**
界面采用 网盘管理_V8 的形态（左侧导航 + 切换式页面 + 10 套主题），并支持**同一家网盘挂多个账号**。

V8_3 不复用 Alist，也不修改三个适配器的源码：每家适配器运行在独立子进程里，
V8_3 用统一的 `云盘适配器` 接口通过行式 JSON 协议驱动它们。登录管理直接启动各家
适配器原来的 GUI，因此凭证、设备指纹、上传协议仍由经过真机验证的适配器核心负责。

* **原来的「网盘管理」标签页已废弃**：每个网盘在左侧导航栏各占一个按钮，
  点击即以「切换页面」的方式打开该网盘页，不再弹新窗口；
* 左侧导航栏宽度固定（74px），**高度始终占满整列、不随内容缩水**；
  按钮按自己的固定高度排列（网盘 58px / 功能 60px / 网盘管理 52px），
  **窗口拉矮也不会把它们压扁**——装不下时整列出现纵向滚动条，上下滑动即可看到
  溢出的按钮（网盘列表另有自己的内层滚动区，所以功能按钮始终露着）；
  > 这条以前是坏的：主题 QSS 给按钮写了 `padding`，Qt 会据此把控件的**最小高度**
  > 算成「文字高 + 上下内边距」（60px 被压成 42px），窗口一矮布局就顺着这个最小高度
  > 把按钮挤扁、两行文字被裁掉。现在高度由 QSS 的 `min-height` 与代码共用同一份
  > 常量（`主题管理器.高度_功能按钮` 等）钉死，`主窗口._钉死左侧栏尺寸()`
  > 在每次套主题后再钉一遍。
* **页面装不下时整页滚动，不压缩控件**：AI 页控件最多（按设计高度排下来约 1040px），
  窗口矮的时候不再把横幅/详情框挤扁、也不会让分组框叠在一起 —— 内容保持设计高度，
  右侧出现细滚动条，上下滑动即可看全（与左侧栏同一套做法：`QScrollArea` +
  `不压缩内容`，见 `v8_3/界面/AI页面.py`）；
* 左下角新增一个纵向「网盘管理」面板：**新增网盘 / 编辑网盘 / 删除网盘**；
* 「登录 / 管理」仍然是启动适配器原 GUI（独立子进程）：三家适配器的顶层包名
  都是 `核心` / `界面`，同一个解释器里无法共存，所以只能以子进程方式打开。

### 多实例（同一家网盘多个账号）

一个网盘 = 一个**适配器实例**，用 `标识`（如 `baidu`、`baidu_2`）唯一区分：

| 字段 | 说明 |
|---|---|
| 标识 | 全局唯一键，引擎 / 任务数据库 / 导航按钮都用它 |
| 类型 | 用哪个桥后端：`baidu` / `guangya` / `quark` / `fake` |
| 名称 | 界面上显示的名字（导航按钮、日志、统计） |
| 路径 | 适配器项目目录；**登录凭证在该目录的 `数据/` 下，一账号一份** |
| 线程数 | 该网盘桥进程里的并发工作线程数 |
| 启用 | 关掉后导航栏隐藏该网盘，配置与登录数据都保留 |

同一家网盘的第二个账号需要**独立的适配器目录**，否则两个实例会共用一份登录数据。
「新增网盘」对话框内置 **「复制适配器项目…」**：复制一份适配器项目（自动跳过
`数据/`、`__pycache__`、`.git`），新目录登录数据为空，点「登录 / 管理」登录另一个
账号即可。CLI 里等价于 `网盘新增 --类型 baidu --副本`。

> 删除网盘只从 `配置.json` 里移除该实例：**适配器目录、登录数据、网盘上的文件
> 都不会动**。

### 统一登录（6 种方式，一个入口）

网盘页管理区两个按钮分工明确：

* **「🔐 登录 / 管理」** → V8_3 的**统一登录对话框**（6 种方式，见下表）；
* **「🖥 适配器原 GUI」** → 启动该适配器自带界面（独立进程）。需要适配器原始的
  完整功能（账号管理、上传记录、分享等）时用它，V8_3 只读取它的登录结果；
* 左侧导航右键菜单：🔐 登录 / 换账号… · 🔄 刷新登录状态 · ✏️ 编辑网盘… · 🗑 删除网盘。

统一登录对话框里 6 种方式的能力矩阵如下——各适配器按自己核心真实支持的能力申报，
不支持的页签置灰并写明原因：

| 方式 | 百度 | 光鸭 | 夸克 | 说明 |
|---|---|---|---|---|
| 🔳 扫码登录 | ✅ | ✅ | ✅ | 图片二维码（百度/夸克）或**设备码**（光鸭：验证地址 + 用户码） |
| 🍪 导入 Cookie | ✅ | — | ✅ | 百度：BDUSS+STOKEN；夸克：`__pus/__kps/__uid` |
| 📱 短信登录 | — | ✅ | — | 手机号 → 验证码（含盾 token 流程，60s 倒计时） |
| 📧 邮箱登录 | — | — | — | 三家适配器核心都未提供 → 置灰 + 说明 + 原 GUI 兜底 |
| 🔑 令牌登录 | — | ✅ | — | 直接写 access/refresh 令牌（光鸭是令牌型网盘） |
| 👤 账号密码 | — | — | — | 三家适配器核心都未提供 → 置灰 + 说明 + 原 GUI 兜底 |

* 能力来自桥命令 `auth_caps`：**各适配器按自己核心真实支持的能力申报**，
  不支持的页签置灰并写明原因，**不谎报支持**；
* 「📧 邮箱登录」「👤 账号密码」这两页保留在界面上（协议里也定义了
  `login_email` / `login_password`），将来某个适配器实现了对应接口就会自动点亮；
  现在点进去会看到原因说明和「🖥 打开适配器原 GUI」兜底按钮；
* 习惯适配器原界面的话，旁边的「🖥 适配器原 GUI」按钮随时可用；
* 扫码成功后对话框 1.5 秒自动关闭，并刷新该网盘页的状态与导航提示；
* 「🖥 适配器原 GUI」按钮仍在网盘页保留（需要适配器自带完整界面时用），
  左下角导航的右键菜单也加了「🔐 登录 / 换账号…」；
* 登录过程全部走后台线程，界面不卡；日志同时进终端与日志页。

协议（`v8_3/桥/后端_基类.py` 的「统一登录协议」段 + `工作进程.py` 分发 +
`子进程客户端.py` 封装）：

```text
auth_caps                     → {方式: {支持, 说明}} × 6
login_qr_start                → {类型: 图片|设备码, 图片base64|验证地址+用户码, 会话, 有效期秒}
login_qr_wait(会话, 超时秒)    → {状态: 成功|超时|已取消|失败, 消息, 账号}
login_qr_cancel(会话)          → {状态: 已取消}
login_cookie(文本)             → {状态, 消息, 提示, 账号}
login_sms_send(手机号)         → {状态, 消息, 会话, 提示}
login_sms_verify(会话, 验证码) → {状态, 消息, 账号}
login_token(访问令牌, 刷新令牌) → {状态, 消息, 账号}
login_password / login_email   → 默认「不支持」，留给将来的适配器
```

假网盘实现了全部 6 种（`后端_假.py`），所以离线也能把整条链路跑通、可自检。

### 跨网盘传输页

```
源网盘：[下拉]   源路径：[输入] [📂 浏览…]
目标网盘：[下拉] 目标路径：[输入] [📂 浏览…]
☐覆盖目标已存在文件  总并发[自动]  重试[3]  ☐保留失败中转文件  ☑用 AI 调整并发/优先级
[▶ 开始传输] [⏹ 停止] [♻ 恢复批次] [🔁 重试失败] [🧹 清空列表]      统计文本
┌ 任务表格：文件 / 状态 / 进度 / 大小 / 速度 / 剩余 / 错误 ──────────┐
├ 传输状态面板（沿用 V8 表格下方那条横向统计栏）────────────────────┤
│ 📋 队列: N │ 📝 任务: <状态> │ 🧭 决策来源: <谁定的> │ ⚙ 当前决策: <定了啥> │
│ 📊 总大小 · 🆕 新上传 · 🔄 覆盖 · ⏳ 等待 · ⏭️ 跳过 · ❌ 失败       │
│ 计算网速 ⬆/⬇ │ 📦 文件速率(个/秒·分·时·天 自动) │ 已耗时/预计 │ 倒计时 │
└──────────────────────────────────────────────────────────────────┘
```

* 源/目标各占一行（网盘与路径在同一行），沿用 V8 的组件排布；
* V8 那条统计栏里的 **「Alist网速」已去掉**，换成 **文件速率**：
  `已完成文件数 ÷ 本次耗时`，单位按数值自动切换
  （≥1 → 个/秒；≥1/分 → 个/分；≥1/小时 → 个/小时；更小 → 个/天）；
* 队列数、字节分布（总大小/新上传/覆盖/等待/跳过/失败）、计算网速、
  已耗时/预计、倒计时都是实时刷新（1 秒一次，倒计时按剩余字节与平均速度推算，
  大小未知时退回按剩余文件数÷文件速率推算）；
* 第一行还显示 **🧭 决策来源** 与 **⚙ 当前决策**：
  - 决策来源：`AI 决策` / `AI 缓存命中` / `AI 相似复用` / `AI 运行时调优`
    / `规则基线` / `本地任务` / `恢复批次`（带 AI 置信度时会一并显示）；
  - 当前决策：这一批实际采用的并发、优先级规则、分批策略与原因，
    例如 `并发 16 ｜ 优先 大文件优先、敏感词提前改名 ｜ 规则基线（AI未启用）`；
  - 鼠标悬停有完整内容，批次结束后仍保留最后一次决策，便于事后核对。
* 同一时刻只跑一批本地上传/下载；期间再加任务会**自动排队**，跑完接着传。

### 敏感词（V8 的敏感词功能 + 上传守卫）

左侧「🔒 敏感词」页 = V8 的敏感词管理页（敏感词表 + 改名记录 + 统计栏），
传输侧改成适配 V8_3 直连结构的**上传守卫**：

1. **上传前预检改名**：扫描文件名命中的已知敏感词，用已学到的安全词替换后上传，
   并写入改名记录（下载/播放时可按云端名反查原名）；
2. **被拦后探测式绕过**（沿用 V8 的 P1–P4 策略）：上传报错且错误信息像
   `405/敏感/违规/禁止/blocked…` 时，如果文件不大（默认 ≤32MiB），把内容读进内存
   ——P1 已知词批量替换 → P2 单段探测 → P3 组合探测 → P4 全中文化保底，
   成功即把学到的"敏感词 → 安全词"写库；
3. **学习闭环**：改名成功记"安全词生效"，失效记"已失效安全词"，下次自动换候选；
4. **按键隔离**：词库按**网盘实例标识**分组，同一家网盘的多账号各学各的；
5. 上传/下载任务、跨网盘批次（引擎内部）都会走同一个守卫；
6. 页面顶部两个开关（总开关 / 上传前自动改名）直接写回配置，关掉即完全不做改名。

相对 V8 的修复：**P1 分支原来没有写改名记录**（导致下载无法还原原名），已补上；
探测上传走本地临时文件而不是常驻内存；日志改走界面日志页。

### AI（V8 的 AI 层 + 调度）

左侧「🤖 AI」页 = V8 的 AI 状态页：余额/阈值/预算摘要、时段与开关、
模型下拉、DeepSeek 价格表（缓存命中/未命中/输出、便宜·中等·昂贵着色）、
调度器与学习库统计、刷新价格/刷新余额/从 V8 配置导入密钥。

调度侧与 V8 对齐（引擎里实现，界面可总开关）：

| 环节 | 行为 |
|---|---|
| 批次策略 | 扫描完源目录 → 队列特征分析 → `请求策略` → 采用返回的并发数 |
| 文件优先级 | `请求文件优先级` → 按分数重排待传任务（大的/敏感的优先） |
| 运行时调优 | 每 10 秒按吞吐/失败率/队列长度问一次，动态调并发上限 |
| 失败诊断 | 任务最终失败时后台问一次"怎么处理"，结论写日志（不阻塞传输） |
| 效果回填 | 批次结束把真实吞吐/失败率/耗时回填学习库，越用越准 |

* AI 层在 `v8_3/AI/`：`队列特征分析`、`时段预算`（时段/预算管理器）、
  `AI学习库`、`DeepSeek价格抓取`、`AI智能助手`、`AI调度器`、`运行时`（门面）。
  **依赖只用 httpx**（V8 用的 requests 已换掉），不 import V8 任何模块；
* **降级**：没填密钥 / AI 关闭 / 预算熔断 / 高峰时段 → 全部走规则基线，
  不联网、不报错、不影响传输；
* **时段语义**（V8 原样）：配置里 `AI.高峰时段` 表示**不调用 AI** 的贵时段，
  区间外（空闲）才调 AI。DeepSeek 的夜间折扣窗口是 00:30–08:30，
  所以默认填 `08:30–00:30`，AI 会在折扣窗口自动工作；
  想随时都用 AI：AI 页点「切换模式」强制开启，或把 `AI.高峰时段.启用` 设为 false；
* **密钥**：`配置.json` 的 `AI.api密钥`（也认环境变量 `V8_3_AI_KEY`）。
  首次可以把旧项目里的密钥一键导进来：AI 页 →「📥 从 V8 配置导入密钥」
  （只读 `网盘管理_V8/配置.json`，只写 V8_3 的配置，不回写旧项目）。

能力接进窗口，**AI 只负责它真正擅长的四件事**：起播决策、字幕翻译、无字幕生成、卡顿调优。

| 需求 | 落地 |
| --- | --- |
| 流畅播 4K 及以上 | 实测带宽 vs 码率决策缓存窗口（4K 12–20s）+ 硬解核实 + HTTP 请求头；**4K HEVC 嵌窗口实测实时、丢帧 0** |
| AI 辅助加载视频 | 起播前给"缓存/硬解/是否可流畅/风险"，来源标注（学习库→本地模型→云端→规则） |
| AI 翻译字幕 | 读 SRT 分批翻译 → 写 `_AI中文.srt` → 自动挂载并选中 |
| 无字幕 AI 生成字幕 | faster-whisper（项目内 899MB，可删）→ SRT → 可再翻译/总结 |
| AI 优化播放 | 每 500ms 采样丢帧/缓冲 → 诊断 → 换参数**重启到原位置**（libvlc 关键选项只能起播前生效） |
| AI 总结 | 字幕/识别结果 → 摘要、看点、时间线 |
| 不污染系统环境 | `数据/运行环境/{config,data,cache}` 接管 VLC 的 XDG 目录 |

**本机实测（不吹）**：CPU 软解 4K H.264 **48.5 fps（1.94× 余量）**、4K HEVC **43.4 fps
（1.73×）**；嵌进播放页窗口播 4K HEVC **实时、丢帧 0**。
**Intel VAAPI 已装并可实测生效**：同一段 4K HEVC 播 10 秒，硬解 CPU **2.81s**、
软解 **17.93s**（差 6.4 倍），两者都实时零丢帧。播放页会显示当前是不是真在硬解
（`硬解能力()` 按**显卡厂商 + 匹配的 VA 驱动文件**核实，不做"看到 /dev/dri 就宣称硬解"
这种过度承诺）。
细节、踩坑与限制见 `docs/播放器.md`。

> 踩过的坑：VLC 3 没有 `libvlc_media_player_get_spu`，回退名没设 `argtypes` 时
> ctypes 会把 64 位播放器句柄**截成 32 位** → libvlc 拿野指针加锁 → **整个进程段错误**
> （一播放就崩）。现在所有符号强制走 `取函数()` + 句柄过 `校验句柄()`，
> 并由 `tests/test_播放层.py` 锁死。

## 性能设计（针对“批量小文件极慢”）

旧 V8 慢在 Alist/WebDAV 转发 + 每个文件一次元信息 + 单线程串行。
V8_3 的对策：

1. **直连原生接口**：下载走各家签名直链，上传走各家原生 OSS/分片协议，中间没有 Alist。
2. **适配器子进程 + 每进程线程池**：三家适配器都要占用顶层包名 `核心`，天然不能同进程共存；
   子进程还带来独立 httpx 连接池和故障隔离。
3. **小文件高并发 / 大文件低并发**：默认 `小文件并发=12`、`大文件并发=3`，
   避免大文件把上行带宽打满后拖死小文件。
4. **目标预检查按目录聚合**：先在目标父目录列一次目录，而不是每个文件发一次元信息（消除 N+1）。
5. **本地中转缓存优先 `/dev/shm`**：源适配器流式下载到内存盘，目标适配器再从本地流式上传。
6. **重试可续**：失败保留/清理中转文件可配；适配器层自带连接重试，引擎层再做任务级重试。
7. **目录缓存**：同一目标目录只创建一次；ID 型网盘（光鸭/夸克）缓存路径→目录 ID。
8. **自适应并发**：每 3 秒按吞吐与失败率调整许可上限；失败先降，吞吐持续上升再升。
9. **任务落盘**：每个任务写入 SQLite；宿主重启后用 `恢复` 继续，已完成/已跳过文件不会重传。
10. **大文件多段下载**：≥ 配置阈值（默认 32MB）时自动用 4 段 Range 并行下载，
    服务端不支持 Range 会自动回退单连接（见 `配置.example.json` 的 `下载`）。
11. **并行源目录扫描**：目录树按层并发列目录（8 并发），大目录枚举不再串行。
12. **并行本地目录上传**：CLI 上传目录支持 `--并发`；基准工具 `--校验`
    会在传输后回载目标端做 SHA-256 全量比对。

### 实测数据（2026-09-15）

| 场景 | 数据 | 结果 |
|---|---|---|
| 夸克→光鸭 | 32 个文件，3.07 MiB（30 个小文件 + 1 个 3MB） | 25s，32/32 成功，10 并发 |
| 其中 2KB 小文件 | 30 个 | 单个约 2.3–3.6s（协议往返为主） |
| 其中 3MB 文件 | 1 个 | 5.3s |
| 夸克→光鸭 单文件 | 2KB | 2.4s，SHA-256 一致 |
| 光鸭→夸克 单文件 | 2KB | SHA-256 一致 |
| 全量回载校验 | 31 个文件 | 哈希全部一致，0 错误 |
| 42 个小文件（2KB） | 夸克→光鸭 | 22.2s，42/42 成功，16 并发+自适应 |

## 直链传输的健壮性（2026-09-16 修复）

跨网盘传输走"源盘直链下载 → 本地中转 → 目标盘上传"，实测定位并修掉了四类失败来源
（详见 `docs/直链传输修复记录.md`，两个复现工具可随时重跑）：

| 问题 | 现象 | 修复 |
|---|---|---|
| 最终一致性可见性 | 刚上传完就传，报"源路径不存在"（夸克列缓存 10s 把它放大） | 点查改实时读取 + 引擎 `_确认源存在()` 重试 4×1.5s |
| 并发建目录竞态 | 多线程上传到未创建目录 → `file is doloading[同名冲突]`（实测 5/8 失败） | 按路径加锁 + 建目录重查重试（回归 0/8） |
| 敏感词文案漏检 | 光鸭返回「名称不可用，请更换后重试」不在关键词表里 → 绕过没触发 | 关键词表补齐各家"文件名不可用"文案 |

**目标同名语义**（2026-09-16 明确化）：默认**不覆盖**用户已有文件——
同名且大小一致→跳过；同名但**大小不同**→跳过并说明两边大小（勾「覆盖」可替换）；
同名是文件夹→跳过并说明；勾「覆盖」时一律先删后传（对预检命中的也生效）。

**大文件断点续传**（2026-09-16 新增，默认开 `传输.断点续传`）：
