# 本地 DeepSeek 模型（V8_3 新增能力）

> **一句话**：V8_3 可以**免费、离线、不上传数据**地跑 DeepSeek —— 装一个本地推理
> 运行时（推荐 Ollama），拉一个 DeepSeek 模型，AI 就再也不用花云端 token 的钱。

---

## 一、它解决什么问题

V8_3 的 AI 层（策略/优先级/诊断/调优）原本只能走 DeepSeek 云端 API：

* 要密钥，没密钥就降级成规则调度；
* 要花钱（虽然便宜），还要看价格、算预算、避开"高峰贵时段"；
* 提示词里带文件名/路径 → 会离开你的机器。

本地模型把这三件事都解决了：**不要密钥、不花钱、不出本机**。

## 二、装（绿色版包**已经内置**，通常这步可以跳过）

发布包里自带官方便携版 ollama 基座，解压后就在 `运行环境/本地模型`（只有运行时，
没有任何模型权重）；代码按**项目相对路径**找它，所以整个文件夹搬到哪儿都能用，
不装系统、不需要 sudo。想升到官方最新版：AI 页「🛒 模型商店 → ⬆️ 更新内置ollama」。

> 包内那份**只带 CPU / Vulkan 推理后端**（约 100 MB）：官方整包 2.1 GB 里 CUDA
> 占 2 GB，带上它发布包就顶到 GitHub 单个资源 2 GiB 的上限了。
> N 卡想用 CUDA 加速：设 `V8_3_本地模型_带GPU后端=1`，再点一次「⬆️ 更新内置ollama」，
> 它会下完整包并保留 GPU 后端。

只有**没有绿色版包**（例如直接从源码跑）时，才需要自己装一次（全部在用户目录）：

```bash
# 1) 装 Ollama（约 1.3 GB 下载，解压后 ~2.1 GB）
mkdir -p ~/.local/ollama && cd ~/.local/ollama
curl -fL -o ollama.tar.zst \
  https://github.com/ollama/ollama/releases/latest/download/ollama-linux-amd64.tar.zst
tar --zstd -xf ollama.tar.zst
ln -sf ~/.local/ollama/bin/ollama ~/.local/bin/ollama

# 2) 启动服务（后台常驻）
ollama serve &

# 3) 拉 DeepSeek 模型（deepseek-r1:1.5b 约 1.1 GB，纯 CPU 可跑）
ollama pull deepseek-r1:1.5b
```

也可以用任何 **OpenAI 兼容**的本地服务（llama.cpp 的 `llama-server`、LM Studio、
vLLM、xinference）：V8_3 会自动探测 `11434 / 8080 / 8000 / 1234 / 5000 / 12345`，
也可以在配置里写死地址。

命令行一句话搞定（V8_3 自带，不用手敲上面那些）：

```bash
PY=运行环境/venv/bin/python
$PY 启动.py --cli 本地模型 --检测        # 探测（默认动作）
$PY 启动.py --cli 本地模型 --启动        # 拉起 ollama serve
$PY 启动.py --cli 本地模型 --拉取        # 拉配置里的模型
$PY 启动.py --cli 本地模型 --测速        # 跑一次短提示，报 tokens/s
$PY 启动.py --cli 本地模型 --对话 "你好"  # 直接对话
$PY 启动.py --cli 本地模型 --开启/--关闭  # 写进配置
$PY 启动.py --cli 本地模型 --安装指引     # 打印上面的安装命令
```

界面：**🤖 AI 页 → 🏠 本地 DeepSeek 模型**卡片（开关 / 模型下拉 / 🔍检测 / ⏱测速 /
▶启动服务 / 📥拉取模型 / 📖安装指引）。

## 三、配置（`配置.json` → `AI.本地模型`）

```jsonc
"AI": {
  "本地模型": {
    "启用": true,              // 关掉就完全回到原来的云端逻辑
    "提供方": "自动",           // 自动 / ollama / openai兼容
    "地址": "",                // 空 = 自动探测常见端口
    "模型": "deepseek-r1:1.5b",
    "超时秒": 180,             // 本地推理慢，超时要给足
    "温度": 0.2,
    "最大tokens": 512,         // ⚠️ 别小于 512：deepseek-r1 先"思考"，
                               //    预算太小答案会被思考挤空（实测 256 → 空）
    "上下文长度": 4096,
    "自动启动": true,           // 需要时自动拉起 ollama serve
    "优先本地": true,           // 优先用本地，云端只在本地失败时兜底
    "云端兜底": true,           // 本地不可用时是否回落云端
    "用途": "全部"              // 全部 / 仅轻量
  }
}
```

也可以只改环境变量（不改配置）：`V8_3_本地模型地址=http://127.0.0.1:8080`。

### 语义（V8_3 与云端的关系）

| 场景 | 行为 |
|---|---|
| 本地可用 + `优先本地=true` | **所有 AI 请求走本地**；云端零调用、零费用 |
| 本地可用 + `用途=仅轻量` | 文件优先级 / 失败诊断 / 运行时调优走本地；**批次策略**走云端（CPU 上一次策略约 15s，交云端更快） |
| 本地失败 + `云端兜底=true` | 自动回落云端（有密钥时） |
| 本地不可用 / 未启用 | 完全回到 V8_1 的云端逻辑（含密钥、预算、高峰时段判断） |
| **本地可用时** | **不受"高峰时段不调用 AI"和"预算熔断"限制** —— 免费又离线，没理由跟着云端一起被卡 |
| 没云端密钥 | 只要本地可用，AI 依然可用（这是最实用的组合） |

## 四、实测数据（本机：Intel Iris Xe 核显 / 15 GB 内存 / 纯 CPU）

| 项目 | 结果 |
|---|---|
| 模型 | `deepseek-r1:1.5b`（Ollama，约 1.1 GB） |
| 短问答（241 tokens） | 11.6 s |
| 测速 | **17–19.5 tokens/s** |
| 结构化策略 JSON（328 tokens） | 15.7 s（`think=false`）／23.5 s（`think=true`） |
| 一次真实调度决策 | 「AI 决策」来源，**本地调用 1 次、云端 0 次** |

> 首次调用会加载模型（约 3–20 s），之后走内存/磁盘缓存会快很多。
> 想要更快可以：模型换更小的、或把 `用途` 设为"仅轻量"、或上独显。

## 五、代码结构（V8_3 自有，不依赖 V8_1）

| 文件 | 作用 |
|---|---|
| `v8_3/AI/本地模型.py` | 客户端：探测 / 列模型 / 对话（Ollama 原生 + OpenAI 兼容）/ 测速 / 启动服务 / 拉模型 / 安装指引 |
| `v8_3/AI/AI智能助手.py` | `_调用本地()` + `_调用一次()` 里的"本地优先 → 云端兜底"分流；`是否可用()` 把本地算进来 |
| `v8_3/AI/AI调度器.py` | 本地可用时跳过云端预算/时段门控；学习库记录来源=本地模型 |
| `v8_3/AI/配置适配.py` | `本地模型` 段合并；**给配置时不回填磁盘上的开启状态**（保证离线测试/临时配置干净） |
| `v8_3/AI/运行时.py` | 门面：`获取本地模型状态/摘要/一行/测速/启动/拉取/保存`；构造时打印一行状态 |
| `v8_3/界面/AI页面.py` | 🏠 本地模型卡片（开关/模型/检测/测速/启动/拉取/指引）；横幅标注"本地模型优先" |
| `v8_3/启动自检.py` | 启动时显式探测一次并打印（含"检测到可用服务但未启用，开启即免费"提示） |
| `v8_3/命令行.py` | `本地模型` 子命令 |

## 七、注意事项

* **停止服务**：`pkill -f "ollama serve"`（它是普通用户进程，没有 systemd 单元）。
* **磁盘**：绿色版里模型在 `数据/本地模型/模型`、基座在 `运行环境/本地模型`
  （整目录删掉也不会坏别的，点「⬆️ 更新内置ollama」就能补回来）；
  自己装的 ollama 才在 `~/.ollama/models` 与 `~/.local/ollama`。
* **端口**：默认只监听 `127.0.0.1:11434`，不对外暴露。
* **合规**：本地推理不联网，提示词（含文件名）不出本机；云端兜底打开时，
  本地失败的那一刻会走云端，介意的话把 `云端兜底` 设为 `false`。

# 🛒 本地小模型市场（AI 页新增，2026-09-19）

> **一句话**：AI 页多了一张「本地小模型市场」卡片 —— 它把**能查询到、能下载、
> 适合本项目**的免费本地小模型列成一张**排行表**，每个模型都带图片、多行详细信息、
> 一句核心总结、推荐指数，以及「一键安装 / 卸载 / 更新 + 下载链接 + 官网」。

## 一、界面长什么样

* 每张卡片：**模型图**（本地绘制，不抓网图）+ 名字 + **推荐指数**（0~100）+
  推荐等级 + 中文名/厂商/体积 + `📌 一句核心总结` + `💡 推荐理由` + 本机安装状态；
* 卡片右侧一排按钮：`⬇️ 一键安装`、`🗑 卸载`、`🔄 更新`、`📥 下载链接`、`🌐 官网`、
  `📖 详细信息`（点开是**多行**详情：模型名 / 系列厂商 / 参数量与量化 / 下载体积 /
  上下文 / 许可证 / 中文·推理·轻量星级 / 可用状态 / 适用场景 / 下载地址 / 官方网站，
  再附「详细介绍」「优点」「注意事项」三段）；
* **排序**：按推荐指数从高到低，**前三名分别用 🥇 / 🥈 / 🥉 醒目标记**；
* 工具行：`🔎 过滤`、`🔄 刷新目录`（动态拉取）、`⬆️ 更新内置ollama`、`📜 显示全部`、
  `⚖️ 推荐权重`（改五个分项权重，立刻重排）。

## 二、推荐指数怎么算

```
推荐指数 = 任务适配×w1 + 中文能力×w2 + 推理能力×w3 + 轻量×w4 + 新鲜度×w5   （归一化后 ×100）
默认权重：任务适配 0.35 / 中文能力 0.20 / 推理能力 0.20 / 轻量 0.15 / 新鲜度 0.10
```

* **分项只取目录里明写的元数据**，缺项按中性 0.5 参与 —— 不猜、不编；
* 「任务适配」= 尺寸/能力与本项目 **短中文决策任务**（并发策略、失败诊断、
  优先级排序、命名分类）的匹配度；
* 官方库已下架/不存在的条目会被重罚（×0.35）排到最后，但仍然列出来，不骗人；
* 权重存在 `配置.json → AI.本地模型.推荐权重`，界面上可随时改。

## 三、数据从哪来（离线可用 + 动态拉取）

| 来源 | 用途 | 说明 |
|---|---|---|
| 策展目录（代码内置 17 个） | 离线基准 | 每个都手写了中文总结/优点/注意/适用场景与五个分项评分 |
| `https://ollama.com/api/tags` | 动态发现 | 只收**能解析出参数量且 ≤ 12B** 的（大模型不进目录） |
| `https://registry.ollama.ai/v2/library/<名>/manifests/<标签>` | 可下载性 + 精确体积 | 逐层求和得到真实下载量；404 记为「不存在」 |

* 核对采用 **8 路并发 + 最多 3 轮降并发重试**（注册表会掐并发连接）：
  实测 17 个模型约 12 秒核完（串行要 30 秒以上）；
* 结果缓存到 `数据/本地模型/模型市场.json`，**24 小时内秒开**；
  缓存还会做字段自检，旧格式/半截写入的缓存直接作废重拉；
* 自检/离线场景可用环境变量 `V8_3_不联网=1` 强制只走策展目录。

## 四、装 / 卸 / 升级

* **一键安装** = `ollama pull <模型>`（带进度，实时显示到状态栏）；
* **更新** = 重新 pull 一次（ollama 只补差量层，很快）；
* **卸载** = `ollama rm <模型>`（会先弹确认框，说明体积）；
* 基座是**内置**的（`运行环境/本地模型`），所以正常情况下装模型不需要先装任何东西；
  万一那份被删/损坏，按钮会提示点 **`⬆️ 更新内置ollama`** —— 它从官方拉一份便携版，
  先自检能跑再替换，失败会保留原来那份。

## 五、打包（预装 ollama 运行时，不预装模型权重）

* `构建/打包.py` 现在会把 `运行环境/本地模型` 一起打进发布包（**只带运行时**）；
  缺运行时会自动下载（`--不要ollama` 可跳过）；
* `构建/构建_windows.sh` 第 ⑤ 步下载 Windows 版便携 ollama 到
  `构建/windows/本地模型`，打包时带进 Windows 包；
* 模型权重**一个都不预装**：用户第一次要用时在 AI 页点「一键安装」，
  权重落到 `数据/本地模型/模型`（跟着项目目录走，删目录即彻底清干净）。
