# 第二步实验：纯 HTTP 登录能否拿到 pan 域 STOKEN

**目的**：决定"不跑 JS 的自研登录器"这条路成不成立 ——
成立就能省掉 209 MB 的浏览器引擎，不成立就立刻止损（别再往这个方向投时间）。

## 背景（为什么必须做这个实验）

我们已经用真机证据钉死：

* 百度**扫码登录**得到的 BDUSS 进不了网页版 pan 域（`/disk/main` 被重定向到
  `errmsg=Auth Login Params Not Corret`），服务端**不下发 pan 域 STOKEN**；
* 写操作（上传/改名/删除）恒 `errno:-6` —— 因为 pan 域 STOKEN 只在
  **真正的网页版登录**时才下发；
* 所以「内置浏览器登录」的唯一价值就是"它跑的是真网页版登录"。

那么问题变成：**不渲染页面、直接打百度的登录接口（纯 httpx），能不能拿到
pan 域 STOKEN？**

## 怎么跑

```bash
cd ~/python/网盘管理
运行环境/venv/bin/python ~/v8_3_工作区/逆向/实验_纯HTTP能否拿STOKEN.py \
    --账号 你的账号 --报告 ~/v8_3_工作区/日志/实验报告.txt
```

* 密码用 `getpass` **交互输入**（不回显、不进 shell 历史、不落盘）；
* 也可以用 `--账号` 先把账号填好，密码仍然交互输入；
* 报告里所有 cookie 值都**只留长度与前 4 字符**，可以放心贴出来。

## 脚本会做什么（每一步都有输出）

| 步骤 | 动作 | 想看到什么 |
|---|---|---|
| ① | 打开 `pan.baidu.com` 拿基础 cookie | HTTP 200 |
| ② | 打开登录页、尝试取 `token` | 取到或"接口不强制" |
| ③ | POST `passport.baidu.com/v2/api/?login`（账号+密码） | 响应里是否出现 `errno=0` / "密码错误" / 验证码 / 风控 |
| ③b | **带 BDUSS 再进一次 `pan.baidu.com/disk/main`** | 这一步很关键：网页版就是靠访问 pan 域才换到 STOKEN 的，少了它会误判 |
| ④ | 摊开所有 cookie（按名字 + 域名） | **有没有 `.pan.baidu.com` 域的 `STOKEN`** |
| ⑤ | 若拿到凭证：用项目适配器打一次 `/api/list`（读）+ `/api/create`（建一个随机名目录，**成功立刻删除**） | `errno:0` = 可写 |

## 安全承诺

* 不落盘任何凭证（密码只在内存；会话文件用**临时覆盖 + 结束时还原**，会打印"已还原"）；
* 写探针只建一个随机名目录并立刻删除，不碰你的任何文件；
* 报告脱敏，可安全分享。

## 干跑结果（用假账号，验证脚本本身没问题）

```
① 打开 pan.baidu.com：HTTP 200
② 登录页：HTTP 200，6221 字节   token：没取到（继续试，接口可能不强制）
③ 提交登录：HTTP 200，1568 字节
④ 登录后的 cookie：BAIDUID、BAIDUID_BFESS、PANPSC、UBI、UBI_BFESS、
                  csrfToken、logTraceID、newlogin（响应头里还有 PASSID）
结论：❌ 连 BDUSS 都没拿到 —— 纯 HTTP 登录这条路（当前参数）不通。
```

假账号当然拿不到 BDUSS（服务端返回的是错误跳转页），所以这次干跑只证明
**脚本能跑、能正确报告失败**，不能证明真账号会怎样 —— 真正结论需要你跑一次。

## 结论怎么读

| 现象 | 含义 | 下一步 |
|---|---|---|
| 出现 `.pan.baidu.com` 的 `STOKEN`，且写探针 `errno:0` | ✅ 纯 HTTP 路线成立 | 写 `引擎_自研登录器.py`（httpx + 自己解析表单，**零引擎体积**，省 209 MB），接在同一个引擎接口上，界面一行不改 |
| 只有 BDUSS，没有 pan 域 STOKEN | ❌ 与扫码同样的命运：**只有真浏览器渲染才给写权限** | 止损。改走 `引擎_WebView2.py`（Windows 系统自带，省 207 MB）或提供"无内置浏览器"的精简包 |
| 出现"要求验证码 / 风控" | ⚠️ 接口路线被风控拦 | 同上：改走真浏览器引擎（但保留"能渲染就能过验证码"的优势） |
| 连 BDUSS 都没有 | ❌ 参数/流程已变 | 先修参数再判；或直接止损 |

## 看完结论之后

把这三行贴给我就够了（**不要贴凭证**）：

1. ④ 里有没有 `STOKEN`，域是什么；
2. ③ 里出现了哪个状态（`errno=0` / 密码错误 / 验证码 / 风控）；
3. ⑤ 的写探针结果（`errno:0` 还是 `errno:-6`）。

# 附：终端扫码登录（自研登录器的雏形）

没有"自研浏览器"可点之前，先在**终端里扫码**把流程跑通 —— 脚本：
`~/v8_3_工作区/逆向/终端扫码登录百度.py`（工作区脚本，不进仓库）。

## 用法

```bash
cd ~/python/网盘管理
运行环境/venv/bin/python ~/v8_3_工作区/逆向/终端扫码登录百度.py
运行环境/venv/bin/python ~/v8_3_工作区/逆向/终端扫码登录百度.py --不保存 --不探针   # 纯测试，不动会话
运行环境/venv/bin/python ~/v8_3_工作区/逆向/终端扫码登录百度.py --放大 2            # 终端大/想更清楚
```

流程：桥启动百度适配器 → `login_qr_start` 取二维码 → **画成终端字符画** →
手机扫码确认 → `login_qr_wait` 轮询 → 成功后写回适配器 → 现场探针（读 + 写）。

## 二维码怎么画的（三种做法都试过，只有一种对）

| 做法 | 结果 |
|---|---|
| 直接 resize 到固定列数（45 列） | ❌ 模块被挤掉（53 模块塞进 45 列），zbar 解不出 |
| 用中心行"最窄条宽"估模块边长 | ❌ 实测估成 5px（真值 15px），算成 53 模块（真值 45），整张废掉 |
| **逐像素找边界 + 候选模块数里"除得最整"的那个** | ✅ 实测 21/29/33/69/93 五种版本 **100% 还原**，zbar 可扫 |

关键点：**必须逐像素扫边界**（采样会漏掉最外圈一格，网格整体错位）；模块数一定是
`21 + 4k`，所以"哪个候选把边长除得最整"就是它。

## 已验证（可复现）

```bash
运行环境/venv/bin/python ~/v8_3_工作区/逆向/验证_终端二维码.py
```

* 与 `qrcode` 库的**真值模块矩阵**逐格比对：**纯文本画法 100% 一致**；
* 用系统 `zbarimg` 扫"字符画还原出来的图"：**能解出原始内容**（等价于手机扫成功）；
* 真实百度登录二维码（265×265、53×53 模块）：三个定位图案完好（黑框/白圈/黑心）、
  时序线 `█·█·█·█` 正常，字符画与原图网格 **2809/2809 = 100%**。

> 彩色半块（`▀`）画法保留为 `--图形`，但**目前不推荐**：还原验证时扫描失败，
> 需要继续调色序。默认用纯文本 `■■` —— 保真 100%、zbar 可扫、任何终端都能显示。

## 这个脚本为什么值得留着

它就是"自研登录器"的第一块砖：**不依赖任何浏览器引擎**就能拿到扫码会话
（`httpx` + 桥的轮询接口）。等第二步实验（`实验_纯HTTP能否拿STOKEN.py`）出结论，
如果"纯 HTTP 能拿 pan STOKEN"，就把这套东西搬进 `引擎_自研登录器.py`
接在同一个引擎接口上 —— 界面层一行都不用改。

### 终端放不下怎么办（用户反馈"二维码太大扫不了"）

实测结论：**百度登录二维码本来就装不进普通终端。**

| 编码 | 模块数 | 终端占用 |
|---|---|---|
| 百度原始图片 | 53×53 | **110 列** |
| 解出内容后用纠错级别 L 重编 | 53×53（URL 136 字符） | 约 112 列 |
| 早期测试用的短 URL（120 字符） | 43×43 | 90 列 |
| 再短的变体（75 字符） | 35×35 | 74 列 ✅ 能放下 |

也就是说：**只有把 URL 砍到 80 字符左右才可能塞进 80 列终端** —— 但那些参数
（`sign`/`t`/`qrloginfrom`…）是服务端用来校验扫码的，**不能乱删**，删了极可能
扫了也登录不上。所以不做这种"为了好看而破坏功能"的优化。

现在的行为（`终端扫码登录百度.py`）：

1. 先解出二维码内容 → 用**纠错级别 L + 静默区 1** 重编（比原始小一截）；
2. 按**终端实际列数**自动挑放大倍数（1 模块 = 2/4/6 个字符），能放下就直接画；
3. 放不下时打印三条**真的能用**的路：
   * ① 二维码已存成图片：`数据/终端二维码.png`（实测 zbar 能解出来），
     用看图工具打开即可扫：`xdg-open 数据/终端二维码.png`；
   * ② 把终端拉到需要的列数以上再跑；
   * ③ **二维码内容就是那个链接**：用手机浏览器打开它也能完成登录
     （最省事，不用扫码）；
4. 另外一直可以用图形界面：「网盘页 → 登录/管理 → 🌐 用内置浏览器登录」。
