# 一键启动（工作区快捷方式）

## 文件在哪

三个快捷方式都放在**工作区根目录** `<工作区根>`（本机是项目目录的上一级） 下：

| 文件 | 平台 | 用法 |
|---|---|---|
| `一键启动_网盘管理.sh` | Linux（推荐） | 双击，或终端里 `./一键启动_网盘管理.sh` |
| `一键启动_网盘管理.desktop` | Linux 桌面 | 双击（要文件管理器允许"执行"），或复制到桌面/应用菜单 |
| `一键启动_网盘管理.bat` | Windows | 双击（双击运行不会一闪而过，失败会 `pause`） |
| `网盘管理_图标.png` | 图标 | 桌面快捷方式用的图标 |

## 它自己会做的事

1. **找项目**：工作区里按"哪个子目录同时有 `v8_3/` 和 `启动.py`"认项目本体
   （适配器目录里也有 `启动.py`，那是它自己的 GUI —— 靠它会把项目找错，
   实测就踩过这个坑，所以认的是项目本体的特征）。可用 `V83_HOME` 覆盖；
2. **选解释器**：优先项目自带的 `运行环境/venv/bin/python3.14`，并且会
   `readlink -f` 解析真实路径，确认解释器**真的在项目自己的运行环境里**
   （别处可能有指向别处的符号链接）；找不到就退回系统 `python3`；
3. **依赖自检**：缺 PySide6 / httpx 直接给一句人话提示，而不是抛一堆 traceback；
4. **防重复启动**：已经在跑就把它切到前台（`wmctrl`/`xdotool` 有的情况下），
   不再开第二个。强制新开用 `V83_FORCE=1`；
5. **日志降噪**：默认给 `启动.py` 传 `--日志级别 警告`，终端不再刷屏，
   界面里的完整日志照旧写 `数据/界面日志.txt`；
6. **失败兜底**：程序非零退出时提示去看 `数据/界面日志.txt`，并给出
   "用 `启动.sh` 跑一遍（会打印报错）"的建议。

## 常用命令

```bash
cd <工作区根>

./一键启动_网盘管理.sh              # 正常启动
./一键启动_网盘管理.sh --check      # 只自检（打印项目/解释器/依赖版本），不启动
./一键启动_网盘管理.sh --调试        # 参数原样透传给 启动.py
V83_FORCE=1 ./一键启动_网盘管理.sh   # 已在运行也再开一个
V83_HOME=/别的/路径 ./一键启动_网盘管理.sh
```

## 为什么脚本里一个中文变量名都没有

本项目踩过两次坑：某些终端/包装器（fish、以及把参数当命令执行的那种）会用
**非 bash 的 shell** 去解析脚本，于是

* 中文变量名会被当成命令执行 → `候选: 不是有效的标识符`、`项目根=…: 没有那个文件或目录`；
* bash 数组语法 `参数=("$@")` → `未预期的记号 ""$@" 附近有语法错误`。

所以这两个启动脚本**刻意只用 ASCII 变量名 + POSIX 语法**，并且支持
`sh -n` 与 `bash -n` 双解析器校验（`工具/验收快捷方式.py` 会检查这一点）。

## 运行环境精简（2026-09-20）

发布包里的 `运行环境/` 天生带着大量"开发时才用得上"的东西。打包时会调用
`构建/精简运行环境.py` 把它们删掉（**只动发布包，不动本地开发环境**）：

| 删什么 | 为什么 | Linux 实测 |
|---|---|---|
| `*.pyi` / `*.pyi.in` | 类型存根，只有 IDE 用 | 5 MB |
| `__pycache__` / `*.pyc` | 字节码缓存，首次运行自动生成 | 10 MB |
| Qt 开发工具与文档 | `assistant/designer/linguist/qmlls/lupdate/include/typesystems/metatypes/qml/libexec` | 16 MB |
| Qt 翻译（305 个 `.qm`） | 界面自带中文，不需要 Qt 翻译；只留中/英 | 15 MB |
| 用不到的 Qt 模块 | QML/Quick（44+11+13 MB）、Designer、Pdf、3D、Charts、Multimedia、Sql、Test… | 60 MB |
| 用不到的 Qt 插件/资源 | qmltooling/renderers/sceneparsers/sqldrivers…、WebEngine devtools pak | 25 MB |
| 第三方包自带 tests/docs | aiohttp/PIL 等的测试目录 | 少量 |

**结果（V1.0.1）**：Linux 包 998 MB → **861 MB**，Windows 包 442 MB → **429 MB**。
Zip 只小 14% 是因为里面约 80% 的体积是**已经压过的二进制**（Qt/.so/模型），
删掉的是文本与未压缩资源，所以磁盘上省 169 MB、zip 里省得少一些。

### 两条必须记住的边界

1. **别删 QtWebEngine 的依赖模块**：`QtWebChannel` / `QtWebSockets` /
   `QtPositioning` / `QtWebView` 看着没用，但「内置浏览器登录」的
   QtWebEngine **依赖**它们 —— 实测删掉后
   `from PySide6 import QtWebEngineCore` 报
   `libshiboken: could not import module 'PySide6.QtWebChannel'`；
2. **保留**：平台/图形插件（`platforms`、`platformthemes`、`imageformats`、
   `iconengines`、`tls`、`networkinformation`、`generic`）、ICU
   （`libicudata/libicui18n/libicuuc`，Qt 内部做 Unicode 用）、QtWebEngine 全套
   （用户要求保留内置浏览器登录）。

验证方式：每次打包后我都会解压新包、用**包内解释器**跑一次
`启动.sh`（`QT_QPA_PLATFORM=offscreen`，无显示环境也能跑）确认界面能起来、
`PySide6` 与 WebEngine 都能导入。

## 浏览器引擎层（2026-09-20 重构）

「内置浏览器登录」原来是"界面 + Chromium"糊在一个文件里。现在拆成三层，
**让浏览器变成可替换、可测试的一块**：

| 文件 | 职责 | 行数 |
|---|---|---|
| `v8_3/界面/浏览器引擎.py` | **接口 + 工厂 + 假引擎**（不含任何具体浏览器） | ~320 |
| `v8_3/界面/引擎_QtWebEngine.py` | 默认引擎：PySide6 自带 Chromium（视图/cookie/交互） | ~300 |
| `v8_3/界面/内置浏览器登录.py` | 只做**界面与流程**：显示、二维码刷新、输入、收凭证、回调 | ~310 |

### 接口只有九件事

`可用()` · `打开(url)` · `取视图()` · `截图()` · `点(x,y)` · `输入文本(s)` ·
`按键(k)` · `取cookie(只要名字, 域们)` · `清cookie()` · `关闭()`（外加 `挂加载回调`）。

cookie 一律是**统一字典** `{name,value,domain,path,httpOnly,secure}`，
归一化只在 `浏览器引擎.规范cookie()` 一处（PySide6 给的是 bytes 的坑就堵在这里）。

### 为什么要这么拆

1. **换引擎不改业务**：将来换 WebView2（Windows 系统自带、省 207 MB）、
   CDP（用户自己的浏览器）、Obscura 或自研引擎，只需要新增一个适配器文件，
   `内置浏览器登录.py` 与桥里的凭证层**一行都不用改**；
2. **登录流程可以离线测**：`假引擎` 能预置 cookie、记录操作、触发"加载完成"，
   于是"取凭证 / 判缺 / 同名去重 / 手动完成 / 引擎不可用"这些逻辑全都有断言兜着
   （`tests/test_浏览器引擎.py`，14 项）；
3. **引擎可诊断**：窗口状态栏/日志能显示"当前用的哪个引擎"，
   将来用户报问题可以先问"你那个包是哪个引擎"。

### 已验证

* 真 QtWebEngine 引擎：开窗、加载、取 cookie（BDUSS + pan STOKEN）全部正常；
* 假引擎：完整会话自动回调、缺凭证不回调并提示缺什么、同名按域名去重、
  手动完成、引擎不可用给提示不崩、关窗释放引擎；
* 单测 646 项全绿、界面自检 485 项全绿。

### 已经修掉的一个真 bug（重构顺手抓到的）

点「✅ 我已登录完成」时，以前直接回调 `self._凭证` —— 如果 1.5 秒一轮的定时器
还没跑过，点下去会**什么都没发生**。现在先现场向引擎取一次 cookie 再回调
（`_手动完成` → `_收引擎cookie`）。

## 清空登录数据（换账号 / 验证纯 GUI 登录）

```bash
运行环境/venv/bin/python 工具/清登录数据.py            # 清掉
运行环境/venv/bin/python 工具/清登录数据.py --看一眼    # 只列出，不删
```

会删这五项（**只删登录态，不动业务数据**）：

| 路径 | 是什么 |
|---|---|
| `适配器/百度网盘适配器/数据/会话.json` | 百度 BDUSS + pan 域 STOKEN |
| `适配器/夸克网盘适配器/数据/凭证.json` | 夸克 Cookie |
| `适配器/光鸭云盘适配器/数据/令牌.json` | 光鸭访问令牌 |
| `数据/内置浏览器/` | 内置浏览器 profile（登录态，也是"自动补全会话"的来源） |
| `数据/终端二维码.png` | 终端扫码临时图 |

**保留**：`上传记录.json`、`设备信息.json`、`敏感词.db`、AI 学习库、界面日志。

清完打开程序，三家网盘都应是 `⚪ 未登录` —— 之后**只能在 GUI 里重新登录**
（「🔐 登录 / 管理」里选扫码 / 内置浏览器 / 短信 / Cookie 导入）。

> 注意：清掉 `数据/内置浏览器` 之后，"打开窗口就是登录态"和"扫码后自动补写成可写会话"
> 这两条自愈能力也就没有了 —— 这正是验证"纯 GUI 登录"该有的状态：
> 必须自己走一遍登录，且百度要拿到可写会话就得用
> 「🌐 用内置浏览器登录」或「📱 用内置浏览器短信登录」。
