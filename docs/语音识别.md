# 本地语音识别（V8_3 新增能力）

> **一句话**：V8_3 能在**本机、离线、不上传**的前提下把"无字幕视频"听写成字幕 ——
> 引擎是 faster-whisper（CTranslate2 后端）+ small 中文模型，
> 依赖和模型**全部装在项目内**的 `运行环境/语音识别/`，不碰系统包、不碰共享 venv，
> 删掉那个目录就等于彻底卸载。

---

## 一、它解决什么问题

播放页的「🎙 AI 生成字幕」原来只能吃现成的 `.srt`。没有字幕轨的视频（网盘里一大把）
就只能干瞪眼：AI 翻译、AI 总结、章节切分这些能力全都无从下手。

本模块补上最前面那一环：**把音轨变成带时间戳的中文段落**，交给
`v8_3/AI/字幕助手.py` 归一化成 `字幕条目`，再写出 `.auto.srt`。

三条硬要求都满足：

* **不污染系统环境** —— 装在项目内的独立 venv 里，`pip` 一个包都没往项目外装过：
  没碰 `/usr`、没碰系统 python、没碰 `~/.local`、也没碰任何别的项目；
* **可被 Python 直接调用** —— `from v8_3.播放.语音识别 import 语音识别器`，
  主程序跑在项目内主环境 `运行环境/venv` 里也照样能用（重活由项目内 venv 的子进程干）；
* **免费、离线、不出本机** —— 不花钱、不要密钥、音频数据一个字节都不出机器。

## 二、最终装了什么、装在哪、多大

| 模型 | `运行环境/语音识别/模型/faster-whisper-small/` |

| 测试音频 | `运行环境/语音识别/测试音频/` |

体积（`du -sh` 实测）：

```
环境总计 : 899M
venv     : 434M      # ctranslate2.libs 75M + av.libs 72M + onnxruntime 67M + ctranslate2 60M + numpy 43M
模型     : 464M      # model.bin 461.1 MiB(483,546,902 字节) + tokenizer.json 2.2M + vocabulary.txt 452K + config.json 2.4K
测试音频 : 1.4M
```

> 模型 461 MiB，**在"1.5 GB 以内"的要求里有 3 倍余量**。

### 为什么选 faster-whisper（而不是 openai-whisper / whisper.cpp）

* **openai-whisper 要拖 torch** —— 光 CPU 轮子就 200 MB+，装完 1 GB 起，
  还得吃 numba；在 Python 3.14 上属于"能装但很沉"；
* **whisper.cpp 要编译或下 GitHub 预编译二进制** —— 本机 **github.com 时通时不通**，
  这条路不可靠；本地编译又要 cmake + 编译链，慢且脆；
* **faster-whisper 在 Python 3.14 上真的有 cp314 轮子** —— 这一点是实测确认过的，
  `ctranslate2 4.8.2` 提供 `cp314-cp314-manylinux_2_28_x86_64` 轮子，
  `onnxruntime 1.30.0`、`av 18.1.0` 也有 cp314，`tokenizers` 走 `cp310-abi3` 通吃；
* 它**不需要 torch**，纯 CPU int8 就跑得动，正好配这台没有 N 卡的 Iris Xe 机器。

装之前先探过 PyPI 的轮子标签，不是猜的：

```bash
curl -s https://pypi.org/pypi/ctranslate2/json | python -c "import sys,json;d=json.load(sys.stdin);print(sorted({f['filename'].split('-')[-3] for f in d['releases'][d['info']['version']] if f['filename'].endswith('.whl')}))"
# → ['cp310', 'cp311', 'cp312', 'cp313', 'cp314', 'cp39']
```

## 三、怎么复现（照着敲就行）

全部命令都在项目根 `网盘管理_V8_3/` 下执行，**不需要 sudo，不碰系统包**。

### 1) 建局部环境

```bash
cd <项目根>
运行环境/python/bin/python3.14 -m venv 运行环境/语音识别/venv
```

> 用共享 venv 的解释器去**创建**一个新 venv，不会往共享 venv 里装任何东西
> （`python -m venv` 只读它的标准库）。

### 2) 装推理依赖（约 110 MB 下载）

```bash
运行环境/语音识别/venv/bin/python -m pip install \
  -i https://mirrors.aliyun.com/pypi/simple/ faster-whisper==1.2.1
```

实测下载速度约 500 KB/s，整条链路约 4 分钟。`pypi.org` 直连也通（3.6 s 握手），
阿里云镜像更快（1.6 s），任选。

### 3) 下模型（约 461 MiB）

**huggingface.co 在本机是不通的**（实测 `curl https://huggingface.co/...` 20 秒超时，
`http_code=000`），所以**必须走 hf-mirror.com**。

方式 A：直接 curl（本次就是这么下的，实测 **38.7 MB/s，11.9 秒**下完 461 MiB）

```bash
BASE=运行环境/语音识别; MDIR=$BASE/模型/faster-whisper-small
mkdir -p "$MDIR"
REPO=https://hf-mirror.com/Systran/faster-whisper-small/resolve/main
for f in config.json model.bin tokenizer.json vocabulary.txt; do
  curl -fL --retry 3 -o "$MDIR/$f" "$REPO/$f"
done
```

方式 B：用 huggingface_hub（已实测可用，`HF_ENDPOINT` 是关键）

```bash
HF_ENDPOINT=https://hf-mirror.com 运行环境/语音识别/venv/bin/hf download \
  Systran/faster-whisper-small --local-dir 运行环境/语音识别/模型/faster-whisper-small
```

> 两个方式都实测过。方式 B 只验证了 `config.json` + `vocabulary.txt` 两个文件
> （证明 `HF_ENDPOINT` 真的指到了镜像），完整模型是用方式 A 落的盘。
> 本模块内部也把 `HF_ENDPOINT` 默认设成 `https://hf-mirror.com`（工作进程环境变量），
> 万一将来要临时下别的模型也不会去撞那堵墙。

## 四、怎么用

```python
from v8_3.播放.语音识别 import 语音识别器, 转SRT

识别器 = 语音识别器()                       # 构造极快：不加载模型、不起进程
可用, 说明 = 识别器.可用()                  # 任何情况都不抛异常
print(可用, 说明)

段落 = 识别器.识别("电影.mkv", 语言="中文",
                   进度回调=lambda 百分比, 已处理秒: print(f"{百分比:.1f}%"))
print(转SRT(段落))                          # 直接得到 SRT 字幕文本
识别器.卸载()                               # 结束工作进程，内存彻底还给系统
```

跟播放页/字幕助手的对接（**已经联调通过**）：

```python
助手 = 字幕助手()
结果 = 助手.生成字幕(媒体来源, 识别器, 语言="中文", 进度回调=...)
# → 助手.识别结果转条目(段落) → 字幕条目 → .auto.srt
```

### 接口约定

| 方法 | 说明 |
| --- | --- |
| `语音识别器(模型大小="small", 模型目录="", 日志回调=None, 设备="cpu", 计算类型="int8", 线程数=0, 束搜索=5, VAD=True)` | 构造**不做重活**（只记参数，不建进程、不加载模型、不查网络） |
| `可用(深度检查=False) -> (bool, str)` | **绝不抛异常**。不可用时说明里带**可以照着敲的修复步骤**。`深度检查=True` 会真的 import 一次 faster-whisper 报真实版本号（约 0.5 s） |
| `模型信息() -> dict` | `{模型, 目录, 大小MB, 设备, 计算类型, 已就绪}` + `运行方式/环境Python/模型已加载/缺少文件/仓库/支持语言数` 等附加项 |
| `识别(媒体路径, 语言="", 进度回调=None) -> list[识别段落]` | `进度回调(百分比: float, 已处理秒: float)`；失败抛 `识别失败`（`RuntimeError` 子类），消息可直接展示给用户 |
| `卸载() -> None` | 结束工作进程 + 清空缓存，**不抛异常**；下次 `识别()` 自动恢复 |
| `模型是否已加载() -> bool` | 模型现在是否真在内存里 |
| `识别失败` | 异常类型，`RuntimeError` 子类，消息可读 |

### `识别段落` 有个"双重身份"

```python
@dataclass
class 识别段落(dict):      # ← 既是 dataclass，也是 dict
    开始秒: float
    结束秒: float
    文本: str
```

继承 `dict` 不是为了好玩：`v8_3/AI/字幕助手.py` 的
`识别结果转条目()` 是按"字段名当字典键"归一化各家 ASR 输出的
（`isinstance(段落, dict)` + `段落.get("开始秒")`），**纯 dataclass 会被它整条丢掉**，
最后表现为"识别成功但一条字幕都没生成"。继承 `dict` 之后两边都满意：

```python
段.开始秒        # 0.37      ← 属性访问
段["开始秒"]     # 0.37      ← 字典访问
"文本" in 段     # True
json.dumps(段)   # {"开始秒": 0.37, "结束秒": 3.17, "文本": "..."}
```

> 已知取舍：直接改属性（`段.文本 = "x"`）**不会**同步字典键。
> 识别结果本来就是只读的，测试里把这个行为钉住了。

## 五、媒体路径：本地文件 与 http 直链

`识别()` 的 `媒体路径` 两种都收，行为**明确如下**：

| 输入 | 行为 |
| --- | --- |
| 本地文件（mp4/mkv/mp3/wav/flv/ts…） | **直接交给 PyAV 解码**，不落临时文件。实测 `.mp4`（h264 + aac）直接可识别 |
| `http(s)` 直链 | **先用 ffmpeg 抽音轨**成 16 kHz 单声道 PCM wav 临时文件再识别，**识别完立即删除**。网络流用 PyAV 直接解容易断，抽一次更稳，还能提前用 ffprobe 拿到总时长好算进度 |
| 本地文件但解码失败 | 自动**退回** ffmpeg 抽音轨再重试一次 |

几个注意点：

* 抽音轨用了 `/tmp`（`tempfile`）。**2 小时视频的 16 kHz 单声道 wav 约 230 MB**，
  跑之前留意 `/tmp` 空间；
* 没有 `ffmpeg`/`ffprobe` 时，**纯本地常见格式不受影响**（那是 PyAV 在解），
  只有"直链"和"怪格式"会失败，且会给出可读的报错；
* `ffprobe` 只用于取总时长算百分比，取不到就退化成"不报百分比"，不影响识别。

## 六、支持哪些语言

* `Whisper语言全集` 里有 **108 个语言码**（Whisper 官方 99 种，另收了 `ceb`/`haw`
  等几个常见补充），去重后就是这个数；
* `支持语言` 别名表收了 **40 个常用写法**，所以下面这些都认：

```python
规范语言("中文")   # 'zh'      规范语言("汉语")   # 'zh'
规范语言("普通话") # 'zh'      规范语言("粤语")   # 'yue'
规范语言("英语")   # 'en'      规范语言("日语")   # 'ja'
规范语言("")       # ''  → 让 Whisper 自动检测
规范语言("auto")   # ''  → 同上
```

中文场景**建议显式传 `语言="中文"`**：自动检测要多跑一遍编码器，
实测慢 **1.61 倍**（6.179 s → 9.942 s，同一段 5.6 s 音频）。

## 七、CPU 上的实测速度（真数据）

**测试机**：Intel Iris Xe 核显（**无 NVIDIA，`ctranslate2.get_cuda_device_count() == 0`**），
8 逻辑核，15 GB 内存。**模型**：faster-whisper-small，`device=cpu` / `compute_type=int8`，
`beam_size=5`、`vad_filter=True`。

> ⚠️ **测速时的机器不是空闲的**：同一台机器上还有别的活在跑
> （`llama-server` 占了 364% CPU，`load average` 在 7~10 之间）。
> 所以下面的墙钟数字**偏保守**，CPU 秒数才是与负载无关的硬指标。

### 吞吐（每档 5 轮，取 min/中位）

| 音频 | 墙钟 min | 墙钟中位 | 倍速(min/中位) | CPU 中位 | CPU秒/音频秒 |
| --- | --- | --- | --- | --- | --- |
| **33.7 s** 长音频 | **3.972 s** | 4.497 s | **8.48x** / 7.49x | 17.094 s | **0.51** |
| 5.6 s 短音频 | 4.151 s | 4.271 s | 1.35x / 1.31x | 12.833 s | 2.29 |
| 3.0 s 短音频 | 3.876 s | 4.026 s | 0.77x / 0.75x | 11.996 s | 4.00 |

**这张表最重要的结论**：Whisper 每次调用都会把输入补齐到 **30 秒**的编码窗口，
所以**短片段极其吃亏** —— 3 秒音频要花 4 秒（0.75x 实时），
33.7 秒音频反而只要 4 秒（8.48x 实时）。**别把视频切成 5 秒一段去识别**，
整条音轨一次性丢进来最划算。

按 0.51 CPU秒/音频秒 折算：**1 小时视频约 30 分钟 CPU 时间**，
在 8 逻辑核上（还有别的活在抢）大约 **7~8 分钟**跑完；机器空闲时更快。

### 冷启动：模型加载与工作进程

### 参数对速度的影响（5.6 s 音频，同一时段对比）

| 配置 | 中位墙钟 | 倍速 |
| --- | --- | --- |
| `beam=5` + VAD 开（默认，最准） | 5.713 s | 0.98x |
| `beam=1` + VAD 开（贪心，最快） | 4.431 s | 1.27x |
| `beam=5` + VAD 关 | 6.185 s | 0.91x |
| `beam=1` + VAD 关 | 4.090 s | 1.37x |
| 指定 `语言="中文"` | 6.179 s | 0.91x |
| 自动检测语言 | 9.942 s | **慢 1.61 倍** |

> `线程数` 不用调：默认 `0`（交给 CTranslate2 按物理核自选）实测最快；
> 手工设 `线程数=8` 反而更慢（6.789 s），`线程数=4` 最慢（8.435 s）。

## 九、怎么卸载

三件事，**没有一件需要 sudo**：

```bash
# 1) 删掉整个局部环境（依赖 + 模型 + 测试音频，899 MB）
rm -rf <项目根>/运行环境/语音识别

# 2) 如果只想删模型、留着依赖（省 464 MB）
rm -rf <项目根>/运行环境/语音识别/模型

# 3) 清掉可能存在的 HF 缓存（本模块把 HF_HOME 也钉在项目内）
rm -rf <项目根>/运行环境/语音识别/缓存
```

**不用管的**：ASR 那套重库只装在 `运行环境/语音识别/venv` 里，主环境
`运行环境/venv` 里从来就没装过任何 ASR 相关的包（实测确认：
`faster|ctranslate|whisper|onnxruntime` 在主环境 site-packages 里匹配数 **0**），
系统 Python、`/usr`、系统包、`~/.local` 一个字节都没动过。

删完之后 `可用()` 会返回 `False` 并给出重新装回来的完整命令，
所以"卸载"和"重装"都是可逆的。

## 十、限制与风险（如实说）

1. **small 模型的中文输出可能是繁体。** 实测同一段音频给出
   `開放時間早上9點至下午5點`（繁体），而关掉 VAD 时给的是
   `开放时间早上九点至下午五点。`（简体+句号）。**Whisper 的输出繁简不稳定**，
   想统一成简体得在下游加一道 OpenCC 转换（本模块没做，也没装 opencc）。

2. **VAD 会改变输出内容，不只是切静音。** 上面同一段音频，VAD 开/关得到的是
   两种文本（繁体无标点 vs 简体带标点）。字幕场景建议保持默认 `VAD=True`
   （能砍掉大段静音、减少幻觉），但要接受文本风格会变。

3. **short clip 严重不划算。** 见第七节：3 秒音频要 4 秒才能跑完。
   `识别()` 是"整条媒体一次调用"的粒度，上层**不要**自己切成小段循环调用。

4. **测速数据是在有负载的机器上取的。** `load average` 7~10，
   墙钟数字偏保守；空闲机器上会更快。**CPU秒/音频秒（0.51）才是可移植的指标**。

5. **segments 级时间戳，不是词级。** faster-whisper 给的是段落级
   `start/end`，长句内的时间对齐比较粗（本模块没开 `word_timestamps`）。
   对字幕够用，做卡拉OK 式逐字高亮就不够。

6. **并发是被串行化的。** `识别()` 内部有锁，同一个 `语音识别器` 实例
   （以及同配置的多个实例，因为它们共用同一个工作进程）**不能并行识别**。
   要并行得多开几个 `模型目录` 不同/`设备` 不同的实例，但 8 核机器上并行
   只会互相抢 CPU，不划算。

7. **直链抽音轨会落临时文件。** 2 小时视频 → `/tmp` 里约 230 MB 的 wav。
   `/tmp` 空间紧张时会失败。

8. **`/tmp` 与磁盘**：模型 464 MB + venv 434 MB 都在 `/home`（当时剩余 177 G，
   绰绰有余）。但**换机器时要重新跑第三节的步骤**，`运行环境/` 不建议进 git。

9. **没有 GPU 加速。** 本机 `cuda_device_count()==0`，`设备="cuda"` 会失败。
   想更快只能换更大的模型（更慢）或更好的 CPU。

10. **`识别段落` 的已知取舍**：它继承 `dict`，但**改属性不会同步字典键**
    （见第四节）。请把它当只读数据用。

11. **`large-v3` 能装但会很慢**：模型约 3 GB（超过"1.5 GB 以内"的目标），
    在这台 CPU 上大概要比 small 慢 5~10 倍。要更准优先考虑 `medium`（约 1.5 GB）。
