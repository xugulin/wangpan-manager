# V8_3 视频播放器（内嵌 libvlc + AI 观影）

> 目标：**在网络正常的前提下流畅播放 4K 及以上视频**，并把 AI 用在「加载前决策、
> 字幕翻译、无字幕生成、播放中优化、看完总结」这几件真正有用的事上。
> 播放器全部封装在项目内（`v8_3/播放/`），**不往系统里装东西、不污染 `~/.config`**。

---

## 1. 为什么是 libvlc，而不是自己写解码器或换 mpv

| 方案 | 结论 |
| --- | --- |
| 参考 VLC 自己写解码/渲染 | 等于重写一个 VLC：工程量以年计，且做不到更流畅 |
| **复用系统 libvlc 3.0.23（本项目选择）** | VLC 的解复用/解码/渲染/网络栈是现成的最优解；我们只做**参数决策 + AI 增强** |
| mpv / libmpv | 本机没装；引入要装系统包 |
| QtMultimedia | 能播，但没有网络缓存/硬解/请求头这些关键旋钮，4K 直链基本没法优化 |

所以「深度优化」落在三个我们**真能控制**的地方：

1. **起播参数**（网络缓存窗口、硬解方式、HTTP 头、时钟策略）；
2. **播放中诊断 → 换参数重载**（AI 顾问 + 学习库）；
3. **AI 观影能力**（字幕翻译 / 无字幕生成 / 总结）。

### 绑定方式：自己写 ctypes 绑定，不用 python-vlc

`v8_3/播放/vlc绑定.py` 直接 dlopen `libvlc.so.5`，只绑用得到的符号。
好处：不引入第三方依赖、能按 VLC 版本**容忍符号缺失**（VLC 3 用 `libvlc_video_*`，
VLC 4 改成 `libvlc_media_player_*`，两套名字都试）。

> **血泪坑（已修 + 已加回归测试）**：`libvlc_media_player_get_spu` 在 VLC 3.0.23 里
> **不存在**，回退名 `libvlc_video_get_spu` 又没进过绑定表，于是 `getattr` 拿到一个
> **没设 `argtypes`** 的函数 —— ctypes 把 64 位播放器句柄按 C `int`（32 位）传进去，
> libvlc 拿着野指针加锁 → **整个进程段错误**（exit 139，崩在
> `libvlc_video_get_spu+0x28`）。触发点是界面每 500ms 刷一次状态，所以"一播放就崩"。
> 现在：所有会被调用的符号一律走 `取函数()`（强制配 `argtypes`），句柄递给 libvlc
> 前先过 `校验句柄()`，并且 `tests/test_播放层.py` 里锁死了这两条。

## 2. 播放链路

```
网盘选片 / 本地文件
   │
   ├─① 取播放直链（适配器子进程 play_link：夸克/光鸭/百度各一套签名 + 请求头）
   │
   ├─② ffprobe 媒体信息：分辨率/档位/编码/码率/帧率/字幕轨/时长
   │
   ├─③ 直链探测：TTFB + 实测带宽（两段 Range 读 2MiB+4MiB）+ Range 支持
   │        └─ 本地文件跳过探测，合成"本地文件（不经过网络）"说明
   │
   ├─④ 参数决策：AI 播放顾问（学习库 → 本地模型 → 云端 → 规则兜底）
   │        输出：网络缓存 ms / 起播等待 s / 硬解 / 附加选项 / 可流畅播放 / 风险
   │
   ├─⑤ libvlc 起播：set_xwindow(窗口句柄) 嵌进播放页；带 Referer/UA/Cookie
   │
   ├─⑥ 每 500ms 采样：状态/进度/缓冲/丢帧/解码帧/码率/字幕轨 → 界面 + 诊断
   │
   └─⑦ 卡顿检测（丢帧增量↑ 或 缓冲中）→ AI 诊断 → 新参数 → **重启到原位置**
```

**「AI 优化播放」为什么是重启而不是热改**：libvlc 的 `:network-caching`、
`:avcodec-hw`、`:clock-*` 这类选项**只在起播前生效**，运行中改不了。所以调优 = 记住
当前进度 → 用新参数重新起播 → 跳回原位置（1 秒内，用户几乎无感）。

### 起播速度：先秒起播，AI 后面追

本地 1.5B 模型一次决策要 **15~24 秒**，如果等它算完再起播，用户要盯着黑屏干等
20 秒 —— 不可接受。所以：

```
点「▶ 播放」 ──► 规则参数（<0.3s，画面立刻出来）
                     │
                     └─► 后台问 AI 顾问（15~24s）
                              │  参数真的变了（缓存差≥1s 或硬解/选项不同）
                              └─► 自动重载到**当前位置**（1 秒内回到原画面）
```

* 实测：**起播 0.2~0.3 秒**（改之前要等 AI，15.1 秒）；
* AI 的结论会写进 AI 面板（`[AI 决策] …`），信息栏也会跟着更新；
* **本地文件跳过 AI 调参**：本地不经网络，AI 拿不到带宽只会给"保守大缓存"，
  对本地是负优化（实测它想把 1500ms 改成 12000ms，白重启一次还丢缓冲）。

## 3. AI 观影能力（对应需求逐条）

| 需求 | 实现 | 入口 |
| --- | --- | --- |
| **AI 辅助加载视频** | 播放顾问给起播参数（缓存/硬解/选项），并给"能不能流畅""风险是什么" | 起播前自动 |
| **AI 翻译字幕** | `字幕助手.翻译文件()`：读 SRT → 分批（默认 40 行）→ 逐批翻译 → 写 `_AI中文.srt` → 自动挂载选中 | 「🌐 翻译字幕」 |
| **无字幕视频 AI 生成字幕** | `语音识别.识别()`（faster-whisper）→ 段落 → SRT；再由字幕助手翻译/润色 | 「🎙 生成字幕」 |
| **AI 优化播放** | 采样 + 诊断（丢帧/缓冲/硬解是否生效）→ 新参数 → 重载 | 「🩺 诊断」/ 自动调优 |
| **AI 总结** | `字幕助手.总结()`：对字幕（或识别结果）出摘要/看点/时间线 | 「📝 总结」 |

**降级原则**：AI 不可用（没密钥/没本地模型/超时）时**一律回落规则**，功能不消失：
翻译失败保留原文，摘要失败给规则摘要，起播参数回落 `规则参数()`。日志里会写明
「走【规则（无可用 AI）】」，不假装是 AI 干的。

### 本地模型（默认开启，免费离线）

配置里 `本地模型.启用=true` 时用 Ollama + `deepseek-r1:1.5b`（CPU 约 17–19 tok/s）。
实测耗时（**要如实告知**）：

| 任务 | 耗时 |
| --- | --- |
| 起播策略 JSON（3 行输入） | ≈15 s（`think=false`）/ 23.5 s（`think=true`） |
| 翻译 3 行字幕 | ≈55.7 s |
| 5 行字幕总结 | ≈84.4 s |

所以：AI 决策**只在起播前跑一次**（页面不卡，后台线程），翻译/总结是**用户主动点**
的慢操作（有进度日志）。`最大tokens` 必须 ≥512，否则 R1 的思考链会把答案挤掉。

## 4. 4K 流畅度：本机实测数据（不吹）

环境：Tea Linux / Arch，Intel i7-1195G7（4 核 8 线程），Iris Xe 核显，15 GB 内存，
VLC 3.0.23，测试片为 ffmpeg 生成的 3840×2160 真 4K。

| 场景 | 解码 | 显示 | 丢帧 | 判定 |
| --- | --- | --- | --- | --- |
| 4K H.264 46 Mbps（无窗口，软解） | 48.5 fps | 17.5 fps | 54/10s | 解码余量 **1.94×** |
| 4K HEVC 20 Mbps（无窗口，软解） | 43.4 fps | 13.4 fps | 64/10s | 解码余量 **1.73×** |
| **4K HEVC 20 Mbps（嵌进播放页窗口）** | — | 实时 | **0** | ✅ 实时播放、零丢帧 |
| 4K H.264 60 Mbps（本地，规则参数） | — | 实时 | 0 | ✅ 缓存 1500ms 立即出画 |

结论：**本机 CPU 软解 4K 有 1.7–1.9 倍余量**，25fps 的 4K 片源（含 HEVC）能实时播、
嵌窗口零丢帧；无窗口模式下的"显示帧率低"是无 X 渲染路径的测试假象，不是解码瓶颈。

### 硬解：本机已装 Intel VAAPI，**实测确认生效**

```
/dev/dri/renderD128  ✅ 在
/usr/lib/dri/iHD_drv_video.so / i965_drv_video.so  ❌ 都没有
（Mesa 只带了 radeonsi / nouveau / virtio / d3d12 的 VA 驱动）
```

之前 `_探测本机硬解()` 只要看到 `/dev/dri` 就宣称"硬解 vaapi" —— **过度承诺**：
VLC 初始化 vaapi 会失败（`libva error: vaGetDriverNames() failed`）然后**悄悄软解**，
界面却显示 vaapi。现在 `硬解能力()` 按 **显卡厂商（读 /sys/class/drm/*/device/vendor）
+ 匹配的 VA 驱动文件**一起判，并给出安装建议：

```
⚠️ 有显卡（Intel）和渲染节点，但没装 VAAPI 驱动 → 只能 CPU 软解。
   想开硬解：装 intel-media-driver（Arch: sudo pacman -S intel-media-driver）
```

装好驱动后的**实测对比**（4K HEVC 20 Mbps，真实 X11 窗口，各播 10 秒）：

| 硬解方式 | 10 秒内进程 CPU | 解码 | 显示 | 丢帧 |
| --- | --- | --- | --- | --- |
| `:avcodec-hw=vaapi`（iHD 驱动） | **2.81 s** | 501 帧 | 210 帧 | **0** |
| `:avcodec-hw=none`（纯软解） | 17.93 s | 501 帧 | 210 帧 | **0** |

**CPU 差 6.4 倍**，画面都是实时、零丢帧 —— 硬解真的接管了。
（VLC 日志里仍会看到 `glconv_vaapi_x11 error: vaInitialize: unknown libva error`：
那是 Xvfb 下 GL 互操作初始化失败，VLC 转用 `glconv_vaapi_drm`，**解码加速照常生效**；
真桌面上不会有这条。）

其它显卡（本项目只检测、不安装）：

| 显卡 | 包 | 装完效果 |
| --- | --- | --- |
| Intel 核显 | `intel-media-driver`（新）/ `libva-intel-driver`（老） | 4K/8K HEVC 硬解，CPU 占用大幅下降 |
| AMD | `mesa`（一般已装） | 同上 |
| NVIDIA | `nvidia-utils` | VDPAU/NVDEC |

装好后播放页信息栏的"硬解"会变成 `vaapi`，AI 日志会打印
`VAAPI 可用：iHD_drv_video.so（Intel）`。

### 带宽侧判定

`直链探测` 实测带宽，规则要求 **带宽 ≥ 码率 × 1.3**：

| 片源 | 需要带宽 | 判定 |
| --- | --- | --- |
| 1080p 13.6 Mbps | ≥17.7 Mbps | 缓存 8000ms |
| 4K 25 Mbps | ≥32.5 Mbps | 缓存 12000ms + 可流畅 |
| 4K 25 Mbps 但实测 20 Mbps | — | ❌ 判卡顿 + 缓存拉到 20000ms + 给风险说明 |

不装 VAAPI 驱动时也能硬解 HEVC 的另一条路：`auto`（本项目默认）让 VLC 自己挑，
挑不到自动回落软解 —— 不会因为"写死了 vaapi"而黑屏。

## 5. 干净环境隔离（不污染系统）

libvlc 默认会往 `~/.config/vlc`、`~/.local/share/vlc`、`~/.cache/vlc` 写东西
（插件缓存、`ml.xspf.tmp` 等）。`启动.py` 在**任何 Qt/libvlc 初始化之前**调用
`vlc绑定.准备干净环境(项目根)`，把三个 XDG 目录指到项目内：

```
网盘管理_V8_3/数据/运行环境/config   ← XDG_CONFIG_HOME
网盘管理_V8_3/数据/运行环境/data     ← XDG_DATA_HOME
网盘管理_V8_3/数据/运行环境/cache    ← XDG_CACHE_HOME
```

本地模型（Ollama）与语音识别（faster-whisper）同样在项目内：

| 组件 | 位置 | 体积 | 卸载 |
| --- | --- | --- | --- |
| Ollama 运行时 | `~/.local/ollama`（用户级，非系统包） | 2.1 GB | 删目录 |
| `deepseek-r1:1.5b` | `~/.ollama` | 1.1 GB | `ollama rm deepseek-r1:1.5b` |
| faster-whisper + small 模型 | `运行环境/语音识别/` | 899 MB | `rm -rf 运行环境/语音识别` |

### 5.1 显示环境：为什么必须走 X11（Wayland 两个坑）

libvlc 3 只有 `set_xwindow(X11 窗口号)` 这一条嵌入路径，于是 Wayland 会话下有两个坑：

1. **闪退**：Qt 走 wayland 插件时 `winId()` 是 wl_surface，交给 `set_xwindow` →
   VLC 拿它当 X11 窗口画 → 整个进程段错误（用户实测：双击开播即崩）；
2. **VLC 抢开窗口**：拿不到有效句柄时句柄给 0，libvlc 就**自己弹一个 VLC 窗口**
   放画面 —— 那个窗口不归本程序管，可能比屏幕还大（用户实测截图：标题栏
   `VLC media player`、画面铺满并超出屏幕，我们的工具栏/全屏全失效）。

所以策略是：

* 启动时（创建 QApplication 之前）**只要 `DISPLAY` 有值就切 `xcb`**（XWayland），
  **即使显式设成 `QT_QPA_PLATFORM=wayland` 也切**；
* 真没有 XWayland 时：**桌面平台下拒绝开播**，状态栏 + AI 日志给出修法
  （`QT_QPA_PLATFORM=xcb` 重启），不再默默让 VLC 弹窗；
* 离屏/无头平台（自检、CI）不受此限：那里句柄 0 就是"无窗口解码"，是正确的；
* 确实想用 VLC 自带窗口：设 `V8_3_允许VLC自带窗口=1`，或用
  「工具 → 用 VLC 自带窗口播放」（界面控件仍可用，但窗口大小/位置归系统管）；
* 另有 `V8_3_不强制X11=1` 可完全保留用户的平台设置（排查用）。

### 6.2 VLC 风格界面（播放页与独立窗口都是这一套）

需求是"播放器界面和功能要和原生 VLC 基本一样，区别只是多了 AI"。菜单栏结构照着
VLC 一条条对齐，**播放页和独立窗口共用同一套控件**（`界面/vlc风格.py` 一处定义）：

```
媒体(M)  打开网盘视频…(Ctrl+O) | 打开文件…(Ctrl+Shift+O) | 把当前加入清单 | 退出

         快进/快退(Ctrl+←/→) | 到开头 | 跳到结尾 | 速度 ▸(0.25×~4×) | 章节 ▸ | 上一章/下一章
音频(A)  增大/减小音量 | 静音(M) | 音频轨 ▸（动态列出文件里的音轨）
视频(V)  全屏(F) | 截图(Shift+S) | 宽高比 ▸(默认/16:9/4:3/1:1/21:9/2.35:1/5:4/16:10) |
         缩放 ▸(自动/1:4~4:1) | 窗口置顶
字幕(S)  添加字幕文件…(Ctrl+Shift+S) | 字幕轨 ▸ | 🤖 AI 翻译字幕 | 🤖 AI 生成字幕 | 🤖 AI 总结
视图(I)  播放清单(Ctrl+L) | AI 助手面板 | 状态栏 | 显示/隐藏控件(Ctrl+H)
工具(T)  查看起播参数 | 🤖 卡顿诊断 | 🤖 自动换参数重载 | 效果/偏好说明
🤖 AI    翻译字幕 | 生成字幕 | 内容总结 | 卡顿诊断 | 自动调优 | AI 面板 | 使用说明
帮助(H)  快捷键 | AI 说明 | 关于
```

工具栏（VLC 同款顺序）：`📂打开网盘 📁打开文件 | ▶播放 ⏹停止 ⏮上一个 ⏭下一个 |
⛶全屏 📋播放清单 🔁循环 🔀随机 | 🔊 音量滑条 | 速度下拉(0.25×~4×)`；
底部还有一条 VLC 式控制条：`⏸ ⏹ ──进度── 时间 音量 倍速 字幕 截图 全屏`。

**播放清单**（右侧「📋 播放清单」标签页，VLC 的播放清单面板）：
双击即播；`⏮/⏭` 按清单走；循环三态（不循环 / 单曲循环 / 列表循环）+ 随机；
一首放完**自动续播**下一项（不循环且是最后一项就停下）。
菜单/工具栏里的音频轨、字幕轨、章节、速度、宽高比都是**动态填充**的
（`aboutToShow` 时重拉，换了文件内容跟着变，VLC 同款行为）。

**画面上右键**也有 VLC 那套：播放/暂停、停止、全屏、截图、速度、音频轨、字幕轨、
宽高比，外加 `🤖 AI` 子菜单。

> 键位说明：`S` 是停止（VLC 默认），所以**截图用 `Shift+S`**；这与 VLC 一致。

### 6.3 网盘页双击视频 = 直接播放

* 在任意网盘的文件表格里**双击视频**（.mp4/.mkv/.ts/.m2ts/.rmvb… 见
  `媒体信息.视频后缀`）→ 自动切到播放页并开播；
* **Ctrl（macOS 为 ⌘）+ 双击** → 直接在**独立窗口**里播，不占主窗口；
* 双击文件夹仍然是进出目录，双击其它类型文件不会误触发播放（有回归测试兜着）。

### 6.4 独立播放窗口

**单播放器架构（重要）**：全局**只有一个播放会话/一个 libvlc media_player**。
"独立窗口"不是另开一个播放器，而是把**画面（vout）搬过去**：

```
播放页窗口 ←──┐                        ┌──→ 独立窗口
              │  同一个 播放会话        │
   绑定页句柄 ─┴─ 重开媒体 + 跳回原位置 ─┴─ 绑定窗口句柄
```

为什么要这样（用户实测的三个症状，全部由此而来）：

* 以前打开独立窗口会**新建第二个播放会话** → 两个 player、两个 vout：
  画面跑到"另一个窗口"里（libvlc 自己开的那个，标题 `VLC media player`），
  我们的窗口一片黑；
* 关掉其中一个，另一个还在播 → "后台还有声音、界面上却没有画面"；
* 每次开/关窗口都要重取直链、重新起播。

现在开窗 = `绑定窗口句柄 → 重开媒体 → 跳回原位置`，关窗 = 反向再来一次：
位置连续、**不会有两路声音**、也不会再多出窗口。

> **窗口按视频分辨率打开（消除黑边）**：开播/接管时从 ffprobe 探测结果取视频宽高，
> 把**视频区的宽高比**调成与视频一致（libvlc 按"保持比例+居中"铺画面，比例一致才没黑边），
> 窗口尺寸 = 目标视频区 + 装饰（菜单栏/进度条/按钮行/状态栏/右侧面板）。
> 4K/8K 自动缩到屏幕可用区域内；竖屏（9:16）也能得到竖着的窗口；小片子不放大。
> 实测：4K 横屏 1420×798（比例误差 0.0017）、1080×1920 竖屏 508×904（误差 0.0006），
> 都装得进屏幕。「视频 → 按视频比例调整窗口」可随时手动重排。
>
> **藏起面板也不留黑边**：藏起右侧「播放清单 / AI 助手」面板会让视频区变宽，窗口尺寸
> 不变就和视频比例对不上 → **左右黑边**。所以面板显隐、页签切换、退出全屏、窗口显示
> 之后都会**按视频比例重排窗口**（藏面板 = 窗口跟着收窄，视频区尺寸保持不变）。
> 实测（真 X11）：藏面板后视频区 1600×900（比例误差 **0.0000**），再显示面板 1420×798
> （误差 0.0017），切页签同样保持。屏幕太窄装不下时状态栏会如实提示"收起面板可消除黑边"。
>
> **选片对话框里可以直接换网盘**：对话框顶部有网盘下拉（用户反馈"打开网盘后不能
> 切换网盘"），换盘会回到根目录重新列；确定后播放页的网盘下拉也跟着切。
>
> **工具栏「速度」后面有「🗂 面板」**：一键显示/隐藏右侧的「播放清单 + AI 助手」；
> 另外「📋 播放清单」「🤖 AI 助手」两个开关可以分别切到对应页签。
>
> **工具栏三档文字密度**（用户要求「速度」和「🗂 面板」必须显示文字）：
>
> | 档位 | 例子 | 大约需要 |
> | --- | --- | --- |
> | 完整 | `📂 打开网盘 ▶ 播放 ⛶ 全屏 📋 播放清单 🤖 AI 助手 🔊 ──── 速度 [1.0×] 🗂 面板` | ~1225px |
> | 精简 | `📂 网盘 ▶ 播放 ⛶ 全屏 📋 清单 🤖 AI 🔊 ──── 速度 [1.0×] 🗂 面板` | ~1070px |

>

**适应屏幕**：窗口默认 1180×720，但小屏/高分屏缩放/上次留下的几何都可能比屏幕大
（标题栏跑到屏幕外=看不成）。所以开窗时就会把尺寸夹到**屏幕可用区域**内并居中，

"自动适应窗口"）—— 4K 片源在 1080p 屏上也一定装得下。

**关闭独立窗口 = 回播放页接着播**：关窗前会把「当前位置 + 直链 + 媒体信息 + 起播参数」
打包交给播放页（`交接信息()`），页面用这份信息在本地起播并**跳回原来的位置**
（直链有时效，重新取可能已过期，还要多等一次网络往返）。

**播放页的暂停/停止指向"当前活动的那一路"**：视频交给独立窗口后，页面自己的会话
已经清空 —— 老实现里按钮点在空会话上，表现就是"暂停/停止无效"。现在页面统一路由：
窗口在播 → 操作窗口；窗口关了 → 操作页面自己（自检里有这两条断言）。

> ⚠️ 三个**实测**出来的细节（都有回归测试）：
> 1. 没有窗口管理器时（Xvfb、精简桌面、部分平铺 WM），`showFullScreen()` 只改
>    状态**不改窗口尺寸** —— 画面只占左上角一块。所以全屏时我们**再显式铺满屏幕**；
> 2. 全屏时视频区会"吃掉"鼠标事件，只在窗口上装事件过滤器是不够的，
>    视频区也必须装，否则鼠标动了控件不出来；
> 3. `适应屏幕` 必须在 `_构建()` **之后**调用（构建前还没有状态栏），否则开窗就报
>    `'播放器窗口' object has no attribute '状态标签'`。

## 6.5 流畅度深度优化（针对实测到的"稍显卡顿"）

用户实测的片源：**4K 10bit HDR HEVC 60fps 12.7 Mbps**，实测带宽 **13.0 Mbps**
（余量只有 **1.02×**，而判定线是 1.3×）。当时暴露了三个问题，都已修：

| 问题 | 原因 | 现在怎么做 |
| --- | --- | --- |
| 缓存被压到 **6000ms** | AI/规则建议把 12000 改成 6000，没人拦 | ①规则基线：4K 且带宽不足 → **20000ms**；②`缓存下限()`：余量 <1.3× 时任何建议都**不许低于 15000ms**，被拦下来会写日志 |
| 越播越顿 | 默认带 `:no-drop-late-frames` + `:no-skip-frames`（迟到帧一个都不丢 → 越积越晚，A/V 持续偏） | 吃力片源（4K / ≥20 Mbps / ≥45fps）自动改成**允许丢迟到帧**（VLC 默认行为），普通片源仍保持"画面完整优先" |
| 4K 缩放吃 CPU | 默认 vout 在 CPU 上做缩放/色彩转换 | 吃力片源试 **`:vout=gl`**（GPU 缩放）；GL 起不来时 `_GL兜底检查` 会在 3 秒内**自动退回默认 vout** 重载，不会"有声没画" |
| AI 没建议时什么都不做 | 用户日志里本地模型"输出解析不出 JSON"，顾问返回空 | 加**规则兜底诊断**：真的在掉帧/缓冲时自动给出"流畅优先"建议并重载 |

另外加了**一键「⚡ 流畅优先」**（工具菜单 / 🤖 AI 菜单）：允许丢帧 + `vout=gl` +
缓存加大，从当前位置重载。卡的时候点它就行。

> 诚实说明：这些改动在本机（虚拟 X 服务器、没有 GPU 显示加速）**测不出帧率提升**
> —— 这里 4K 显示路径本身就是瓶颈（4K H.264 实测 25fps/零丢帧；4K HEVC 约 14fps，
> 两种参数都一样）。改动本身是**针对性**的：缓存下限直接对应你日志里"12000→6000"，
> 丢帧策略对应 60fps 片源的时钟累积，vout=gl 对应 CPU 缩放。
> 你机器上有 Intel 硬解 + 真实 GL，建议开播后看状态栏的**丢帧**计数，必要时点
> 「⚡ 流畅优先」对比一下。

## 6.6 偶发"视频和播放器分离"的根治（游离窗口巡检）

现象：**偶尔**开播后画面又跑到一个标题为 ``VLC media player`` 的窗口里，我们的窗口
是黑的。根因是 libvlc 拿 ``set_xwindow`` 那一刻如果窗口**还没映射到屏幕**，它会自己开
一个窗口当画布。修法分两层：

1. **消除竞态**：起播/接管/切全屏之后都先确认窗口"已映射"（``QWindow.isExposed()``），
   没就绪就等 90ms 重试（最多 ~1.4 秒，超时照常起播并记日志）；只有 X11 需要等，
   离屏/无头平台直接放行（否则会把起播卡死 —— 这个坑也踩过）；
2. **运行时自愈**：``v8_3/播放/游离窗口.py`` 用 ctypes 直连 libX11 巡检，判据是
   **``WM_CLASS == vlc``**（不是标题！中文界面下 VLC 的窗口标题是"VLC 媒体播放器"，
   按英文标题匹配会**漏掉**，用户实测"分离"仍然发生就是这个原因；类名不随语言变，
   而 Qt 我们自己窗口的类名是 ``python3``，天然不会被误判）。标题只有在类名取不到时
   才作为兜底（中英文都认）。巡检**从起播前就开始**（VLC 恰恰是在 ``set_xwindow`` 那
   一刻自开窗口的），并且**播放期间一直盯着**（3 秒一次，不设次数上限）。
   发现后 ``界面/游离窗口守护.py`` 依次：
   把我们自己的画面**重新绑回来**（绑句柄 + 重开媒体 + 跳回原位置）→ 还在就发
   ``WM_DELETE_WINDOW`` 客气体面地请它关 → 再不行 ``XDestroyWindow`` 收掉
   （它只是 libvlc 的 vout 画布，关掉后画面回到我们窗口 —— 用户自己也验证过这个行为）。

## 8. 这一轮踩到并修掉的坑（都有回归测试）

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| **一播放就段错误**（exit 139） | VLC 3 没有 `libvlc_media_player_get_spu`，回退名没配 `argtypes`，ctypes 把 64 位句柄按 32 位传 | 所有符号走 `取函数()` 强制配类型 + 句柄过 `校验句柄()` |
| 所有视频都被判成 **SD** | 档位表阈值是"像素总数"，却拿 `max(宽,高)` 去比 | 按**短边**分档（横竖屏同档），1080p 正确 |
| 界面显示"硬解 vaapi"其实在软解 | 只看 `/dev/dri` 存在就宣称 vaapi；Intel VA 驱动根本没装 | `硬解能力()` 按**厂商 + 匹配驱动文件**核实，并给出安装命令 |
| 播放中偶发**段错误** | VLC/探测/语音识别都从各自线程回调日志，而 `_AI写` 直接 `appendPlainText`（跨线程碰控件） | 日志改走 `日志追加` 信号 + `Qt.QueuedConnection`，只在界面线程落字 |
| 播放中界面**卡 40~50 秒** | 自动调优诊断（问本地模型）在界面线程同步跑 | 诊断挪到后台线程，建议回来了再在界面线程应用 |
| 点"AI 翻译字幕"总说**没有字幕** | 只查本地 `<远端路径>.srt`，而网盘视频在本地根本没有文件 | 新增"**网盘同目录**同名 .srt"查找 + 下载到 `数据/字幕/` |
| 字幕下载"成功"却找不到文件 | 桥子进程 `cwd=v8_3/桥`，**相对本地路径被解析到桥目录里**（文件跑到 `v8_3/桥/数据/字幕/`） | 桥客户端把本地路径统一**绝对化**；字幕缓存目录固定到项目根 |

| 摘要显示成 **"整体内容，150 字以内"** 或一段 JSON | 模型把**提示词格式示例**抄回来 / 把整个对象塞进摘要字段 | 新增摘要质量判定：回声或 JSON 片段 → 换规则摘要，**保留** AI 的章节与标签 |
| 独立窗口"控件看不见" | 窗口没 `show()` 时子控件 `isVisible()` 恒为 False | 起播前先 `show()`（并 `_置顶()` 只在真显示环境调，离屏平台会刷告警） |

| **一开播整个 GUI 段错误闪退**（用户实测） | 会话在 Wayland 上（`QT_QPA_PLATFORM=wayland;xcb`）：`winId()` 是 wl_surface，**不是 X11 窗口号**，交给 `set_xwindow` → VLC 拿它当 X11 窗口画 | 启动时（QApplication 之前）探测：有 `DISPLAY` 就切 `xcb`（XWayland，用户无感）；真没有 XWayland 时句柄闸返回 0（无窗口模式）+ 明确提示 |

| 播放清单"移除"报 TypeError | `QListWidget.row()` 只吃 QListWidgetItem，代码传了 `selectedIndexes()` 的 QModelIndex | 改用 `index.row()`；单测覆盖 |

## 10. 已知限制（不藏着）

1. **VAAPI 已可用**（iHD 驱动），4K 走硬解、CPU 占用降 6 倍以上；
   但 4K 60fps / 8K 仍未实测，高码率 HEVC 建议先把片子放本机试一遍。
2. **字幕翻译/总结较慢且质量一般**（本地 1.5B 模型 CPU 推理：2 行 18~20 s、
   总结 57~136 s；译文有时生硬，摘要有时是提示词回声 —— 后者已被过滤成规则摘要）。
   要质量就填云端密钥（配置后自动优先云端）。
3. **"来源"标签偏保守**：走 AI 助手那条路时（助手内部其实可能用的就是本地模型），
   字幕助手会标成"云端"。日志里能看到 AI 助手真实的"🏠 本地模型 … 免费"记录。
4. **语音识别首次要下模型**（464 MB，走 hf-mirror.com，huggingface.co 被墙）；
   短音频效率低（Whisper 会补齐到 30s 窗口）。
5. 转码/画质增强（超分）**没做**：Iris Xe 上跑实时超分不现实，宁可如实不做。
6. 播放页 AI 面板的「生成字幕」目前是**阻塞式**（后台线程 + 日志进度），
   没做取消按钮；长视频请等它跑完。
