# V8_3 架构设计

## 1. 目标与约束

目标：在**不使用 Alist** 的前提下，把工作区里三个 100% 自研适配器统一起来，
完成“添加网盘（同一家可多账号）/ 登录管理 / 跨网盘传输”，并解决旧 V8 的批量
小文件传输性能问题；界面套用 网盘管理_V8 的形态（左侧导航 + 切换式页面 + 主题）。

约束：

1. **不改适配器源码**：三家适配器都已经过真机验证，V8_3 只做驱动与编排。
2. **代码文件独立**：V8_3 不复制、不修改其他项目文件（主题管理器是按 V8 的样式
   在 V8_3 内重新落地的一份，不 import V8 的模块）。
3. **适配器登录 GUI 原样使用**：账号添加/扫码/短信登录仍走原 GUI，
   且只能以**独立子进程窗口**打开（见第 4 条）。
4. **不能同进程直接 import 三家核心**：三家的顶层包都叫 `核心`/`界面`，
   在同一解释器里会互相覆盖；因此“把适配器原 GUI 嵌成一个页面”不可行，
   网盘页改为 V8 主页式的原生实现 + 「登录 / 管理」按钮拉子进程窗口。
5. Python 3.14 + PySide6 有已知 GC/HTTP2 陷阱，沿用适配器已有规避策略
   （关闭 GC 自动回收、`http2=False`）。

## 2. 总体结构

```text
┌──────────────────────────── V8_3 主进程 ────────────────────────────┐
│  CLI / PySide6 GUI（左侧导航：每个网盘实例一个按钮 → 切换式页面）    │
│    │                                                               │
│ 传输引擎（线程池、小/大文件并发、重试、进度、本地中转）             │
│    │                                                               │
│ 云盘适配器统一接口                                                  │
│    ├── 子进程适配器(百度)  ── 行式 JSON ──> 工作进程 → 百度适配器核心 │
│    ├── 子进程适配器(光鸭)  ── 行式 JSON ──> 工作进程 → 光鸭适配器核心 │
│    └── 子进程适配器(夸克)  ── 行式 JSON ──> 工作进程 → 夸克适配器核心 │
└────────────────────────────────────────────────────────────────────┘
```

V8_3 不碰 Alist 的任何概念（WebDAV、挂载点、驱动工厂）。

## 3. 子进程桥协议

工作进程：

```bash
python v8_3/桥/工作进程.py --adapter baidu|guangya|quark|fake \
    --project-root <适配器目录> --threads 8
```

工作进程启动时把 `<适配器目录>` 插入 `sys.path[0]`，随后导入该适配器的
顶层 `核心` 包；因此每个工作进程只看见一家适配器。

协议为 stdin/stdout 行式 JSON：

```json
{"id": 1, "cmd": "list", "params": {"path": "/"}}
{"id": 1, "ok": true, "result": [{"name":"目录","is_dir":true,...}]}
{"event":"progress","task_id":"t1","phase":"download","current":123,"total":456}
{"event":"log","level":"info","message":"..."}
```

工作进程主线程只读请求，请求交给 `ThreadPoolExecutor` 并发执行；
每个线程有自己的一套“网络客户端 + 接口对象”（thread-local），
共享只读的凭证仓库（仓库自带锁）。这样可以：
- 同一适配器内多个文件并发上传/下载；
- 避免多个线程共用一个可变的 `上传总调度` 目录缓存。

当前命令：`ping` / `account` / `list` / `stat` / `ensure_dir` /
`upload` / `download` / `delete` / `close`。

## 4. 统一模型与路径

统一逻辑路径为 POSIX 风格：`/`、`/目录/文件`。各后端翻译方式：

| 网盘 | 地址模型 | 目录判定 | 上传入参 | 下载入参 |
|---|---|---|---|---|
| 百度 | 路径 | `isdir==1` | 目标路径（`上传接口.上传文件`） | 远端路径 |
| 光鸭 | fileId | **`resType==2`**（`dirType` 不可用） | 父目录 fileId（`上传接口.上传文件`） | 文件 fileId |
| 夸克 | fid | `dir==true` 或 `file_type==0` | 父目录 fid（`上传总调度.上传文件`） | 文件 fid |

ID 型网盘（光鸭/夸克）在桥内维护 `路径 → 目录 ID` 缓存，并负责逐级 `确保目录`。

## 5. 传输引擎

一次传输的执行流程：

1. `扫描源`：`文件信息` + 递归 `列目录`，得到扁平文件列表（源路径、相对路径、大小）。
2. `构造任务`：`目标路径 = 目标根 + 相对路径`；每个文件一个 `传输任务`。
3. `目标预检查`：按目标父目录聚合列目录，一次性判断哪些文件已存在；
   默认跳过已存在（`--覆盖` 则先删后传）。
4. `计算并发`：小文件与大文件分别给并发上限；显式 `--并发` 优先。
5. `单文件执行`：
   - 覆盖时先删除目标；
   - 源适配器 `download` 到本地中转文件（优先 `/dev/shm`）；
   - 目标适配器 `ensure_dir`（目录缓存只调一次）；
   - 目标适配器 `upload`；
   - 进度事件按 `task_id` 回传，更新 UI/CLI。
6. 失败重试：任务级指数退避，最多 `重试次数` 次；成功/失败后按配置清理中转。

### 性能取舍

- **为什么先落本地中转**：三家适配器的上传接口都接受本地文件路径；
  先落盘可以复用它们的流式上传/分片/秒传逻辑，也方便失败重试。
  本地盘（尤其 `/dev/shm`）不是瓶颈，云端协议往返才是。
- **为什么小文件单独提并发**：单文件延迟由哈希、取令牌、OSS PUT、轮询决定，
  并发多个小文件能把这些固定延迟重叠起来。
- **为什么大文件低并发**：避免多个大文件同时占满上行，反而让队列整体变慢。
- **N+1 消除**：目标预检查从“每文件一次 filemetas”改为“每目录一次列举”。
- **目录缓存**：跨网盘目录只创建一次，且 ID 型网盘缓存 path→ID。

## 5.1 自适应并发与持久化

- **并发控制器**：线程池固定 32 个工作线程，但真正同时执行的任务数由
  `并发控制器` 的许可上限控制；`吞吐自适应器` 每 3 秒根据“已完成字节增量 /
  失败增量 / 队列长度”调整上限。
- **任务数据库**：SQLite（默认 `数据/传输任务.db`，WAL 模式）。
  批次表记录源/目标/配置，任务表记录状态、字节数、错误、重试次数。
  `恢复批次` 会把未完成/失败/取消的任务重置为等待，已完成/已跳过不重传。
- **崩溃安全**：状态变化时落盘；下载中/上传中崩溃重启后会重新下载该文件
  （本地中转文件默认清理），不会破坏已完成文件。

## 6. 登录与凭证

V8_3 不解析、不打印、不转存凭证。桥进程直接使用适配器自己的仓库：

- 百度：`数据/会话.json`
- 光鸭：`数据/令牌.json`（带自动刷新）
- 夸克：`数据/凭证.json`

登录入口是各适配器原来的 `启动.py` GUI；V8_3 只是 `subprocess.Popen` 它
（在网盘页点「登录 / 管理」）。

凭证按**实例**隔离：一个实例指向一个适配器项目目录，凭证就在该目录的 `数据/` 下。
同一家网盘的第二个账号要有一份独立的项目目录（界面「复制适配器项目…」，
CLI `网盘新增 --副本`），V8_3 只复制代码，不复制 `数据/`。

## 7. 与旧 V8 的对比

| 维度 | 网盘管理_V8 | V8_3 |
|---|---|---|
| 传输通道 | Alist / WebDAV | 三家原生接口 |
| 适配器 | Alist 适配器为主 | 三家自研适配器 |
| 小文件 | 串行、每文件多次元信息 | 高并发、目标目录一次列举 |
| 大文件 | 受 WebDAV/Alist 中转 | 原生直链 + 原生分片上传 |
| 进程模型 | 单进程多线程 | 每网盘一个子进程 + 线程池 |
| 登录 | Alist 配置 | 原 GUI + 原仓库 |

主窗口

线程模型：所有阻塞调用（列目录、账号状态、上传、下载、批次传输）都跑在

列目录用「加载世代」丢弃过期回调，避免快速切换目录时旧结果覆盖新列表。

## 9. 多实例（同一家网盘多个账号）

一个网盘 = 一个 `适配器规格`，用 `标识` 唯一区分；`类型` 只决定桥后端：

```text
配置.json
"适配器": [
  {"标识": "baidu",   "类型": "baidu", "名称": "百度网盘", "路径": "百度网盘适配器",   "线程数": 12, "启用": true},
  {"标识": "baidu_2", "类型": "baidu", "名称": "百度小号", "路径": "适配器实例/baidu_2", "线程数": 8,  "启用": true}
]
```

* **键统一成标识**：传输引擎的适配器表、SQLite 批次表的 `source_cloud`/`target_cloud`、
  界面导航按钮、CLI 参数，全部用标识；
* **向后兼容**：`网盘类型` 是 `str` 枚举，`网盘类型.百度 == "baidu"` 且哈希一致，
  所以旧代码/旧配置用类型名当键仍然命中；旧版 `适配器` 字典写法在加载时自动升级为列表；
* **凭证隔离**：各家适配器把凭证写在“项目根/数据/”下（百度 会话.json、光鸭 令牌.json、
  夸克 凭证.json），所以第二个账号必须有一份独立的适配器项目目录；
  界面的「复制适配器项目…」按钮（CLI：`网盘新增 --副本`）负责复制，
  自动跳过 `数据/`、`__pycache__`、`.git`，保证新目录登录数据为空；
* **删除语义**：只从配置里移除实例，适配器目录、登录数据、云端文件都不动。

## 10. 敏感词与 AI（V8 能力在 V8_3 的落地）

### 10.1 敏感词：从"Alist 405 触发"到"上传守卫"

V8 的 `敏感词绕过器` 挂在 Alist 适配器上，靠 Alist 返回 405 触发，注入
`写函数(路径,数据)` / `属性函数(路径)` 与传输层解耦。V8_3 是原生直连，
所以改成 `v8_3/敏感词/上传守卫.py`：

```text
上传(本地文件, 远端目录, 名称)
  ├─ 预检：敏感词库扫描文件名 → 命中且已有安全词 → 换名上传 + 写改名记录
  ├─ 正常上传（走适配器）
  └─ 失败且错误像"敏感词/405/违规/blocked…"且文件 ≤32MiB
       └─ 读入内存 → 绕过器.尝试绕过()
            P1 已知词批量替换 → P2 单段探测+瘦身 → P3 组合探测+瘦身 → P4 全中文化
            每步都"改个名写一份"来探测，成功即记录 敏感词→安全词
```

* `写函数` = 落临时文件 + `适配器.上传`；`属性函数` = `适配器.文件信息`；
* 词库（`敏感词数据库`：纯 Python AC 自动机 + SQLite）按**实例标识**分组，
  改名记录支持"云端名 → 原名"反查，供下载还原；
* 相对 V8 的修复：P1 分支补写改名记录、探测文件走临时文件中转、日志走界面。

### 10.2 AI：调度接口与降级

`v8_3/AI/` 是 V8 `AI层` + `业务层/AI学习库` + `配置管理` 的时段/预算管理器的
移植版（requests → httpx，配置走 `v8_3/配置.AI配置()`，数据落 V8_3 的 `数据/`）。
界面通过 `AI运行时` 门面使用；传输引擎只认 5 个方法：

| 引擎调用 | 时机 | 作用 |
|---|---|---|
| `请求策略(特征, 决策来源标记=)` | 扫描源目录后 | 返回并发数等策略 |
| `请求文件优先级(文件列表)` | 调度前 | 按分数重排待传任务 |
| `请求运行时调优(当前并发,吞吐,失败率,队列,已完成,总数)` | 每 10 秒 | 动态调并发上限 |
| `请求失败诊断(错误,文件名,重试次数)` | 任务最终失败 | 后台线程问一次，结论进日志 |
| `回填效果(标记,吞吐,失败率,耗时)` | 批次结束 | 写学习库，供相似复用 |

**降级链**（任一层不满足就直接走规则，不联网不报错）：
无密钥 / `AI.启用=false` / 预算熔断 / 高峰时段 / 批次小于最小规模 / 频率超限。

## 11. 可观测性：决策显示 + 终端日志

### 11.1 决策来源与当前决策

引擎把"这批任务听谁的"结构化发给界面（``引擎事件.数据``）：

```json
{"type": "AI策略", "message": "AI 策略（AI，置信度 0.88）：并发 48；AI 决策",
 "data": {"来源": "AI", "并发": 48, "置信度": 0.88, "调度原因": "AI 决策",
          "优先级规则": ["大文件优先", "敏感词提前改名"], "分批策略": "顺序处理"}}
```

* ``来源`` ∈ ``AI`` / ``缓存`` / ``相似复用`` / ``规则`` / ``规则基线``；
  ``AI调优`` 事件则由运行时调优线程发出（新并发 + 理由 + 吞吐）；
* 传输页把 ``来源`` 映射成 ``AI 决策 / AI 缓存命中 / AI 相似复用 / 规则基线``，
  把 ``并发 + 优先级规则 + 分批策略 + 原因`` 压成一行"当前决策"，
  显示在统计栏第一行（悬停看全文，批次结束后保留最后一次）。

### 11.2 启动自检（V8 观感）

`v8_3/启动自检.py` 按 V8 `main.py` 的顺序分步自检并打印：
主题 → 价格抓取器（含来源/时间/模型数）→ 时段与预算 → 敏感词库 → AI 学习库 →
AI 助手（模型列表/注入价格抓取器）→ AI 调度器 → 网盘实例清单（目录/凭证）→
连通性测试。自检同时把装配好的 `AI运行时` 交给主窗口复用，避免重复初始化；
连通性测试在**后台线程**逐个实例拉账号状态，不阻塞界面；
横幅原文通过 `启动日志=` 传给主窗口写进日志页。

**网盘核心信息**（`v8_3/网盘信息.py`，纯文本、无 Qt 依赖）分两段打印：

| 段 | 内容 | 来源 |
|---|---|---|
| 静态 | 启用/停用、类型、线程数、适配器目录与可用性、凭证（位置/大小/时间）、Python 解释器、敏感词守卫与词数、同类型多实例提示 | `适配器规格` + 文件 stat + 词库 |
| 账号 | 登录状态、用户名、容量（TiB/GiB）、详情字段、注意事项、桥耗时与 ping | `适配器.账号状态()` + `ping` |

脱敏：凭证只报"在哪/多大/何时/有没有"；详情里 `token/cookie/bduss/stoken/sub/uid…`
只显示 `✅/已配置`，≥16 字符的 hex/base64 长串打码；容量与 ISO 时间统一格式化。
同一模块被启动自检、CLI `网盘详情` / `状态` 复用，保证三处口径一致。

### 11.3 终端日志

`v8_3/日志.py` 是唯一出口（V8 用裸 ``print``）：

* 级别用中文：调试 < 信息 < 警告 < 错误，``--调试/--静默/--日志级别 X``
  或配置 ``界面.终端日志/终端日志级别`` 控制；
* 写 **stderr**，所以 ``--cli`` 的 stdout 仍然只有结果，方便管道；
* 标准库 ``logging``（AI 层等）由 ``设置终端日志()`` 统一挂 handler，
  第三方库（httpx 等）压到 WARNING；
* 桥进程 stderr ≈ 适配器自己的 print，按"信息"上报（含 Traceback 的降级为警告）；
* 界面 ``追加日志`` 一条消息三处可见：终端 + 日志页 + ``数据/界面日志.txt``；
* **emoji 规则**：``日志.图标()`` 依次判断——消息自带 emoji（正则匹配常见区间）→
  级别（错误/警告）→ 成败正则（``失败(?!率)`` 且排除"失败 0"这类统计口径）→
  类别关键字表；所以 ``失败率 0%`` 不会被打成 ❌，``[桥] 后端已就绪`` 会得到 ✅；
* 适配器日志前缀带实例图标（``[🦆 光鸭云盘] …``），敏感词库的 ``print`` 已全部
  改成 ``logging``（logger 名即前缀，避免叠两层），AI 层同理。

## 12. 登录 / 管理（统一登录 + 适配器原 GUI）

网盘页管理区两个按钮：

* **「🔐 登录 / 管理」** → `界面/登录对话框.py` 的统一登录（6 种方式）；
* **「🖥 适配器原 GUI」** → `subprocess.Popen` 该适配器的 `启动.py`，
  需要适配器原始完整界面时用（登录 / 换账号 / 账号管理都在里面）。

统一登录底层通过桥命令驱动**适配器自己的认证服务**：

```text
界面 登录对话框（6 个页签，能力门控）
  │  子进程适配器.登录方式表() / 扫码开始() / 扫码等待() / Cookie登录() / 短信…()
桥 工作进程（dispatch）: auth_caps / login_qr_start / login_qr_wait / login_qr_cancel
                        / login_cookie / login_sms_send / login_sms_verify / login_token
                        / login_password / login_email
     └── 后端_基类「统一登录协议」段：所有 login_* 返回
         {"状态": 成功|失败|超时|已取消|不支持, "消息", "提示"?, "账号"?}
     适配器核心：百度 登录服务（二维码 / 手工导入 cookie）
                 光鸭 登录服务（设备授权码扫码、短信登录_*）+ 令牌仓库
                 夸克 登录服务（二维码、手动 Cookie 登录）
```

* **能力申报**而非硬编码：`auth_caps` 由各后端按自己核心真实支持的能力返回
  `{方式: {支持, 说明}}`；界面置灰不支持的方式并展示原因，**不谎报支持**；
* 邮箱 / 账号密码：三家适配器核心里都没有对应接口，协议保留
  `login_email` / `login_password`（默认返回"不支持"），将来某家实现了会自动点亮；
* 扫码两种形态：图片（base64 PNG）与设备码（验证地址 + 用户码 + 会话）；
  只给链接的（夸克）由桥或界面用 `qrcode` 本地渲染成二维码；
* 阻塞语义：`login_qr_wait` 在桥里阻塞到成功/超时（GUI 用后台线程调用）；
  部分后端的"超时"不销毁会话，界面提示仍可重试；
* 假网盘把 6 种方式全实现了（含"故意不支持邮箱/账号密码"的能力矩阵），
  整条链路离线可跑、可自检；
* 三家真实后端已实测通过（临时副本、真凭证 md5 前后一致）：
  百度真二维码 PNG + 无效 Cookie 回滚；光鸭设备码 + 无效令牌失败 + 非法手机号不外呼；
  夸克二维码链接 + 本地渲染 PNG + 无效 Cookie 失败。
* `登录对话框._建面板` 曾把**布局**当控件塞进 `QStackedWidget`（点击按钮即报
  "Internal C++ object (QVBoxLayout) already deleted"），已修并纳入自检 `[23]`。

## 13. 后续优化路线

1. **小文件字节直传**：源端下载到内存（夸克 `下载到内存` 已具备），
   目标端直接走 OSS `PUT bytes`，跳过本地文件与重复哈希。
2. **哈希复用**：若源条目自带 md5/sha1，直接传给目标端秒传/预上传，
   去掉一次全文件读盘。
3. **自适应并发**：按域名/接口成功率与吞吐动态调小文件并发，替代固定值。
4. **连接池调优**：适配器主客户端已是 100 连接/20 keepalive，
   后续可按小文件并发进一步压测调参。
5. **断点续传**：失败时保留 `.part` 与偏移，重试从偏移继续（百度/夸克都已具备 Range）。
6. **整目录下载**：网盘页目前按选中文件逐个下载，后续支持整目录递归下载。
7. **任务持久化**：SQLite 记录批次与任务状态，重启 DSH 后继续排队。
8. **敏感词大文件**：目前 >32MiB 只做预检改名；后续可做"流式分块探测"。
9. **AI 效果闭环**：接入更多特征（域名成功率、时段价格）后自动选择并发。

## 13. 本地 DeepSeek 模型（V8_3 新增）

AI 层的模型来源从"只有云端"变成"云端 / 本地二选一"：

```
AI调度器 ──► AI智能助手.请求结构化策略/请求文件优先级/请求失败诊断/请求运行时调优
                 │
                 └─► _调用一次()
                       ├─ 本地优先（AI.本地模型.启用 且 优先本地）
                       │     └─ 本地模型客户端.对话()
                       │           ├─ Ollama 原生  POST /api/chat
                       │           └─ OpenAI 兼容 POST /v1/chat/completions
                       └─ 云端（本地失败且 云端兜底，或 用途=仅轻量 时的重决策）
                             └─ POST https://api.deepseek.com/chat/completions
```

* `_调用一次(..., 用途="重"/"轻")`：`用途=仅轻量` 时只有轻量请求走本地；
* `_AI可用()`：本地可用 → 直接放行，**跳过云端预算熔断与高峰时段判断**；
* 本地推理 `费用=0`、`来源="本地模型"`，学习库按来源分别记录；
* `配置适配.取AI配置` 在"调用方给了配置"时**不回填磁盘上的本地模型开启状态**，
  保证离线测试与临时配置干净（否则开发机上真跑着的模型会影响别人）。
