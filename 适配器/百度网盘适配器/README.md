# 百度网盘适配器

一个基于 **PySide6** 的百度网盘桌面客户端，独立实现（不依赖官方客户端或 any 第三方云盘 SDK）。

通过对百度网盘 Web 端真实抓包的逆向分析，实现了文件浏览、管理、上传（含秒传）、下载、分享与转存等核心能力。

> ⚠️ **仅供个人学习与研究使用。** 逆向 Web 接口可能违反百度网盘用户协议，请自行评估风险。
> 本项目不分发任何账号凭证，也不会绕过服务端风控（如短信验证码）。

## 安装

### 环境要求

- **Python 3.10 ~ 3.12**（`requires-python = ">=3.10,<3.13"`）
  > 上限 3.13 是为规避 Python 3.14 上 PySide6 的段错误风险。
  > 实测 3.14.7 + PySide6 6.11.2 在**离屏模式**下可正常运行，但带真实显示的 GUI 未经验证。
- 操作系统：Linux / Windows / macOS（GUI 基于 Qt，跨平台）

### 步骤

```bash
# 1. 创建虚拟环境
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 2. 安装依赖
pip install httpx PySide6
# 或者按项目元数据安装：
pip install -e .

# 3. 启动
python 启动.py
```

依赖只有两个：`httpx`（HTTP 客户端）与 `PySide6`（GUI）。
**不需要** `oss2`（阿里云 SDK）或 `qrcode`（百度二维码由服务端下发图片）。

## 获取 Cookie（登录）

登录方式有两种，**推荐手工导入 Cookie**（最可靠）。

### 方式一：手工导入 Cookie（推荐）

1. 用浏览器打开 <https://pan.baidu.com> 并登录
2. 按 `F12` 打开开发者工具 → **Network（网络）** 标签
3. 刷新页面，点击任意一个 `pan.baidu.com/api/*` 请求
4. 在 **Request Headers** 里找到 `Cookie:` 一行，**整行复制**
5. 在客户端点击「🔑 导入 Cookie」，粘贴后确定

**必需的最小 Cookie 集**（实测确认）：

| Cookie | 必需性 |
|---|---|
| `BDUSS` | ✅ 必需 |
| `STOKEN` | ✅ **必需**（缺少时即使 BDUSS 有效也返回 `errno:-6`） |
| `BDUSS_BFESS` | 推荐（BFE 边缘节点冗余，与 BDUSS 互为备份） |

`BAIDUID`、`BIDUPSID`、各类 `Hm_*` 埋点 Cookie **都不需要**。

### 方式二：扫码登录

点击「🔐 扫码登录」，用百度网盘 App 扫描窗口中的二维码。
> ⚠️ 该链路的**流程已按真实抓包实现**，但因抓包中服务端响应体未被记录，
> 字段名系按 passport 公开协议推断，**尚未在真机走通**。
> 若失败请改用手工导入 Cookie。

### 凭证存放位置

会话保存在 `数据/会话.json`（权限 `0600`，已在 `.gitignore` 中排除）。

> 🔴 **BDUSS 等价于账号密码。** 请勿把它提交到版本库、粘贴到聊天窗口或写入日志。
> 本项目所有日志只输出凭证的「长度 + 字符形态」，不含明文。

## 已知限制

### 🔴 必须了解的

1. **「彻底删除」无法自动化。**
   百度对回收站彻底删除启用了**短信二次验证**（`errno:132`）。
   客户端遇到该错误会提示你去网页版处理，**不会也无法绕过**。
   回收站的「还原」是可以自动化的。

2. **转载/分享的 `sekey` 依赖会话 Cookie。**
   转存需要先调 `/share/verify` 校验提取码，它会种下 `BDCLND` cookie，
   后续 `/share/list` 与 `/share/transfer` 都依赖它。

3. **上传通道域名是动态的。**
   `*-cm01.pcs.baidu.com` 会变（实测同机 1 小时内出现过 3 个不同节点）。
   客户端通过 `locateupload` 动态解析，**不要硬编码**。

### ⚠️ 功能降级

4. **上传记录是「本机视角」**，不是账号视角。换机器看不到历史。
5. **扫码登录链路未在真机走通**（服务端响应体未被抓包记录），请优先用手工导入 Cookie。
6. **离线下载（云添加）未实现** —— 抓包样本不足，协议未摸清。
7. **上传没有并发与跨会话断点续传** —— 当前为顺序上传，单片失败有 3 次重试 + 切换备用域名。

### ℹ️ 环境相关

8. **GUI 仅在离屏模式验证过**：
   ```bash
   QT_QPA_PLATFORM=offscreen timeout 10 python 启动.py   # 退出码 124 即正常
   ```
   带真实显示服务器的运行未在本机验证。

### ⚠️ 风控提示

9. 请**控制请求频率**（建议 ≤5 req/s）。高频操作可能触发风控导致账号被临时限制。
10. 遇到 `errno:132` 一律是服务端要求人工验证，**不要尝试自动重试或绕过**。

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| `errno: -6` | 未登录。检查会话是否含 **`BDUSS` 与 `STOKEN` 两者** |
| `errno: 132` | 触发了风控验证，需去网页端完成短信验证 |
| 下载 `HTTP 403 {"error_code":31045}` | 直链请求**没带 Cookie**。正常实现应自动带上；若是自写脚本请补上 |
| `errno: -9`（`/share/list`） | 缺 `BDCLND` cookie。必须先调 `/share/verify` 校验提取码 |
| `pwd length param error` | 创建分享时提取码为空。百度要求必须是 4 位 |
| 上传大文件失败 | 检查 `locateupload` 是否可用；查看日志里的上传节点 |
| 秒传一直不命中 | 小于 256 KB 的文件**无法秒传**（持有证明需要 256 KB 数据），属正常回落 |

调试日志在「📋 调试日志」标签页，也可直接看终端输出。

## 开发说明

### 重要文档

**`PLAN.md`** 是本项目的核心文档，包含：
- 完整的 HAR 逆向分析结论（认证模型、上传协议、下载链路、接口字段语义）
- 所有关键参数的实测证据与推导过程
- 分阶段实施方案与验收记录
- 风险清单与待验证问题

改动代码前建议先读 `PLAN.md` 对应章节。

### 真机验证脚本

`_har/spike_*.py` 是各阶段的真机验证脚本，可直接运行（需要 `_har/cookies.txt`）：

```bash
.venv/bin/python _har/spike_file_list.py    # 文件浏览
.venv/bin/python _har/spike_phase34.py      # 文件管理 + 上传/秒传
.venv/bin/python _har/spike_phase5.py       # 下载（MD5 比对 / Range / 去重）
.venv/bin/python _har/spike_phase6.py       # 分享
.venv/bin/python _har/spike_phase6b.py      # 转存
```

### 几个容易踩的坑（都已在代码中规避）

1. **判目录用 `isdir == 1`**，不是 `category` —— 目录的 `category` 恒为 6。
2. **`/api/filemetas` 与 `/api/categorylist` 的返回键是 `info`**，只有 `/api/list` 是 `list`。
3. **`/api/list` 不返回 `total`**，分页只能按「本页是否满」推断。
4. **`create.block_list` 必须用 `superfile2` 返回的 md5**，不是 `precreate` 响应里的 `[0,1,2…]` 占位序号。
5. **单分片文件的 `block_list[0]` 是 `md5(整文件)`**，不是 `md5(首 256KB)`（后者只用于秒传的 `slice-md5`）。
6. **MD5 有两套表示**：上传协议用**纯净** MD5，用户可见字段用**加密态**（第 9 位被替换成 `g`..`v`）。
   官方算法见 `核心/上传/哈希计算器.py` 的 `加密md5()` / `解密md5()`。
7. **分享列表字段名与别处不一致**：`shareId`（大写 I）/ `passwd`（不是 `pwd`）/ `shortlink` 是完整链接而 `shorturl` 只是短码。
