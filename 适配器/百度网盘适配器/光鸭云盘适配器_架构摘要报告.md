# 光鸭云盘适配器 — 结构化架构摘要

> 对象：`<项目根>/适配器/光鸭云盘适配器/`（只读分析，未修改任何文件）
> 规模：44 文件 / 7058 行；技术栈 Python 3.10–3.13 + PySide6 6.10 + httpx + oss2 + qrcode
> 形态：纯桌面 GUI（`启动.py` → `界面.主界面.运行界面()`），无服务端、无 CLI 实现

**核心结论**：分层骨架干净且平台无关，平台特性几乎全部沉淀在第 2 层（业务接口）。换平台时第 3 层（网络/凭证）可基本保留，第 1 层只需替换字段映射表，第 2 层需按新平台接口清单重写。但存在 3 个必须先修的结构缺陷：令牌不回流、两套上传实现并存、公共请求头四处重复。

## 1. 分层架构

### 1.1 四层与依赖方向

```
第 0 层  启动.py                 GC 策略 + sys.path 注入 + 异常兜底
   ▼
第 1 层  界面/                   主界面.py（中枢）· 页面/*（6 Tab）· 弹窗/*（3）
   ▼                            · 公共线程.py（3 个 QThread）· 字段映射/格式化工具/样式
第 2 层  核心/接口/*（7 个）     上传 文件 云添加 分享 任务 资产 杂项 + 埋点签名
        核心/认证/*（3 个）     登录服务 认证服务（令牌仓库归第 3 层）
   ▼                            └─ 旁路未接线：核心/上传/* · 核心/下载/* · 核心/埋点/*
第 3 层  核心/网络/*（3 个）     网络客户端 追踪上下文 设备身份
        核心/认证/令牌仓库.py    令牌存取 + 静默刷新 + 并发锁
   ▼
        httpx / oss2 / 文件系统
```

依赖**严格单向向下**，无循环。第 2 层 7 个接口文件全部只 `from ..网络.网络客户端 import 网络客户端`。三处例外：

1. `界面/格式化工具.py:14` — `from 核心.认证.登录服务 import 默认国家码`：UI 为一个字符串常量反向依赖认证业务。
2. `核心/认证/令牌仓库.py:56-62` — 函数体内延迟 import `设备身份`，注释称「避免循环依赖」（实际不构成环）。
3. `核心/上传/分片上传.py:18` — import `秒传服务.上传令牌`，旁路链路内部横向依赖。

### 1.2 「界面层如何调用核心层」——三条通路

**通路 A（只读查询，最常用）**：以列目录为例

```
文件浏览页.加载目录(父ID,路径)                    # 纯 UI 状态
 → self.启动网络任务("列目录", 任务, 成功, 失败)   # 基类提供
 → 网络查询线程(任务名, 函数)                      # 公共线程
 → 成功/失败.connect(页面回调); finished.connect(主窗口._线程完成清理)
 → 主窗口.活动线程.append(线程); 线程.start()
 ── worker 线程 ──
 → 文件接口(self.网络).取文件列表(parentId=...)
 → 网络客户端.请求("POST","/userres/v1/file/get_file_list",json数据=...)
 → httpx.Client.request(...)
 ── 回主线程 ──
 → 成功信号 → 列目录成功(任务名,数据) → 填 QTableWidget
```

关键：页面**从不 new `网络客户端`**，一律走 `页面基类.网络` property 取 `主窗口.网络`（`基类.py:24-26`），全局仅一个 httpx 连接池。

**通路 B（长任务）**：`选择并上传文件 → QFileDialog → _启动批量上传 → QProgressDialog + 批量上传线程`，worker 内调 `上传接口.上传文件/上传文件夹`，四路信号（总进度/单文件成功/全部成功/失败）回 UI。这是唯一跨页面联动处（`文件浏览页.py:442` 直接调 `self.主窗口.上传记录页.加载上传记录(仅刷新=True)`）。

**通路 C（登录）**：`主界面.开始扫码登录 → 扫码登录线程 → 登录服务.完成扫码登录(二维码回调)`；二维码信号 → 二维码弹窗；成功信号 → `全局令牌仓库.获取访问令牌() → 主界面.初始化网络客户端(令牌)`。短信登录走模态对话框，对话框内部自起 `网络查询线程` 完成 4 步。

**登录刻意不走网络客户端**：`登录服务.py:61-76` 与 `令牌仓库.py:99-104` 各自 new 裸 `httpx.Client`（账号域名不带 did/dt/smid），代价是公共请求头在两处重复定义。

### 1.3 主窗口「中枢」职责

持有唯一的 `网络` 与 `认证` 实例、`活动线程: list[QThread]`（`closeEvent` 时统一 `quit()+wait(2000)`）；`_标签页切换(索引)` 硬编码 `索引 == 2` 控云添加定时器并调用页面 `首次进入()`；`全局刷新()` 用 `if/elif` 按 `Tab.currentIndex()` 0..4 分派到 5 个页面。

### 1.4 五个结构性问题（改造前必读）

1. **两条平行上传实现，一条未接线**。在用：`核心/接口/上传接口.py`（手写 OSS V1 签名 + 整体/流式 PUT）。未接线：`核心/上传/{上传总调度,分片上传,秒传服务,哈希计算器}.py`（`oss2` 真分片）。全仓 grep 确认后者的类名/函数名**零外部引用**。
2. **`核心/下载/下载服务.py` 未被使用**：`文件浏览页.py:477-523` 内联 `import httpx` 自行 `stream("GET", signedURL)`，绕过下载服务。
3. **`核心/埋点/` 整包未使用**，且 `埋点上报.py:35` `默认密钥 = ""`（注释自承「为空时上报通常被忽略」）。
4. **`项目配置.toml:17` 声明 `光鸭 = "命令行:入口"`，但 `命令行.py` 不存在** → pip 安装后该入口 ImportError。
5. **`项目配置.toml:5` 写 `requires-python = ">=3.10,<3.14"`，而 `启动.py:10-13` 专门为 3.14 关 GC**，口径不一致（`网络客户端.py:175` 注释：3.14 上 `http2=True` 会 hpack 段错误，故全仓一律 `http2=False`）。

## 3. 网络层抽象

### 3.1 构造参数

```python
网络客户端(基础地址 = 接口基础地址, 超时秒 = 30.0, 客户端标识 = 默认客户端标识)
```

内部固定行为：`httpx.Client(base_url=..., http2=False, limits=Limits(max_connections=100, max_keepalive_connections=20, keepalive_expiry=60.0))`，四段独立超时 `connect=10.0, read=3600.0, write=3600.0, pool=30.0` —— **构造参数 `超时秒` 实际未生效**（死参数）。`http2=False` 是硬性要求（3.14 hpack 段错误）。实例属性：`基础地址/客户端标识/设备ID/设备指纹/设备类型/客户端/访问令牌`，三个设备字段在 `__init__` 中即触发落盘。

### 3.2 公共请求头注入（两层）

**（a）Client 构造期默认头**（`网络客户端.py:189-199`，每请求自动带）：`accept: application/json, text/plain, */*` · `accept-language: zh-CN,zh;q=0.8` · `origin: https://www.guangyapan.com` · `referer: https://www.guangyapan.com/` · `user-agent: Chrome/147 macOS 固定串`。

**（b）每请求动态头**（`_构造公共请求头(带业务头=True, content_type="application/json")`）：

| 头 | 来源 | 条件 |
|---|---|---|
| `content-type` | 参数 | `None` 时跳过（multipart 交给 httpx 生成 boundary） |
| `did` / `dt` / `smid` | `设备身份` 三个 getter | `带业务头=True` |
| `traceparent` | `生成追踪头()`，**每请求新生成** | 同上 |
| `authorization` | `Bearer {self.访问令牌}` | 令牌非空 |

调用方 `headers=` 可覆盖追加；最后统一过 `_校验请求头()`（value 必须 ASCII，否则 `ValueError`）；URL 过 `_安全URL()` 做百分号编码，避免中文路径触发 `UnicodeEncodeError`。

### 3.3 错误处理模型

单一异常类：`接口错误(Exception)`，四属性 `消息/状态码/业务码/请求ID`。触发路径：

1. HTTP 401 且 `需要认证=True` → `接口错误("未登录或登录已过期", 状态码=401)`（`:275-277`），不走 `raise_for_status`。
2. 其他非 2xx → **`httpx.HTTPStatusError` 原生逃逸，未包装成接口错误**（不一致点）。
3. 响应非 JSON → `接口错误("响应不是合法 JSON: ...")`。
4. 业务码不在白名单 → `接口错误(msg, 状态码, 业务码, 请求ID=x-request-id)`。

业务码白名单（`网络客户端.py:39`）：`默认允许业务码 = (None, 0, 147, 156, 200)` —— `None/0` 普通成功、`147` 文件上传中（轮询常见）、`156` 秒传命中、`200` HTTP 语义化成功。接口层可追加，如 `云添加接口.确保默认目录` 传 `允许业务码=(159,)`（目录已存在）。

**缺陷**：判定是 `允许集 = set(默认允许业务码); 允许集.update(允许业务码)`，即**全局并集**语义，无法在某次调用中收紧（例如不能声明「本次不接受 147」）。换平台后不同业务码会互相「合法化」。

**重试模型**（`_执行带重试`）：`最多重试=3`（共 4 次尝试）、初始 0.5s、倍增 2.0。仅捕获 `_连接层错误 = (httpx.ConnectError, httpx.ConnectTimeout)`，理由「请求根本没到达服务端，重试安全」；明确**不重试** `ReadTimeout/WriteTimeout/PoolTimeout/ReadError/WriteError/RemoteProtocolError`（可能已被服务端处理，重试有重复操作风险）。耗尽后 re-raise 最后异常。

### 3.4 请求原语

| 原语 | 签名要点 | 用途 | 重试 | 返回 |
|---|---|---|---|---|
| `请求` | `(方法,路径,json数据,params,headers,基础地址,带业务头,需要认证,raw,允许业务码)` | 全部 JSON API（95% 调用） | ✅ | dict；`raw=True` 时 `httpx.Response` |
| `表单文件请求` | `(路径,文件字段名,文件路径,额外字段,基础地址,带业务头,允许业务码)` | multipart 上传本地文件（仅 `云添加接口.解析种子` 使用，字段名 `torrent`） | ✅（文件已读入内存以便重放） | dict |
| `账号请求` | `(方法,路径,**kw)` | 账号域名语法糖：`setdefault(基础地址=账号基础地址, 带业务头=False)` | 继承 | dict |

### 3.5 多域名切换

只有两个域名，用**常量 + 参数覆盖**实现，无域名注册表：

## 4. 认证与令牌模型

### 4.1 令牌数据结构与存储

**内存字段**：`_内存令牌: str|None`、`_刷新令牌: str`、`_过期时间戳: float`、`_用户标识: str`、`_锁: RLock`、`_刷新锁: Lock`、`_刷新回调: Callable`。

**磁盘格式**（`_保存()`，`:185-191`）：

```json
{ "访问令牌": "<JWT>", "刷新令牌": "gy.xxxxx",
  "过期时间戳": 1789311383.2560987, "用户标识": "aedZqpwocgzRgIb2",
  "保存时间": "2026-09-13 20:56:23" }
```

**路径**（`_默认存储文件()`，`:40-53`）：`<项目根>/数据/令牌.json`（项目根 = `Path(__file__).resolve().parents[2]`），异常回退 `~/.光鸭云盘/访问令牌.json`。当前实际文件存在于 `数据/令牌.json`（1044 字节）。键名全中文，仅 `过期时间戳` 是计算值（`time.time() + expires_in`），其余直接来自服务端 `access_token/refresh_token/sub`。**不解析 JWT**，只信任本地算出的过期时间。`客户端ID` 在 `令牌仓库.py:33` 与 `网络客户端.py:32` 重复定义，值相同，无单一来源。

### 4.2 刷新机制

**触发**：`提前刷新余量 = 300`（5 分钟）。`_需要刷新()` 判定：无 refresh_token → False；有 refresh_token 无 access_token → True；`time.time() >= 过期时间戳 - 300` → True。唯一入口是 `获取访问令牌()`：先 `if self._需要刷新(): self._尝试刷新()`，再在锁内判 `>= 过期时间戳 - 安全余量`（默认 0.0），过期则 warning 并返回 `None`。

**回调注入**：`设置刷新回调(回调: Callable[[str], Optional[dict]])`，传 `None` 重置回默认实现。入参 refresh_token，出参约定含 `access_token/expires_in/refresh_token?/sub?`。**全仓无人调用 `设置刷新回调`**，始终用默认实现。

**默认实现**（`_默认刷新实现`，`:65-130`）：裸 `httpx.Client(base_url=https://account.guangyapan.com, timeout=20.0, http2=False)` + 16 个 Authing 设备头 → `POST /v1/auth/token`，body `{"grant_type":"refresh_token","refresh_token":...,"client_id":"aMe-8VSlkrbQXpUR"}`；非 200 / 非 JSON / 缺 `access_token` 一律返回 `None`，不抛异常。

**并发安全（双检锁 + 单飞，`_尝试刷新` `:236-284`）**：
1. 抢 `_刷新锁`（`threading.Lock`）→ 同一时刻只有一个线程跑网络刷新；
2. 进锁后在 `_锁`（`RLock`）内**二次检查**：若已被别的线程刷好（`内存令牌 and time.time() < 过期时间戳 - 300`）直接 `return True`，不重复请求；
3. 拷贝 `刷新令牌/回调/用户标识` 到局部变量后**释放字段锁**再执行网络 I/O（避免持锁做网络调用）；
4. 成功后 `保存令牌(...)`（内部再取 `_锁`），`_刷新锁` 释放 → 等待线程由步骤 2 命中。

**★ 致命缺口（换平台必须先修）**：`网络客户端.访问令牌` 是**构造/登录时的一次性快照**。全仓 `设置访问令牌` 仅 4 个调用点（`认证服务.py:23`、`主界面.py:197`、`主界面.py:374`、`主界面.py:323` 间接），**没有任何一处把刷新后的新令牌回灌到 `网络客户端`**。access_token 有效期 7200s，因此会话超过 2 小时后所有请求仍带旧令牌 → 连续 401 → `接口错误("未登录或登录已过期")`，而仓库里躺着刚刷新的有效令牌。正确做法：`网络客户端` 注入 `获取访问令牌` 回调（或持有 `令牌仓库` 引用），每请求前取一次。

## 5. 上传协议

### 5.1 在用链路（`核心/接口/上传接口.py`）

```
上传文件(本地路径, 父目录ID, 进度回调)
 ├ 0. 预检：is_file() 否则 FileNotFoundError
 ├ 1. 计算 MD5 ─ _md5_文件（2MB 分块 hexdigest）              [进度 0 → 0.05]
 ├ 2. 取上传令牌 ─ POST /userres/v2/get_res_center_token       [0.10]
 │     body {"capacity":30,"name":文件名,"res":{"fileSize":N,"md5":"..."},"parentId":"..."}
 │     ├ code=156 或 msg="上传已完成" → 命中秒传：data 只有 taskId → 注入 _秒传=True
 │     └ 否则必须含 creds → 注入 _秒传=False
 ├ 3A. 秒传命中 → 跳过 4/5，直接 等待任务完成(taskId)          [0.90 → 1.0]
 └ 3B. 普通上传
      ├ 4. OSS 直传                                            [0.15 → 0.85]
      │    if 大小 > 分片阈值(100MB): OSS直传流式（1MB 生成器 + 自建 httpx.Client）
      │    else:                       OSS直传（read_bytes 全量入内存）
      │    两者：_构造OSS请求头 → OSS V1 签名 → PUT {fullEndPoint}/{objectPath} → ETag
      ├ 5. 秒传检查（失败忽略）                                 [0.90]
      │    POST /userres/v1/check_can_flash_upload  {"taskId","gcid","cid"}
      │    gcid 优先取 ETag 去引号，回退 令牌.gcid；try/except 全吞，仅 warning
      └ 6. 轮询等待任务完成                                     [0.95 → 1.0]
           POST /userres/v1/file/get_info_by_task_id  {"taskId"}
           msg=="success" 且 data 非空 → 返回 data（含 fileId/fileName）
           code==147 → sleep(1.0) 继续；超 300s → TimeoutError；其他 → RuntimeError
```

`创建目录(parentId, dirName, failIfNameExist=True)` → `POST /userres/v1/file/create_dir`；`确保目录` 按 `/` 逐级建；`上传文件夹` 先建顶层目录 → `os.walk` 收集全部文件 → 用 `目录缓存: dict[str,str]`（键为累积相对路径，`""` 映射顶层目录）避免重复建目录 → 每文件进度按 `基 + p*范围` 线性映射到全局。

### 5.2 OSS 直传签名（阿里云 OSS V1 + STS）

`_计算OSS签名`（`:126-190`）实现抓包还原的四段式：

```
StringToSign = "PUT\n" + Content-MD5(空) + "\n" + Content-Type + "\n" + {x-oss-date 的值} + "\n"
             + CanonicalizedOSSHeaders   # 所有 x-oss-*：名字小写、字典序、value 去首尾空格、每行 \n 结尾
             + CanonicalizedResource     # /{bucketName}/{objectPath}
Authorization = "OSS " + AccessKeyId + ":" + base64(HMAC-SHA1(AKSecret, StringToSign))
```

参与签名的头仅三个：`x-oss-date`（RFC1123 GMT，`_生成OSS日期` 用 `email.utils.format_datetime(..., usegmt=True)` 规避中文 locale 的 `%a/%b`）、`x-oss-security-token`（STS sessionToken）、`x-oss-user-agent`（`aliyun-sdk-js/6.23.0 Chrome 151.0.0.0 on Linux 64-bit`）。**两个易踩的坑（源码注释已显式标注 `:147-152`）**：`CanonicalizedOSSHeaders` 必须包含 `x-oss-date` 自身；`Date` 槽位填的是 `x-oss-date` 的值而非留空。

### 5.3 分片大小、并发度、哈希

| 项 | 在用链路（`上传接口.py`） | 旁路链路（`核心/上传`） |
|---|---|---|
| 哈希 | MD5，2MB 分块，全文件一次 | MD5，2MB 分块（`哈希计算器.py:22`） |
| 分片阈值 | `分片阈值 = 100MB`（`:89`） | 无阈值，一律走 OSS multipart |
| 分片大小 | **无真正分片**：<100MB 全量 bytes；≥100MB 用 1MB 读块的**流式整体 PUT**（`:417`）。`默认分片大小 = 10MB`（`:90`）定义后**从未被引用** | `分片大小=1MB`（`分片上传.py:32`），`oss2.SizedFileAdapter` 按 part 切；`determine_part_size` 已 import 未使用 |
| 并发度 | **1**（单连接顺序 PUT）。`capacity=30` 是发给服务端的「通道数」参数，**不是本地并发** | `并发数=4`，`ThreadPoolExecutor`（`分片上传.py:92`） |
| 进度回调 | `(阶段: str, 0~1: float)`；阶段串 `计算 MD5/取上传令牌/直传 OSS/服务端校验/等待服务端确认/秒传命中/完成`；文件夹上传加文件名前缀 `f"{文件名} - {阶段}"` | `(已上传字节, 总字节)`；`上传总调度` 转成 `(阶段,比例)`，阶段串**无空格**（`计算MD5/取上传令牌/分片上传/完成`），与在用链路不一致 |

### 5.4 断点续传与重试策略

**没有断点续传**：无持久化上传会话（无 uploadId / 已传分片清单落盘），进程退出即全丢；无 `list_parts` / resume 逻辑，每次 `init_multipart_upload` 全新开始。秒传（`code=156`）是唯一免上传机制，但依赖服务端已有同 MD5 文件，不解决中断恢复。

| 层 | 策略 |
|---|---|
| 连接层 | 仅 `ConnectError/ConnectTimeout`，指数退避 0.5→1→2s，3 次重试；适用于所有 JSON 请求、`表单文件请求`、`原始PUT` |
| 流式体 | **不重试**（生成器不可重放）：`流式PUT`、`OSS直传流式`、`流式GET` |
| 业务轮询 | `code=147` 时每秒重试，上限 300s（`上传接口`）/ 3600s（`云添加接口`） |
| 秒传检查 | try/except 全吞，失败仅 warning，不影响主流程 |
| 批量上传（UI） | **无逐文件重试、无失败续传**：任一文件抛异常 → 整个线程中断 → `失败` 信号；已成功文件不回滚，剩余文件不再上传 |
| 分片上传（旁路） | 单分片失败 → `任务.result()` 抛出 → 整个上传失败，已传分片不清理（靠 OSS 生命周期兜底） |

**旁路链路两个必须先修的缺陷**：① `秒传服务.py:96` 无条件执行 `上传令牌.从字典(响应数据["data"])`，而 `从字典`（`:48`）强制要求 `数据["gcid"]` 与 `数据["taskId"]` → 秒传命中时 `data` 只有 `taskId`，**`KeyError: 'gcid'`**，与「秒传应跳过上传」的意图直接冲突；② `上传总调度.py:87-91` 调用 `检查是否可闪电上传(taskId=..., gcid=取结果.令牌.gcid, cid=取结果.令牌.gcid)` —— **`cid` 被赋成 `gcid` 的副本**，疑似参数错误，且返回值被丢弃未参与分支。

### 6.2 页面基类提供什么

`页面基类(QWidget)`（`基类.py`）刻意极薄，只做三件事：

1. **持有主窗口引用**，通过两个只读 property 暴露依赖：`网络 → 主窗口.网络`、`认证 → 主窗口.认证`。页面因此不需 import `网络客户端`，也不管连接池。
2. **统一后台任务入口** `启动网络任务(任务名,函数,成功回调,失败回调=None)`：建 `网络查询线程` → 连 `成功/失败` → 连 `主窗口._线程完成清理` → 注册进 `活动线程` → `start()`。未传 `失败回调` 时落到 `_默认失败`（只 log 不弹窗）。
3. **三个生命周期钩子**（默认空实现）：`设置启用(已登录)`/`首次进入()`/`重置()`。

`日志页` **不继承页面基类**（直接继承 `QTextEdit`），但仍实现 `设置启用` 以配合主窗口统一调用；`首次进入/重置` 缺失，靠主窗口侧不调用规避。

### 6.3 `字段映射.py` 与 `格式化工具.py` 的作用

**`字段映射.py` = 「后端原始字段 → 人类可读」的唯一翻译层**，供 `账号信息页` 递归树使用：
- 四个按类型决定格式化策略的字段名集合：`时间戳字段`（约 25 个：`ctime/utime/dtime/vipExpireTime/createTime/exp…`）、`字节字段`（约 25 个：`fileSize/totalSpaceSize/*Traffic/size…`）、`秒数字段`（8 个：`vipLeftTime/leftTime/urlDuration…`），以及 `字段中文名`（**约 190 条**英文键→中文名，覆盖账号/资产/文件/分享/任务/回收站/短信登录全领域）。
- 四个枚举映射：`VIP状态映射`、`资源类型映射`、`任务状态映射_文件`、`操作类型映射`。其中两个**直接来自核心层**（`from 核心.接口.云添加接口 import 任务状态映射`、`from 核心.接口.分享接口 import 分享类型映射, 下载类型映射`）—— 枚举定义留在核心层，UI 只做二次展示。
- `翻译字段名(键) -> str`：查表，未命中原样返回。
- `格式化值(键, 值)`：按集合成员关系分派 —— 时间戳（`>1e9` 才格式化，附原值 `"2026-09-13 20:56:23 (1789311383.56)"`）、字节（`>0` 才格式化）、秒数、各类枚举（统一 `"中文名 (原值 N)"`）、bool → `是/否`；**整函数包 try/except，任何异常静默返回原值**。

**`格式化工具.py` = 与平台无关的纯展示工具**：`非法字符集 = set('\\/:*?"<>|')` · `格式化大小(字节)`（B→PB，1024 进制两位小数，负数保留符号）· `格式化时长(秒)`（天/小时/分/秒组合，负数→「已过期」，有「天」时省略「分」）· `格式化时间戳(值)`（`>1e12` 视作毫秒，本地时区 `%Y-%m-%d %H:%M:%S`）· `默认新文件夹名()`（`新建文件夹-YYYYMMDDHHMMSSmmm`，**对齐光鸭默认命名**）· `规范化手机号(输入)`。

### 6.4 线程模型

**三类 QThread + 一个主线程 UI，全部遵循「worker 里只发信号，UI 更新只在槽函数里」**：

| 线程类 | 信号 | 用途 | 生命周期 |
|---|---|---|---|
| `网络查询线程(任务名, 函数)` | `成功(str,object)` / `失败(str,str)` | 通用：所有页面查询（列目录、上传记录、云添加、分享列表、账号信息、新建/删除/清空、下载） | 一次性，每任务 new 一个 |
| `扫码登录线程()` | `二维码(str,str)` / `成功(dict)` / `失败(str)` | 扫码登录（含长轮询） | 主窗口持有 `扫码线程`，可 disconnect 后重建 |
| `批量上传线程(网络,路径列表,父目录ID,是文件夹)` | `总进度(str,float)` / `单文件成功(str,dict)` / `全部成功(int,int)` / `失败(str)` | 批量/文件夹上传 | 页面持有 `上传线程实例` |

**解耦机制**：
1. **依赖注入而非全局单例**：线程构造时接收 `网络客户端`（`批量上传线程.__init__(网络,...)`），或在其 `run()` 内通过闭包捕获的网络引用 new 接口实例（`网络查询线程` 的 `函数` 是闭包，闭包里写 `文件接口(self.网络).取文件列表(...)`）。核心层完全不知道 Qt 的存在。
2. **信号跨线程自动排队**：`Signal(str, object)` 用 `object` 承载任意 dict/list，Qt 自动 `QueuedConnection` 投递，槽函数在主线程执行 → UI 操作天然安全。
3. **统一回收**：所有线程 `finished.connect(主窗口._线程完成清理)`，该槽用 `sender()` 取线程，从 `活动线程` 移除后 `deleteLater()`（`主界面.py:449-467` 注释明确「不能直接 del，必须 deleteLater」）。短信对话框有自己的一份 `_线程完成清理`（`:251-264`），因其线程不注册到主窗口。
4. **退出路径**：`closeEvent` → 停云添加定时器 → 遍历 `活动线程` 逐个 `quit()+wait(2000)` → `clear()` → 关网络 → 关认证。短信对话框 `closeEvent/reject` 停倒计时并 `wait(500)` 后关登录服务。
5. **重复回调防护**：云添加页 `刷新中` 标志 + 1 秒防抖（`:328-334`）；分享页 `列表加载中` 标志 + 1 秒防抖（`:180-186`）；扫码登录用 `sender()` 比对丢弃过期线程回调。
6. **Python 3.14 约束**：`公共线程.py:4-5` 明确「所有线程 `run()` 里绝对不能调用 `gc.collect()`」，配合 `启动.py` 关闭自动 GC；`批量上传线程.run()` 中无任何 GC 调用（符合约定）。

**唯一破口**：`账号信息页.刷新全部()` 在主线程循环里连续调 8 次 `查询账号信息`，每次 new 一个线程立即 `start()` —— 瞬间 8 个并发线程打同一连接池（池上限 100/20，尚可承受，但无节流、无合并、无取消）。

### 7.2 注释风格

- **每文件顶部一段中文模块 docstring**，说明「作用 / 参考抓包 / 流程步骤 / 关键坑」。接口类文件（`上传接口/文件接口/云添加接口/分享接口`）的顶部 docstring 是**完整的 HAR 抓包笔记**，直接列出端点、请求体、响应字段、业务码含义（例：`分享接口.py:6-58` 用 50 行记录创建/列表/取消三种接口的真实字段），是可执行的接口文档。
- **变更溯源注释**：日期标记修复（`【连接层重试 - 2026-09-13】`、`（HAR 修复）`、`（HAR 确认 2026-09-13）`）。
- **⚠️ 警告块**覆盖在易踩的坑紧上方：`Date 位置填 x-oss-date 的值（不是留空！）`、`必须用 deleteLater()`、`绝对不能调用 gc.collect()`、`必须传纯数字 id 而不是 shareId`。
- **分节分隔线**：`# ==================== 段名 ====================` 与 `# ---------------- 段名 ----------------`，接口与 UI 文件大量使用。
- **参数说明用 `:param x:` + 中文**写在 docstring 内而非行内。
- 行内注释偏密且解释「为什么」而非「做什么」（`# 注意：Python 3.14 上 http2=True 可能导致 hpack 段错误`、`# 用 RLock 因为 保存令牌 可能被嵌套调用`、`# 只保留纯数字部分，防止误传带后缀 shareId`）。
- 把抓包观察写进代码（`# 抓包中 dt=4`、`# 159 属于预期内`）。

### 7.3 docstring 风格

类 docstring 极短，常见是**类名复读**（`class 文件接口: """文件接口"""`、`class 分享接口: """分享相关接口"""`），信息量集中在模块与方法 docstring。方法 docstring 为「一句话职责 → 空行 → `:param X:` / `:return:`」；多步流程用编号列表（`上传接口.上传文件` 的 docstring 即 5 步流程）；部分方法内嵌**响应样例 JSON**（`文件接口.创建文件夹`、`分享接口.取分享列表`、`云添加接口.解析种子`）。**几乎每个公开函数都有完整 PEP 484 类型标注**（`-> str | None`、`list[dict]`、`Callable[[str,float],None] | None`），中文标识符与类型标注共存无碍（3.10+ 支持）；未标注的仅限回调参数（`进度回调=None`、`日志页._安装处理器` 的内嵌类），属一致惯例。

### 7.4 日志命名

- **logger 名严格分层，全部以 `光鸭云盘` 为根**：`光鸭云盘.网络/.令牌/.登录/.认证/.上传/.文件/.云添加/.分享/.任务/.资产/.埋点/.界面/.界面.线程/.界面.页面/.界面.文件浏览/.界面.上传记录/.界面.云添加/.界面.分享/.界面.账号信息/.界面.短信登录` —— `getLogger(__name__)` 的**手工中文等价物**，对应目录结构。
- **消息统一 `[模块]` 前缀**（简写形式）：`[网络]/[令牌]/[登录]/[上传]/[文件]/[云添加]/[分享]/[任务]/[界面]/[短信登录]/[OSS]/[埋点]`，形如 `logger.info(f"[上传] ✅ {文件名} fileId=...")`。
- **状态 emoji 作语义标记**：`✅` 成功、`❌` 失败、`⚡` 秒传命中、`⚠️` 警告。UI 状态标签同样用 `⚪/🟡/🟢/🔴` 与 `📁/📄/⏳/⬇️/✅/❌/⏸/🗑`。
- 级别规范：连接失败重试 `warning`、重试耗尽 `error`、流程关键节点 `info`、请求/响应细节与 StringToSign `debug`、未捕获异常 `logger.exception`（`公共线程`、`网络客户端.流式GET`）。
- **配置位置**：`logging.basicConfig(level=DEBUG, format="%(asctime)s [%(levelname)s] %(name)s: %(message)s", datefmt="%H:%M:%S")` 写在 `主界面.py:29-33`（导入期副作用）；`日志页.py:29-54` 再往 **root logger** 挂一个上色 `Handler` —— 即 DEBUG 全量打控制台 + 同一 root 转发到 GUI 文本区。

### 7.5 导入风格

**核心层用相对导入，界面层引用核心用绝对导入、同层用相对导入** —— 分界清晰且被严格遵守：

- `核心/**` 内部：`from .令牌仓库 import 全局令牌仓库`、`from ..网络.网络客户端 import 网络客户端`、`from ..接口.埋点签名 import 计算埋点签名`（`核心/埋点/埋点上报.py:29`），无一例外。
- `界面/**`：引用核心层 `from 核心.认证.认证服务 import 认证服务`、`from 核心.接口.文件接口 import 文件接口`；同层 `from .样式 import 应用全局样式`、`from ..公共线程 import 网络查询线程`、`from .基类 import 页面基类`。
- `启动.py` 绝对导入 `from 界面.主界面 import 运行界面` 并先手工把项目根插入 `sys.path[0]`；`主界面.py:18-20` **重复同一件事**（被 `import 界面.主界面` 直接加载时兜底）。
- **包 `__init__.py` 策略**：`核心/**/__init__.py` 全为空文件（不 re-export）；`界面/__init__.py` 只有一行注释；仅 `界面/页面/__init__.py` 与 `界面/弹窗/__init__.py` 做 re-export + `__all__`。即核心层要求显式全路径导入，界面层支持短名导入（实际 `主界面.py` 仍走全路径）。
- 第三方 import 在标准库之后、本仓之前；`主界面.py` 把 `logging.basicConfig` 与 `logger` 定义插在第三方与本仓 import 之间（`:29-34`），属该文件独有小瑕疵。
- 局部延迟 import 仅三处且均有注释原因：`令牌仓库._取设备ID`（避免循环依赖）、`文件浏览页._下载一个文件` 内 `import httpx`（页面内联下载，见 §8）、`二维码弹窗` 内 `import qrcode`（可选依赖降级）。

### 8.4 改造时优先处理的五个结构性问题

1. **令牌不回流**（§4.2）：`网络客户端.访问令牌` 是快照，2 小时后必然 401。应注入 `获取访问令牌` 回调，每请求前取一次。
2. **两套上传实现并存**：先决定保留 `oss2` 分片路线还是手写签名路线；若保留旁路，须先修 `秒传服务.py:96` 的 `KeyError: 'gcid'` 与 `上传总调度.py:90` 的 `cid=gcid` 参数错误。
3. **公共请求头四处重复**（`网络客户端.py:189-199`、`令牌仓库.py:75-96`、`登录服务.py:65-103`、`上传接口.py:331-343`）：抽成一份「会话头 + 浏览器指纹」提供者。
4. **业务码白名单是并集语义**（§3.3）：无法按调用收紧，换平台后不同业务码会互相「合法化」，建议改「基线 + 覆盖」或按接口声明。
5. **UI 内联网络代码**（`文件浏览页.py:488-501` 下载、`账号信息页.刷新全部` 8 线程齐发）：前者改调 `下载服务`，后者串行化或合并请求。
